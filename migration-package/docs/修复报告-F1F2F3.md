## 二、F1 · 硬裁判携带被争议的判断 → 已修

### 改了什么

判据**物理分层**为两个文件：

| 文件 | 内容 | 谁裁决 | 否决权 |
|---|---|---|---|
| `fixtures/spec/arithmetic.json` | 10 条纯算术锚点 | 硬裁判自动 | **有** |
| `fixtures/spec/adjudication.json` | 3 条判断轴，**不含 `expected`** | **人类闸门** | 无 |

### 三道 fail-closed 硬闸门（全部实测拒载）

| 闸门 | 规则 | 实测 |
|---|---|---|
| 1 算术层路径白名单 | 比对型判据的 `path` 必须在 7 个锚点内 | 塞入 `summary.diff_count` → **exit 2** |
| 2 金额闸门 | 金额路径必须用 `decimal_equals` + `scale` | 用 `numeric_equals` → **exit 2** |
| 3 人类闸门防伪 | item 不得含 `expected`；record 须有 `source` 与非空 `recorded_by` | 缺任一 → **exit 2** |

> **闸门 1 是本修复的核心。** 那 7 条白名单**恰好**把原序 5/6/7/8（`diff_count` / `diffs` /
> `amount_diff_total` / `excluded_amount_total`）机械地挡在算术层之外 ——
> 不靠人自觉，靠拒载。

### 裁定语义

| `--spec-layer` | `--record` | verdict | 退出码 |
|---|---|---|---|
| `arithmetic` | — | `pass` / `fail` | 0 / 1 |
| `adjudication` | 否 | `pending_adjudication` | **3** |
| `adjudication` | 是 | `adjudicated` | 0 |
| `all`（缺省） | 否 | `fail` / `pending_adjudication` / `pass` | 1 / **3** / 0 |

**「未裁决」= 退出码 3，不是 0。** 未裁决 ≠ 通过 —— 这正是 F1 要消除的假信心。

### 向后兼容

legacy 单层 `truth.json` **不回归**（14/14 pass、exit 0），但：
- 打弃用警告
- 结果里标 `carries_undeclared_judgment: true`

**白名单在 legacy 模式下不生效** —— 强制会销毁回归基线，而 legacy spec 的判断项早已知晓。
但由此产生一个诚实的后果：**legacy 模式下硬裁判仍然只能复述判断**。兼容是为了不破坏历史，不是为了继续用它决策。

## 三、F2 · 「写权限唯一化」是纯文本约束 → 已修

### 改了什么

1. **显式写入域**：`config/write_domains.json`
   `allow = runs/round{n}/...`｜`deny = fixtures/ outputs/ docs/ protocol/ prompts/ config/ judges/`
2. **结构审计第 8 查**：`gen_manifest.py --write-domain ...` 前后快照比对

### 端到端实测

```
步骤1  建基线        -> runs/round1/wd-baseline.json（33 条 / 7 个禁止前缀）
步骤2  模拟越权写入  -> fixtures/_SIMULATED_VIOLATION.txt
步骤3  比对          -> verdict=HIT，准确报出 [added] fixtures/_SIMULATED_VIOLATION.txt，exit 1
步骤4  移走该文件    -> verdict=CLEAN，exit 0（allow 域正确报出 24 个文件）
```

### 一个必须写明的语义边界

比对脚本**只判结构变化**（sha256 新增/删除/变更），**不判语义**。
`HIT` ≠ 越权 —— 一次有决策日志留痕的按需再生成也会 HIT。
「越权写入」与「合法再生成」由 PM 在 `docs/decisions/` 留痕裁定。

这不是缺陷：**工具负责把不可见变成可见，判断留给人。**

### Windows 上的诚实边界

物理隔离（`chmod`/ACL）只在 macOS/目标机可行。
Windows 的 `attrib +R` 只是软屏障（进程可自行清除），**不得视为安全边界**。
Windows 侧只有**检测**可用。→ **检测可得，预防不可得。**

## 四、F3 · 浮点安全性被容差掩盖 → 已修

### 改了什么

- `make_fixtures.py` 全程 `Decimal`（`ROUND_HALF_EVEN` 对齐 `round` 语义）
- `verify.py` 新增 `decimal_equals` 检查类型；`load_json` 用 `parse_float=Decimal`
  （金额从 JSON 字面量直接构造 Decimal，**完全绕过 float**）
- 金额路径必须用 `decimal_equals` + `scale`，否则**拒载**

### 实测

```
float 裸算：(2500.01-2500.00)+(3210.51-3210.50) = 0.020000000000436557   ≠ 0.02
Decimal   ：同样运算                             = 0.02                    ✓
```

**三数不变的硬保证**：`truth.json` 与冻结基线 sha256 一致 —— `03b41c4927991adb`。
（`Decimal → float → json` 的 repr 与改造前逐字节相同）
