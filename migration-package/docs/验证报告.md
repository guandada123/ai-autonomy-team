## 四、四个结构缺陷（本轮真正的产出）

### 🔴 F1 · 硬裁判携带了它本该仲裁的那个判断（最严重）

**事实链**：

1. `TASK.md` 明文声明「契约只定义计算方法，**不预设**你对『该不该算差异』的判断」。
2. 但 `truth.json` 中 `excluded_amount_total = 180.00` 这个期望值，**恰恰就是**「口径差异应当排除」这一判断的编码结果——它不是纯算术锚点。
3. EX-02（异族对立面）为**对立立场（甲）**构造了 steelman，其论证包括：
   - **n=2 无法确立规则**：6% 税率只能从 T104/T105 两个样本归纳，两笔一致的比率在真实对账中是最经典的巧合陷阱；
   - **契约自相矛盾**：契约封禁含税/不含税换算，而「排除」的判据恰恰依赖换算；
   - **风险不对称**：多报差异的代价是一次复核，少报差异的代价是它永久消失；
   - **字段语义**：字段名叫 `amount_diff_total`，不是 `unexplained_diff_total`；
   - **信息支配性**：乙的输出可无损还原甲的数字（680.02 = 500.02 + 180.00），反之不可。
   EX-02 自评「论证质量更倾向于甲」，给出甲立场下数字为 `680.02 / 0.00`。
4. **然而聚合结果没有改变**——因为最终裁决者是 `truth.json`，而它本身就是争议判断的载体。

> **这是本轮最重要的一条**：硬裁判之所以看起来有权威，是因为它输出二值裁决；但二值裁决的合法性完全依赖判据无歧义。**当判据本身携带被争议的判断时，硬裁判无法仲裁，只能复述。** 它不是在判定，是在宣布。

**七查归属**：第 2 查「外部钩子」+ 第 5 查「规格假设」（AD-01 独立判定一致）。
**这不是执行体犯错**——甲、乙两立场在文本内部均自洽，执行体无论多努力都无法同时满足「不预设归类」和「命中隐含归类期望值」。

**改进建议（可执行）**：
- 将 `truth.json` 拆为两层：`arithmetic.json`（纯算术锚点：行数、总额、总额差——**无解释空间**）与 `adjudication.json`（需人类裁决的判断项，**不参与自动 pass/fail**）。
- 硬裁判只对 `arithmetic.json` 出裁决；判断项一律输出为「**待裁决假设**」并升级至人类闸门。
- 落地位置：`scripts/judge/verify.py` 增加 `--spec-layer arithmetic|adjudication` 参数。

### 🔴 F2 · 「写权限唯一化」是纯文本约束，没有物理屏障

**已核实事实**：
- `migration-package/fixtures/recon.py`（5364 字节）由 **EX-03 写入共享输入目录**，其内**硬编码 Windows 绝对路径**。
- `migration-package/runs/round1/_ex02_compute.py` 由 **EX-02 写入**。
- `_scratch_ex03/`（工作区根，8 个探针脚本）由 **EX-03 自行新建**——协议没划定写入域，席位就自己发明了一个。
- 三个席位都被明确告知「只有只读与提案权」。

> 三处越权、两个席位。其中「凭空发明一个目录」最能说明问题：
> **当规则只声明而不划界时，执行体不会询问边界在哪，它会自己划一条。**

**AD-01 的独立判定**（第三家族 · 干净上下文）：属「**契约本身缺少约束机制**」，而非单纯执行体越权——`01-架构.md` 只声明「只读、只提案」，没有路径白名单、没有工具层写入拦截。

**附带影响**：`recon.py` 落在 `fixtures/` 内，**污染了夹具集**，会随迁移包一起发运。（已处置：移至 `runs/round1/evidence-boundary-violation/` 留证。）

> 诚实说明：EX-03 关于「未覆盖既有文件」的自述**经核验属实**——`answer-baseline.json` 的 sha256 与裁决记录一致（`373e58f39bbf4d8b…`），证据链未断裂。违规是「越权写入」，不是「破坏数据」。

**改进建议**：
- 协议显式划定写入域：**允许** `runs/round{n}/{seat}/`，**禁止** `fixtures/` 与 `outputs/`。
- 目标机上利用文件系统权限落实（EX 席位的运行目录设为只读 + 单独可写 scratch）。
- 结构审计新增第 8 查：**「本轮是否发生共享输入目录被写入」**（可用 mtime + sha256 清单自动判定）。

### 🟠 F3 · 浮点安全性是被容差掩盖的，不是浮点正确

**独立复验结果**（我自己跑的，非采信 EX-03 自述）：

```
(2500.01 - 2500.00) + (3210.51 - 3210.50) = 0.020000000000436557
是否 == 0.02 → False
```

而全部数值判据都带 `tol=0.01`，因此当前**恰好**通过。EX-03 还做了反向实验：同一答案，spec 去掉 `tol` → **fail**，加上 `tol` → **pass**。
**结论：结论完全寄生在容差上。**

**改进建议**：金额一律用 `Decimal` 或分单位整数；并把「金额类检查必须显式声明容差」做成 spec 硬闸门（缺 `tol` 即拒绝加载）。

### 🟡 F4 · 迁移包曾有 5 个空目录，包不可用

`find migration-package -type d -empty` 曾返回 `config / docs / judges / prompts / protocol` **全部为空**——**硬裁判 `verify.py` 根本不在包内**，只迁 `migration-package/` 跑不起来。（已修复：目录已填充；`precheck.py` 新增目录完整性检查以防复发。）
