## 0 · 签字前必须知道的三件事

1. **签的是什么**：签的是「我承担这个归类判断」，不是「我确认机器算对了」。
   判断项没有机器真值 —— 这正是判据分层的意义。
2. **选哪个都不会被系统评判为「错」**，但会决定本轮产物是否与你的判断一致。
   本轮机器产出是 `diff_count = 6`。若你选的选项不是这个数，验证会判 **fail** ——
   那是**正确结果**（说明机器产出与你的判断不一致，应由 PM 记录并重做聚合），不是你的判断错了。
3. **防伪边界（不可删）**：校验器只检查 `source` / `recorded_by` / `decisions` 的**声明字段**，
   **无法证明**本文件确实由人而非模型写成。真正的保证是程序性的：
   它在你的机器流程之外填好、放进路径，工具链**不自动生成它**。

## 1.3 · 本轮结构审计的覆盖范围

**本轮结构审计未锚定裁判侧产物**（其产出无 `audited_inputs` 字段）→ 其**第 1 / 5 / 7 查不得作为签字依据**。

原因：它在裁决侧产物落盘之前就写了结论，无法证明它审计的是「已裁决」的本轮。这不是它的过错 —— 契约当时尚未要求该字段 —— 但它使那三查的证据力不足。

**受影响的字段**：`summary.amount_diff_total`、`summary.excluded_amount_total`

| `exclude` | 不计入（费用视为已解释的结算口径差异） | `amount_diff_total=380.0`；`excluded_amount_total=0.0` |

## 3 · ADJ-002

**问题**：差异清单（`summary.diff_count` 与 `diffs`）应包含哪些条目？由一个选项同时决定：(a)「equity」类（2 条）是否列入；(b)「settle_day」类（1 条）是否列入。

**受影响的字段**：`summary.diff_count`、`diffs`

| 选项 | 含义 | 对应的值 |
|---|---|---|
| `6` | 两类都列入（equity + settle_day） | `diff_count=6` |
| `5` | 只列入 equity 类 | `diff_count=5` |
| `4` | 只列入 settle_day 类 | `diff_count=4` |
| `3` | 两类都不列入 | `diff_count=3` |

## 5 · 填写格式

另存为 `runs/round26/adjudication-record.json`：

```json
{
  "task_id": "TASK-BROKER-006",
  "source": "human_adjudication",
  "recorded_by": "<你的署名>",
  "recorded_at": "<ISO8601，例如 2026-10-20T10:00:00+08:00>",
  "decisions": [
    {"id": "ADJ-001", "chosen": "<count / exclude>", "rationale": "<你的理由>"},
    {"id": "ADJ-002", "chosen": "<6 / 5 / 4 / 3>", "rationale": "<你的理由>"}

}
```

★ `decisions` 必须**恰好**覆盖上表的全部 id。缺项、或出现 spec 之外的 id（如已退役的 ADJ-003），都会被拒载（退出码 2）。
