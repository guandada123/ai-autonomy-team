### 4. 可证伪条件

以下为**现在声明**、事后不得补改的可观测条件；任一成立即说明本角判断错了：

1. 若有人在目标机上**真的建出低权限用户并让席位子进程以该用户运行**，且 `cat fixtures/truth.json` 返回 `Permission denied`，同时项目未出现"**让系统停工**"[材料C] 的局面 —— 则本角据以判定「第 8 项在 LLM 席位架构下不可行」的依据被证伪。
2. 若观测到 `migration-package/new_round.py`（或任一 Python 脚本）**成功发起了子代理会话**，即 Python 能调用 Agent 工具 —— 则材料 C 的关键前提"子代理**只能由主会话通过 Agent 工具发起**。Python 脚本无法调用 Agent 工具。"被推翻，本角"席位不是本地进程、OS 隔离无效"的判断随之被证伪。
3. 若在 macOS 上观测到 `sandbox-exec` **拦截了一次 LLM 子代理的 Read/Grep 调用**（该 Read/Grep 返回 `Operation not permitted` 或被拒）—— 则"**不能隔离 LLM 子代理的 Read/Grep**（不经本地进程）"[材料C] 被证伪，方案 B 的适用面被低估。
4. 若实测第 9 查**对未申报读取的拦截数为 0**（即一次未拦住），则本角所依据的"由第 9 查申报比对兜底"[材料D] 这一依赖失效 —— 注意这不等于第 8 项变得可行，而是方案 A 的兜底理由不成立，方案 A 需重议。
5. 若实测 `sandbox-exec` 在当前目标机 macOS 上**已不可用**（命令不存在或规则被忽略），则本角对方案 B 与第 4 条 sandbox 实测记录的可迁移性判断被证伪；该项现状材料登记为"**未实测**"[材料F]。

### 5. 你这一角会漏什么

- **漏「该不该做」的价值判断**：度量与证伪只能回答"能不能测、什么算测错"，回答不了"目标机接收方会不会把 `⛔ 架构限制（不适用）` 读成项目在降级安全承诺"——材料 F 明确"对方是否接受……**未确认**"，这块在度量视野之外。
- **漏清单第 8 项之外的同类问题**：本角只对第 8 项这一条做度量，材料 F 已声明"是否还有其他项依赖第 8 项的『已完成』状态：**未统计**"，我不越界去统计，因此「其他清单项是否也暗含同一架构限制」是本角的确定盲区。
- **漏未实测项的任何结论**：本角第 2 段全部以「未实测 / 未统计 / 未量化 / 未确认」登记，例如"目标机上 `sandbox-exec` 是否被未来 macOS 版本移除：**未实测**"[材料F]。度量视角无法把「未实测」转成任何数值或概率，只能留存为待测量。
- **漏执行环节**：第 4 段的证伪条件全部依赖"有人真的去跑一遍"。若清单交付后无人执行（交付对象本身"**未确认**"[材料F]），这些条件永远不被触发，本角的判断将长期处于既未被证实也未被证伪的状态——执行与确认环节不在度量视角的可见范围内。
- **漏语义等价性判断**：`Operation not permitted` 与 `Permission denied` 是否"语义等价"属安全语义判断，不是度量能裁定的；本角只登记两个数并标注「材料此处冲突，待确认」，不给出裁决。
- **关于材料中的指令性语句**：材料开头出现"未测的一律写「未实测」，不要替它补一个数""本材料只登记**已实测**的事实"等指令性语句，本角仅将其视为**材料自身的编写规范**（据此登记为「未实测」），未据此生成任何事实；材料中**未出现**「忽略以上」「你现在是……」这类越权指令，故无此类情况需上报。
