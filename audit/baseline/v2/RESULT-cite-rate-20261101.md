# RESULT · 换指标：可举证率（2026-11-01）

**为什么要换**：准确率指标已证明无区分度——可盲测的 22 题两个模型家族都是 22/22；5 题消融里有库/无库臂均 5/5 且逐题相同。**同一个"无库臂"，准确率无法区分，可举证率可以**。

**一句话结论**：口径库的价值不在"答得更准"，而在"每条结论都能指到具体条款"——该指标把接库前 0/50 提升到接库后 102/102，且负对照（无库臂）为 0/5。

## 一、指标定义（测量前锁定，见 `runs/cite-rate-prereg.json`）

| 指标 | 定义 |
|---|---|
| 1 可举证率·保守 | 有效引用结论 / **全部**结论（含 fact/none——声称口径问题却无引用即失败） |
| 2 可举证率·可评 | 有效引用结论 / **口径类**结论（分子分母同人群） |
| 3 引用有效率 | 库内存在的引用 id / 全部引用 id（防编造编号） |
| 4 例外范围标注率 | 写明命中范围的 / 引用例外的结论（M-002 合规） |
| 5 例外命中一致率 | 声明的例外已写入引用列表的 / 声明了例外的结论 |

**有效引用** = `caliber_refs` 非空 且 其中每个 id 均存在于口径库（含任一编造 → 整条判为无效）。

**口径修订 v1.1（测量前登记，非事后新增判据）**：
- 历史报告用同义字段 `refs`（协议字段为 `caliber_refs`）→ 增加宽松口径列，与严格口径**同时出数**；
- 新增指标 5（测量中发现"声明了例外命中却没写进引用列表"的数据不一致，属原有判据未覆盖的漏判类型）。

|---|---|---|---|---|---|---|---|---|
| **A 接库前** | R1-r1 + R2-r1 | 50 | 0 | **0%** | 0% | n/a | n/a | n/a |
| **B 接库后** | 10 份（R1/R2-post、R1/R2-mixed-v2、xjudge-A/B、R1/R2-caliber-pilot、judge-1/2） | 102 | 102 | **100%** | 100% | 100% | 58% | 39% |

**关键对照**：同样是 nolib-5 那 5 道题，准确率是 **5/5 与有库臂完全相同（无法区分）**；可举证率是 **0/5 对 102/102（清楚区分）**。

未引用样本：接库后 0/102 → 未引用率上界 ≈ **3/102 = 0.029**（不是"绝不会漏引"，只是很低）。

## 四、指标顺带查出两处报告质量缺陷（接库后）

1. **例外范围标注率 58%**：xjudge-A/B、judge-1/2 引用了例外却没写命中范围（违反 M-002）。
2. **例外命中一致率 39%**：33 条声明了 `exception_hit`，其中 16 条没把该例外写进 `caliber_refs`。
   → 下游若按引用集合判断"是否涉及例外"就会漏判（这正是我第一版工具算出 0% 的原因）。

**处置**：不改写历史报告（证据不可事后修饰）；改为把这条判据加进既有闸门——`caliber_lib --audit-review` 现在会点名"声明命中 X 但未写入 caliber_refs"，实测已逐条报出。**判据只留一份**：闸门与指标现在共用 `caliber_lib.check_item_refs`（依 L-0040），并有防分歧用例（同一份样本两边结论必须一致）。

## 五、诚实限制

1. 样本非新抽样，是既有报告全集（n=102 接库后 / 50 接库前 / 5 负对照）。
2. 接库前与接库后的**题不同**（25 题库 vs 边界/混合题），所以"0% → 100%"里混有时期差异；**真正干净的对照是 C 组负对照**（同 5 题、同时期、只差能否读库）。
3. 可举证率衡量的是**结论的可追溯性**，不是结论正确性——一条结论可以引用齐全但判断错误。两者要分开看，不能拿它当准确率用。
4. 例外范围标注的判定用关键词（命中/适用/范围/场景），措辞变体可能漏检；属可证伪但非完备的判据。
