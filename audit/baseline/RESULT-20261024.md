## 关键数字：参照自己的不确定度

零失败时单侧 95% 下界 = `0.05^(1/n)`：

| 单 agent n | 全对时下界 | 多席位所需 n（margin 5pp） |
|---|---|---|
| 9（本次） | **71.7%** | 8 |
| 20 | 86.1% | 15 |
| 30 | **90.5%** | 20 |
| 40 | 92.8% | 23 |

**本次 n=9 的基线，自身不确定度约 ±28pp，是 margin（5pp）的 5.6 倍。**
因此 V2 现在仍不可评——卡点不在多席位要多少样本，而在**参照太抖**。

## 结论与下一步

- 若按点估计 100% 代入 → 多席位需 n≥59；
- 若按下界 71.7% 代入 → 多席位需 n≥8（但这时"非劣效"几乎没有约束力）；
- 两条都不可取。**要把参照稳到下界 ≥90%，单 agent 需扩到 n≥30 且全对**，再多席位 n≥20，
  合计约 50 个任务。

## 本轮最重要的发现：基线对题集极度敏感

**同一模型、同一会话、同一判分口径，只换题集：100% → 61.1%。**

这说明"单 agent 基线是多少"这个问题**目前没有意义**——它测的是"题集怎么选"。
因此 V2 的真正前提不是样本量，而是：

1. **题集必须先固定**（题面、口径、判分方式一次性写死，之后不再增删）；
2. **题集必须经独立评审**（不能由实现者同时出题、答题、判分）；
3. 在此之上才谈得上 n 要多少。

按合计点估计 74.1% 代入 margin 5pp，多席位需零失败 n≥12——这个数字仍然没有意义，
因为它建立在一个还没固定的题集上。

## 顺带发现：注入式记忆与磁盘记忆不一致（对用户重要）

做题时对不齐，才发现**会话开始时注入的摘要**与**磁盘上的 MEMORY.md** 不是一回事：

| 项 | 会话注入摘要说 | 磁盘 MEMORY.md 说 |
|---|---|---|
| 持仓 | 5 只，含长电 600584、华天 002185、**招行**、美的、紫金 | L144：实盘 3 只（长电 600584 / 华天 002185 / **国金**）+ 模拟 3 只 = **6 只**，无招行 |
| 本金 | 实盘本金 ¥50,000（3 万基础 + 2 万加仓） | L144：**模拟盘**总资 ¥50,000；实盘另列 3 只 |
| 半导体 | 占比 77%，上限 50% | 全文 grep「半导体」**0 命中** |

文件 L251 自己解释了原因：注入上限约在 L98，**L100 之后的内容模型读不到，除非主动 grep**。
推论：注入摘要要么来自另一源、要么已过期；**磁盘文件才是当前真源**。
（本轮 Q21/Q23 因此被判"无真源/口径分歧"而排除——不是答错，是问题没有可验证的答案。）
