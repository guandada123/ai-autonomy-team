## 为什么这不是「题太难」

四题分歧里没有一题是席位漏看了事实。它们的事实引用全部正确，结论仍与用户相反。
所以这不是信息不足，是**权重不同**：席位把「新增机制的运维成本」算得重、把「已有资产的可选价值」算得轻。

这条差异在「出题人 = 裁决人」时被掩盖：我写的材料里已经含我的权重，
参考答案自然与材料同向，于是四臂满分、差异归零（D-0063）。
一旦把裁决权交出去，差异立刻显形——这是 v3 存在的意义。

## 补记（同日 10:10）：Q02 的 launchd 路线失败，改用平台定时器

原计划用 launchd 每日 09:10 跑 `recompute_watch.py`。写好 plist、改成模板注入路径、
装进 `~/Library/LaunchAgents` 后，用 `launchctl kickstart` 端到端实测，**失败**：

```
shell-init: error retrieving current directory: getcwd: cannot access parent directories: Operation not permitted
python3: can't open file '.../scripts/recompute_watch.py': [Errno 1] Operation not permitted
```

排除法：同一命令在交互 shell 下正常，文件存在且 4043B 可读。
**这是 macOS TCC 拒绝 launchd 后台进程访问外置卷**，不是路径写错、不是文件缺失。
要让这条路走通，需要用户手动给解释器「完全磁盘访问权限」——那是系统设置里的动作。

处置：
1. **卸载 launchd 任务**。理由：它每天都会失败并把错误写进 `/tmp`，属于「没人看的红灯」，
   比不做更糟（本项目一贯反对静默/噪声告警）；
2. 并入**已有的**每日 08:10「发布前检查」定时任务（同一仓库，不新建第二个日报）：
   先跑 `recompute_watch.py`，再跑 `pre_release_check.py`，合并成一条汇报。
   顺手把它 prompt 里写死的「回归 50 项」去掉——实际已 54 项，写死计数必然漂；
   该任务的运行上下文具备外置卷访问权限；
3. `scripts/install_launchd.sh` 与 plist 模板保留在仓库，作为「已授予 TCC 后」的备用路线。

一个值得记的反讽：席位在 Q02 上判 C（「加定时要新增调度/告警/重试/日志四件套，不划算」），
结论与用户相反，但**它指出的成本方向是对的**——只是它没想到真正的拦路虎是系统权限，
不是代码量。这加强而不是削弱 `RESULT-v3` §二的判断：分歧在「代价怎么算」，不在事实。
