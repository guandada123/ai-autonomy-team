| 3 | 选项由**定义式**生成（两个判断点 `decides` → 剔除不列入者 → `len==int(id)`），**不手写清单** | 手写四组 id 列表正是漂移来源（`L-0005`：没有定义式的阈值是装饰品） |

| 6 | `cost_budget` 走**声明式**：新增 `usage{tokens, minutes, source}`；`usage_required` 按轮次门控 | ① 不实现等于删条款；③ mtime 会被复制/解压重置且含人类停顿 |

| 9 | `new_round.build_prompts` 按 `role` 取段落；未知 role **显式告警不降级** | 原实现把「不引入新证据 / idle 不适用」写死，与 `evidence_round` 自相矛盾 |
| 10 | `precheck` 的待签轮次 = **最新一次含 `answer-final.json` 的轮次** | 按「任一未签轮次」判定会让 round1 永远挂着待签，而它用的是已退役三轴 spec，签不了也不该签 |

## 二、依据（全部实测）

| 1 | 旧设计的自由度是假的 | 4 组合中 `(as_diff,not_diff)`→`7 vs 5`、`(not_diff,as_diff)`→`6 vs 7`、`(not_diff,not_diff)`→`6 vs 5`，**均必有一条 fail**；「都不算=4 条」不在选项空间 |

| 4 | 4 选项自洽 | `len(diffs)==int(id)` 全部成立、4 组互不相同、id 集 = `{4,5,6,7}`（回归第 30/31 项） |
| 5 | 签署链路正反向都通 | `ADJ-002=7` → `adjudicated 14/14` exit 0；`ADJ-002=6` → `fail 12/14`，失败项正是 `diff_count` 与 `diffs`（多出 T106） |

## 三、备选方案与未采用理由

| 备选 | 未采用理由 |
|---|---|
| 把 `diffs`/`diff_count` 从各轴 `implies` 移出，改为按轴声明成员归属、条数由合成规则算 | 要给判定引擎引入「派生字段」，改动面与回归风险都大；单轴四选项已能完整表达同一自由度 |
| 选项 id 用语义名（`both`/`no_month`/`no_caliber`/`neither`） | `derive_stance` 从 `diff_count` 直接产 `str(int)`；加一层「数→名」映射 = 多一处会漂移的地方 |
| 直接把 `pointer_id` 降到**文件级** | 会与 `file_key` 重复，且抹掉「同一文件第 10 行 vs 第 20 行算新观测」。宁可保留残余绕过并如实写明 |
| 用 mtime/`generated_at` 作 wall-clock 代理 | 复制/解压会重置 mtime；且含人类停顿，不是任务耗时。会给出**看似客观实则错**的数字 |
| `usage` 一律设为 required | round2 与全部夹具立刻失格。与 `contract_version` 同构按轮次门控才对 |
| 重写 round2 历史产物使其与当前 spec 对齐 | 篡改审计轨迹。历史产物的 sha 本就是时点凭证 |
