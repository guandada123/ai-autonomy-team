# D-0048 · 代码行数表纳入门禁 B 项（同步工具 + 校验一体）

- **日期**：2026-10-23 21:28
- **决策者**：用户（本轮"继续推进"授权自主选点）；依据 / 弃因见下
- **操作分级**：🟢 低（只动校验与同步脚本，可回滚）
- **状态**：生效

## 决定

1. `sync_doc_numbers.py` 增加「代码行数表」同步：`| `xxx.py` | NNN |` 的 NNN 改成实际行数；
2. `check_docs_consistency.py` 的 **B 项**（索引行数）从「只看 `docs/*.md` 的 markdown 链接」
   扩展到「状态文档里的代码行数表」——不新增门禁字母，8 项门禁计数不变。

## 为什么

`ARCHITECTURE.md` 的模块表里有一列「行数」，是给人判断「这文件多大、改它值不值」用的。
2026-10-23 实测：**28 行里 17 行与实际不符**，最大偏差 164 行：

| 文件 | 声明 | 实际 |
|---|---|---|
| `snapshot_sources.py` | 217 | 381 |
| `check_docs_consistency.py` | 165 | 307 |
| `redact_report.py` | 155 | 248 |
| `pre_release_check.py` | 234 | 275 |
| `new_round.py` | 1113 | 1154 |

这张表**从来不参与任何检查**：B 项的正则要求 `[`文件`](链接) | 行数 |`（markdown 链接），
而这里是裸文件名。同一类数字，两种写法，只检了其中一种。

这不是新问题：项目文档里已记过四次「索引行数值没跟上被引用文件的行数变化」，
前四次都修在 `docs/`，这张表一直漏在视野外。

## 为什么放 B 项而不是新增 F 项

| 备选 | 弃因 |
|---|---|
| 新增 F 项「代码行数」 | 8 项门禁要变 9 项，文档里所有「门禁 8/8」跟着改——**机制扩张**换来零新增能力 |
| 只手工同步一次 | 下次改代码又飘；这类数字靠人记必然复发（已复发四次） |
| 纳入 B 项 | 同一性质（索引行数）合并计一处，输出仍是 `B. 索引行数 : 校验 31 处`，**机制扩展** |

## 解析口径（避免误伤）

- 只认**第二格是纯数字**的表行；`| `judges/seat_check.py` | `metrics.py`、`new_round.py` | … |`
  这种「依赖关系表」不会被当成行数；
- 文件定位顺序：`scripts/` → 仓库根 → `migration-package/`
  （表里既有 `judges/seat_check.py` 这种源树相对路径，也有 `precheck.py`（包内）这种只在包里存在的）；
- 找不到文件 → 报 B 类问题「引用了不存在的脚本」，不是静默跳过。

## 风险

| # | 风险 | 处置 |
|---|---|---|
| 1 | 表格写法变了（如改成链接）导致正则失效 | 失效即静默漏检——由「校验点数」可见（B 项从 31 掉回 14 就是信号），`make check` 每次打印该数 |
| 2 | 同名文件（`verify.py` 在源树与包内都有）解析到错的一侧 | 定位顺序固定为源码树优先；包内独有文件（`precheck.py`、`gen_manifest.py`）才落到包 |
| 3 | 行数随每次改动变化，同步动作变频繁 | 这正是它该有的样子：`make sync-docs` 一条命令改完，且门禁会告诉你漏了 |
