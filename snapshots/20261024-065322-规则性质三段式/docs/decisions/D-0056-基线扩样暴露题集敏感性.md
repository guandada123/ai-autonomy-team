- **日期**：2026-10-24 01:00

- **操作分级**：🟢 低（只新增测量产物与记录）
- **状态**：生效

## 决定

把单 agent 基线任务集从 9 题扩到 **30 题**，新增 21 题的来源改为
**git 历史 / 旧文件 / 跨会话记忆**，并**故意放入 3 道我并不确定的题**

## 核心发现：基线对题集极度敏感

**同一模型、同一会话、同一判分口径，只换题集：100% → 61.1%。**

所以"单 agent 基线是多少"这个问题**目前没有意义**——它测的是"题集怎么选"。
V2 的真正前提因此不是样本量，而是：

1. **题集先固定**：题面、口径、判分方式一次性写死，之后不再增删；
2. **题集经独立评审**：不能由实现者同时出题、答题、判分；
3. 在此之上才谈 n 要多少。

按合计点估计 74.1% 代入 margin 5pp，多席位需零失败 n≥12——这个数字**没有意义**，
因为它建立在一个还没固定的题集上。

## 顺带发现（两件，都比分数重要）

### 1. 注入式记忆与磁盘记忆不一致

做题对不齐才发现：**会话开始时注入的摘要**与**磁盘上的 `MEMORY.md`** 不是一回事。

| 项 | 注入摘要 | 磁盘 MEMORY.md |
|---|---|---|
| 持仓 | 5 只，含长电 600584、华天 002185、**招行**、美的、紫金 | L144：实盘 3 只（长电 600584 / 华天 002185 / **国金**）+ 模拟 3 只 = **6 只**，无招行 |
| 本金 | 实盘本金 ¥50,000（3 万基础 + 2 万加仓） | L144：**模拟盘**总资 ¥50,000 |
| 半导体 | 占比 77%，上限 50% | 全文 grep「半导体」**0 命中** |

文件 L251 自己解释了原因：注入上限约在 L98，**L100 之后的内容读不到，除非主动 grep**。
推论：注入摘要要么来自另一源、要么已过期；**磁盘文件才是当前真源**。
本轮 Q21/Q23 因此被判"无真源/口径分歧"而排除——不是答错，是问题没有可验证的答案。

**给用户的动作**：以磁盘 `MEMORY.md` L143–L148 为准校正实盘/模拟盘口径；
若希望"半导体上限 50%"这类铁律每次生效，须写进规则层（L98 之前）。

### 2. 又两处口径分歧

- **Q27**：同一会话的两份摘要分别写"1126 项测试"与"1118+ passed"——测试总数与
  passed 数是两个口径，题面必须说清问哪个。
- 加上上一轮的 **T01**（`make backup` 报 9,197 个文件 vs `tar -tzf` 10,024 条目），
  本基线两轮共出现 **4 次口径分歧**——全部靠"排除该题"解决，没有一次靠猜。

## 明确不做

- ❌ **不把 74.1% 或 100% 当作"模型能力"的报告**：它报告的是题集与记忆口径；
- ❌ **不据此启动多席位对照**：题集未固定，对照数字不可解读；
- ❌ **不为了凑分数改题**：改题就等于换基线，历史分数全部作废。

### 从这 5 条更正里提炼的三条出题标准（已写入清单，今后每题必过）

1. **问数量必带时点**（截至 X 日）——Q21/Q27 两例；
2. **问规则值不必带板块，问实际值必须带**——Q24 一例；
3. **问文件数必说明算不算文件夹**——T01 一例。

**性质修正（三段式，用户 2026-10-24 06:53 原话校正）**：

1. **建议由 AI 提出**（半导体 ≤50%、止损 −8%）——不是用户自己定的规矩；
2. **用户同意了该提议**——形成过共识，不是单方主张；
3. **实际操作未按建议执行**——半导体实际 77%，偏离 27pp。

因此表述必须三段齐全：既不能说成「硬约束」（它源自建议），也不能淡化成「随口一说」（用户同意过）。
统一说法：**「用户同意过的建议，实际未执行」**。后续判断不得再简写为「上限 50%」。
