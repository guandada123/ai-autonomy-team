## 1. V2：选 A 之后发现 A 不等于"零成本"

用户选 A 的理由是"拿实测基线当参照，成本近零，n=20 立刻可用"。
落地时查历史基线，发现这个前提不成立：

| 事实 | 出处 |
|---|---|
| 唯一的单 agent 实测 = **14/14 全过**（= 100%） | `migration-package/docs/验证报告.md` §3.1 |
| 且它是 **n=1**（一条合成任务），报告自陈"样本量远不足" | 同文件 §2 注释 |
| 14/14 是**检查项**通过率，不是任务级正确率 | 同上 |

代入非劣效 margin 5pp（需下界 ≥ 参照 − 0.05）：

- 按点估计 100% 代入 → 需 **n ≥ 59**（`ln0.05/ln0.95 ≈ 58.4`）；
- 按 n=1 的诚实下界（单侧 95% ≈ 0.05）代入 → 任何 n 都过 = **判据空转**。

两条路都不可取，说明 A 的真实前提是**先在留出集上测出基线**——而这一步
（扩样 20 条留出任务）自 2026-10-16 起被四份决策反复列入，从未做过。

**因此 V2 改写为**：参照 = 单 agent 在留出集上的实测通过率；**实测前 V2 不可评**；
参照实测后按 `n ≥ ln0.05/ln(参照−0.05)` 定所需样本量。
（我在上轮说"A 成本近零"是错的，已向用户更正。）

## 2. 否决窗口：按"否决权不得悄悄过期"设计

原状（实测）：33 轮 `verdict-layered.json` 里 `veto_deadline` **0 处存在**，
`params` 只有 `veto_window_hours: 24`，无脚本读取 → "超时视为接受"是口头约定。

新增 `scripts/veto_sweep.py`，四条设计约束：

| 约束 | 实现 |
|---|---|
| 否决权不因没人跑扫描而过期 | "超时视为接受"改为**必须显式 `--settle` 才算接受**；未 settle 一直留在待裁清单 |
| 不造"没人开的闹钟" | 无需常驻/调度器：`--list` 是人想看时跑的（同 `make backup-list`） |
| 否决随时可用 | `--reject` 在 settle 之前任何时刻可用，需 `--who` + `--reason` |
| 一条结论只记一次否决 | 重复 `--reject` 返回 rc=2 并拒绝覆盖——否则会抹掉"第一次为什么否"的证据 |

写入面只限 verdict 的三个字段（`veto_deadline` / `human_veto` / `accepted_at`），
原子写；窗口小时数只从 `params` 读（单一真源）。

**可证伪（实测）**：未盖戳 → `❓` 暴露；盖戳 → `⏳ 24.0h` 且 `--list` exit 1；
否决 → `🚫`；重复否决 → rc=2；到期 → `⌛`，`--settle` 后 `✅`。
`make veto-list` 对 33 轮历史结论全部显示 `❓ 未盖戳`——**这是诚实的暴露，不是失败**。
