## 为什么

三处都是 fail-open：缺文件、缺参数、缺输入时**悄悄跳过**，输出与"检查通过"无法区分。

| 项 | 修前实测 |
|---|---|
| C1 | 无 `--premise-card` → 记一行"本轮不做前提审查"后放行；`premise_probe.py` 缺失 → 记一行"跳过"后放行 |
| C2 | `--routing-json` 指向空文件 → `xj_family_check=null`，与"没做"和"通过"三者不可区分 |
| C3 | 上游删掉/改名夹具后，旧副本长期留在 `_trash/tmp-regress/fixtures`，测试可能读旧文件而"通过" |

## C4 为什么不做

四份 `sh()/_run()/run()` 的差异是**语义差异**，不是复制粘贴：

| 位置 | 超时 | 编码 | 返回 |
|---|---|---|---|
| `pre_release_check.py:58` | `None`（不设） | 默认 | `(rc, out+err)` |
| `verify_handover.py:53` | 300 s | 默认 | 同上 |
| `make_backup.py:54` | 无 | `text` 可关 | 同上 |
| `regress.py:49` | 无 | `utf-8 + errors=replace` | 同上 |

合并需要把这些差异全部参数化，收益约 20 行，代价是四条门禁路径同时改动。**收益 < 风险**，保留现状。`seat_check.py` 内部同名 helper 是**有意不抽**（docstring 已写明：避免冻结裁判依赖可变模块），更不应合并。
