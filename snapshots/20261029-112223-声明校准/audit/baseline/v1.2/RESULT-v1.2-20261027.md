## 五、四个发现

### 5.1 满分不是好消息，是量程不够

两臂同时满分、25 题零分歧 —— 这不是"多席与单席一样好"，是**这份卷子分不出高下**（与 v1.1 同一结论）。
事实核查类题目对"单席 vs 多席"的区分度已耗尽：**要回答"要不要开三席"，只能上判断类题库（v2）**。

### 5.2 Q19 的 quotepath 陷阱被多数票吃掉（本轮唯一的真实分歧）

| 席 | Q19 | 做法 |
|---|---|---|
| S1 | **284** ❌ | `git ls-tree -r \| grep -c '\.md$'` —— git 默认 `quotepath` 给中文名加引号，全部非 ASCII 名被漏掉 |
| M1 / S2 / S3 | 654 ✅ | 用 `-z` + 按后缀精确判定 |

三票 2:1 → 多数票 654 = 真值。**多数票能压掉工具/方法噪声**（一个席位踩坑、两个没有），
这与 v1.1 的"格式噪声被 2:1 吃掉"是同一机制；但**压不掉同源盲点**——本轮没出现同源盲点，
不是因为它不存在，是因为四席同源却恰好方法不同。

### 5.3 T05 的 attested 真值 54 与 git 静态数不一致（遗留疑点，**未动**）

四席都用"静态解析 `s.check/s.expect` 的项号（1..54 无缺号）"答出 54。
但 `git show 156d33d:scripts/regress.py` 里 `s.check(` + `s.expect(` 的**调用点共 56 处**，
与真值 54 不符（可能含条件跳过/循环展开）。

- 未改真值、未改题面（草案不含此项，不顺手改）；
- 记入 v1.3 待办：T05 应改为"读最近一次门禁记录"或退役。

### 5.4 T03 的单位口径没写进题面（潜在歧义）

77,294,725 字节：按 1024 进制 = **73.7**（仓库 `scripts/make_backup.py::human()` 的口径，四席都取此值）；
按 10⁶ 进制 = 77.3。题面只写"MB，一位小数"，**两种读法都可辩护**——与 v1.1 作废三题是同一类缺陷。
本轮四席恰好同取 73.7 才没暴露。记入 v1.3 待办：题面写明"1024 进制"。

### ★ 口径声明（请读者自行采信哪一档）

本轮提示词把「禁读」定义为**不得打开 / 不得取内容**，允许文件名出现在检索输出（**须如实申报**）。
这比 v1.1 的 S2b 判定**宽松一档**：

- v1.1 作废 S2b 的决定性依据不是"扫到目录"，而是**有污染迹象**（Q31 精确命中只在 baseline 里存在的 867）；
- 本轮 M1/S1 均无污染迹象（没有任何答案只可能来自 `audit/baseline/`）。

**若读者采用"扫到即作废"的更严标准，本轮两臂都不成立**：M1 作废 → 单席臂为空；
S1 作废 → 三席只剩 2 席，无法形成多数票。此为口径选择的影响，已在此声明，不在结论里藏。
