# L-0035 自检夹具写进源码，会被「被校验的扫描器」当成真实内容

**日期**：2026-10-29
**标签**：自引用 / 测试夹具 / 扫描器 / 门禁假绿
**性质**：跨项目通用（任何「测试数据 → 源码字面量 → 同一套扫描器」的组合）
**状态**：已实测（ai-autonomy-team：给 `pre_release_check.py` 补 `--self-test` 时当场踩中）

## 发生了什么

给门禁补自检时，F 项（决策编号）需要造两个样本编号：一个"有对应文件"、一个"文件缺失"。
直接写成字面量：

```python
(r / "README.md").write_text("见 D-8888。\n")     # 期望：假仓库里被判缺失
```

跑真门禁，屏幕上是：

```
🔴 F 决策编号   缺文件: D-8888（D-0017,D-9999 已标注未建）
```

**真仓库里多了两个"缺失决策"**——因为 F 项的扫描范围包含 `scripts/*.py`，
我自己写的夹具文本正躺在里面。更阴的是那个 `D-9999（未建）`：
它撞上了 F 项自己的 `INTENTIONAL_ABSENT` 豁免正则，**把自己的污染标记成"已标注未建"**，
于是输出里看起来"有豁免、很规矩"，反而更难被发现。

同一模式的三个变体，本项目已中过三次：

| 变体 | 后果 | 已有防线 |
|---|---|---|
| `unlink(` 字样进扫描脚本 | 回归第 20 项自己扫自己 | 模式串拼接构造 + 跳过注释行 |
| `sk-…` 假密钥进源码 | 门禁 E 判本仓库泄露 | 运行时拼接 `"sk-" + "A"*26` |
| `D-NNNN` 进源码 | 门禁 F 判本仓库缺决策 | 本次改为 `"D-" + "8888"` |

## 教训

1. **凡是"扫描 `scripts/` 自身"的检查，源码里就不能出现被判据认作事实的字面量。**
   判据的对象范围一旦包含代码目录，代码里的**示例、夹具、注释**就都是"事实"。
   不是"测试不严谨"，而是**测试数据参与了它正在测试的那次判定**。
2. **写夹具前先问一句：这个值会被哪个门禁扫到？** 被判据扫到的目录里，
   任何"故意造的坏值"都必须**运行时拼出来**，不能落在字面量上。
3. **最危险的不是红，是"豁免把自己也豁免了"。** 本次 `D-9999（未建）` 触发了
   `INTENTIONAL_ABSENT` ——判据的豁免机制无法区分"文档声明某编号未建"和
   "测试夹具里写了这串字"。凡是**基于文本模式的豁免**，都要假设它会豁免掉自己的测试数据。
4. **发现路径值得记**：这不是我自检出来的，是**真门禁在真仓库上红给我看的**。
   也就是说"给门禁补自检"这件事，第一步收益就来自门禁本身——它先抓到了它的测试者。
5. **修法验证要带对照**：改完后 `grep -n "D-[0-9]\{4\}"` 必须只剩真实引用（本项目 3 处，
   全是 D-0053 的历史注释与说明），再跑门禁确认 F 项恢复"全覆盖（D-0017 已标注未建）"。
