# L-0041 接线检查的字面匹配会误报历史文档的"区间写法"——展开规范区间，不回溯改历史

**日期**：2026-10-30
**标签**：接线检查 / 字面匹配 / 区间写法 / 历史文档 / 可证伪
**类型**：跨项目通用
**性质**：凡是"检查 id 是否在某文档中真实出现"的一致性校验
**状态**：已实测（A5 用例修订，13/13 + 反向探针自证）

## 发生了什么

A5 接线核对（manifest 的 qid 是否都出现在题库文档中）首跑 12/13：报 T07/T08
"不在 questions-v1.3.md"。取证后发现题面真实存在——v1.3 文档用区间写法
「T06–T09」引用这批题（写明"同 v1.2"），字面匹配自然找不到。

## 裁决与教训

1. **历史产出不回溯改判**：为过检查器而改写已冻结的实验文档，会让历史记录失去
   可信度。正确方向是让检查器理解文档的真实写法，而不是让历史迁就工具。
2. **豁免必须可证伪**：检查器只认规范格式（`T数字[–—-]T数字`），起点>终点的
   异常区间一律不展开；豁免后用**反向探针**自证契约未放松（构造 `T07x`、`T99`、
   真缺的 `Q21` 均须报红）。没有反向探针的豁免等于拆掉闸门。
3. **先取证再裁决**：12/13 的失败先查"是真缺题还是写法问题"（对照 v1.2 题库），
   确认是写法问题后才裁决豁免——若直接放宽断言，真缺题也会被放过。

- `test_route_gate.py`：新增 `_RANGE_RE` + `_expand_ranges()`（零填充宽度取两端最大），
  A5 改为「字面出现 ∪ 区间展开」比对，注释写明裁决依据与日期

## 一句话

**检查器报红先分清"真缺陷"还是"写法差异"：前者修数据，后者扩检查器——但扩检查器必须带反向探针，否则豁免就是漏洞。**
