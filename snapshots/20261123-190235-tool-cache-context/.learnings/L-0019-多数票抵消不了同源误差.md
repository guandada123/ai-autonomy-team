# L-0019 · 多数票只能抵消随机误差，抵消不了同源误差

- **日期**：2026-10-24
- **发现场景**：v1.1 同条件对照实验（1 单席 + 3 席，可查仓库）
- **性质**：跨项目通用（多席位/多人评审/模型集成）★ 升级候选 〔🔁auto-promote-2026-11-22·✅已评估·同族覆盖→「多数票只抵随机误差,抵不了同源误差」〕

## 现象（两处，同一根因）

### ① 多个独立席位一致地答错

Q25、Q26 两题，**不同席位给出完全相同的答案**（87、86），且都不是真值：

| 题 | 各席答案 | 真值 | 各席引用的来源 |
|---|---|---|---|
| Q25 | 87（多席一致） | 80 | 同一行：`docs/自治团队方案-审计-20261022.md:128` |
| Q26 | 86（多席一致） | 89.69 | 同一行：同文件 `:126`「覆盖率 86 硬门槛」 |

它们不是随机错，是**读了同一行、走了同一条推理**。

### ② 并发实测互相踩，制造假红

`scripts/regress.py` 的 scratch 根是**固定路径** `_trash/tmp-regress`。
两席同时跑回归 → 互相覆盖 → 回归从 54/54 变红；**单独跑立刻全绿**。

同一份代码、同一台机器，只因"同时跑"，结论从"通过"变成"失败"。

## 真实原因

**误差有相关性**。多席位共享同一份材料、同一个仓库、同一种阅读顺序时，
它们的错误不是独立抽样，而是**同一次抽样被复制了三份**。

```
独立误差：三票多数 → 把单票错误概率 p 压到 3p²−2p³
同源误差：三票等于一票 → 压不下去，反而把 p 抬成"高置信度的 p"
```

并发污染是同源的另一面：**共享可变状态**（固定临时目录），
两个"独立"执行者其实在写同一块地。

## 为什么危险

1. **它长得最像正确答案**：一致票 + 高置信度 + 有出处（哪怕是同一处）；
2. **聚合规则会放大它**：多数票机制的前提是"误差独立"，前提不成立时，
   聚合把"三份相同错误"升级成"共识"；
3. **本项目协议里已预言**：`02-辩论协议.md` 写「全体一致且无独立证据 → 触发魔鬼代言人轮」，
   但这条在事实核查场景里从未被执行过——因为没有"独立证据"的判定方式。

## 结论（纪律）

1. **聚合前先查同源**：每席必须交 `evidence` 指针，**若多席指向同一文件同一行，视为一票**；
2. **一致性不是正确性**：全体一致时不要加分，要**加一次反证**（魔鬼代言人轮）；
3. **实测型任务禁止并发共享状态**：要么串行，要么每次执行用独立临时目录（`mktemp -d`），
   否则"独立席位"在物理上并不独立；
4. **报告里必须写"误差是否独立"**，不能只写"三席一致"。

## 可迁移到哪里

- 多人代码评审（同一份 diff、同一种 lint 提示 → 会一起漏同一处）；
- 模型集成 / self-consistency（同模型多次采样，错误高度相关）；
- A/B 测试（共享同一批用户、同一时间窗 → 组间不独立）；
- 任何"投票"机制：**先问票与票之间是否独立，再问票数。**

## 落地动作（本项目）

- `audit/baseline/v1.1/RESULT-v1.1-20261024.md` §5.1/§5.2 记录了现场证据；
- v1.1 题面对 T05 标注"并发会互相踩"，要求串行或改读门禁记录；
- 后续 v2（判断类）席位契约里，`reads` 必须与 `evidence` 一起交，用于同源检测。

## 追加（同日，第二轮实测）：格式差异会被记成"分歧"

T05 三席实际都指向同一个数，但写法不同：

| 席 | 作答 |
|---|---|
| M1 | `54` |
| S1 | `54` |
| S3 | `"54/54"`（照抄回归末行） |

聚合器把 `"54/54"` 与 `54` 判为两票不同 → 2 席口径下无多数票 → 按"未作答"计 → `c=1`（多席"输"一题）。

**同一个事实，只因写法不同，就被记成能力差异。** 与 v1 判分器"字典 vs 列表"误杀是同一族问题。

结论补充：

5. **聚合前必须做答案规范化**（同一语义的不同写法不算分歧），且规范化规则要写进题面；
6. 报告里凡出现"分歧"，先问一句：**这是实质分歧，还是格式分歧？**
