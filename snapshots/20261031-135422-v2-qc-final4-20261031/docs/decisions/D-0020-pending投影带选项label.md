# D-0020 · pending 投影必须带选项 label（纯数字选项不可签）

- **日期**：2026-10-20（补落为正式文件；实施早于此）
- **依据来源**：`migration-package/judges/verify.py:878` 注释
- **操作分级**：🟢 低（投影字段增补）
- **状态**：已执行

## 决策

`pending_view()` 输出的待裁投影，除 `id` 外**必须包含 `label`**，供人闸门签署时阅读。

## 依据

| # | 依据 | 来源 |
|---|---|---|
| 1 | ADJ-002（清单范围）的四个选项是**纯数字** `'6'` / `'5'` / `'4'` / `'3'`，人类无法从 id 判断签的是「两类都列入」还是「只列入 X 类」 | `make_tasks_20.py` `opts2` 构造 |
| 2 | 待裁投影是给人看的（人闸门），不是给机器反推用的；id 供机器、label 供人 | `verify.py` `pending_view` |
| 3 | 实测：20 个任务的 ADJ-002 选项 id 恒为 `['6','5','4','3']`，仅 label 区分语义 | 契约 3.0 裁定记录 §8.2 ④ |

## 备选方案与未采用理由

| 备选 | 未采用理由 |
|---|---|
| 只给 id，靠人回查 spec | 签署时无法自足；签字动作与理解动作分离会引入误签 |
| 给 id + 完整 question | question 已在外层；label 才是选项级的最小充分信息 |

## 审计发现

**机器可辨 ≠ 人类可签**。同一个字段在机器侧（implies 反推用 id）和人侧（签字用 label）
需要不同的表示；只提供机器侧表示会让「签字」变成盲签。

## 落地校验

| 校验 | 方法 | 期望 |
|---|---|---|
| 投影含 label | `verify.py --spec-dir ... --answer ...`（无 --record） | `pending[].options[].label` 非空 |
