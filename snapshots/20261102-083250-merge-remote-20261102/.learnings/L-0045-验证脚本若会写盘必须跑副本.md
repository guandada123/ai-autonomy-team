# L-0045 验证脚本若会写盘，必须跑副本或跑完还原——否则污染工作树并让门禁在 CI 红

**日期**：2026-11-01
**标签**：验证方法 / 副作用 / 门禁 / CI / 可复现性
**类型**：跨项目通用
**性质**：任何"拿现有脚本做验证"的场景（评分脚本、生成器、迁移工具、格式化器）
**状态**：已实测（2026-11-01：跑 `score_v2_passk.py --multi-name r4` 验证 ruff 修复，改写被追踪的 `score-summary.json`，本地门禁全绿、CI 的 H 闸红）

## 现象

修完 ruff 报的 6 处后，为确认"被改文件仍能跑"，我执行了 `score_v2_passk.py --multi-name r4`。
它跑通了、输出正常——**但它顺手把结果写进了被 Git 追踪的 `score-summary.json`**（多了一个 `"multi_name": "r4"` 字段）。

后果链：
1. 本地工作树被悄悄改动（我没提交它，因为没意识到它变了）；
2. 打快照 → 快照里含**被污染**的版本；
3. 本地门禁全绿（真源与快照在磁盘上是一致的）；
4. **CI 红**：CI 只有已提交文件，真源是旧版、快照是新版 → H 真源快照闸报不一致。

即：本地全绿掩盖了"我漏提交一个被自己改动的文件"。

## 判据

一个脚本能当"验证工具"用，必须满足其一：

| 方式 | 做法 | 适用 |
|---|---|---|
| **只读** | 脚本支持 `--dry-run` / `--check` / 输出到 stdout | 首选 |
| **副本** | 在 `cp` 出的临时目录里跑，读结果、丢弃副作用 | 次选 |
| **跑完还原** | `git checkout -- <被写文件>`，并在提交前 `git status` 复核 | 兜底 |

三条都不做 = 把验证变成了修改。

## 做法（本次实际）

`git checkout -- audit/baseline/v2/score-summary.json` 回滚；重新打快照；提交前用
`git status --short` 逐项确认"每个改动都是我预期的"。

## 边界

- 不是"不要跑脚本验证"——恰恰相反，改完必须跑；要求的是**跑之前想清楚它会写什么**。
- 与既有铁律同源：`像查询实会写盘的函数须验三件事`。本条是它在"验证环节"的具体化：
  **验证者自己也会污染被测系统**。
