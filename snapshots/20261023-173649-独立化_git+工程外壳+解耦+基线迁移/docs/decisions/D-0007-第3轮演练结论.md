## 四、本轮暴露的三个新缺陷

### F26 🔴 审计席位的读取域与它的职责互斥

AD-01 为履行第 1/3 查，读了 `runs/round2/` 的 6 个文件 → 8 条 `E_READ_DOMAIN_VIOLATION`
→ 被判 `invalid` → `aggregation_blocked` 非空 → **`metrics` exit 5（blocked_by_contract）**。

**这是契约缺口，不是席位过错**（先例：`L-0003` 判定越权写入为契约缺陷）。
修法：`expand_domain` 新增 `{prev}` 占位符；`read_domains.json` 给 AD-01 追加
`runs/round{prev}/`（**只上一轮，不是全部历史**；且只给 AD-01，不给 PM/XJ）。

**残余风险（已写进配置）**：AD-01 因此能看到上一轮的结论与裁决。审计席位看到历史答案是
有代价的 —— 它可能被锚定。这比「让它闭着眼睛审计」更可取，但不等于无代价。

### F25 🔴 净化层只擦上一轮，把答案路径递进了辩论包

`runs/round3/inputs/pack-ANON-B.json` 与 `pack-ANON-C.json` 里残留
`runs/round1/adjudicated.json` —— 该文件含 `verdict=adjudicated` 与全部 `expected`。
而 `redaction.json` 的 `targets` 只有 `runs/round2/`。

这与 F5 是同一件事的第二种形态：F5 防的是席位**主动去读**答案，
F25 漏的是净化层把答案的**路径字符串**留在了包里。

修法：`read_domain_targets` 改为枚举 `runs/` 下**全部** `round*` 目录（当前轮除外）。
回归第 37 项新增断言：`runs/round1/` 与 `runs/round2/` 在 targets 内、`runs/round3/` 不在。

### F27 🟠 预算上限是按估值填的，实测被超 57%

`per_task_token_hard_cap=80000`，六席申报合计 **126100** → `terminate_branch`，exit 4。
`params._basis` 自己写着「填 80000/30 使『预算耗尽』终止条件**可执行**」——
即那个数字是为了让条款能跑，不是实测出来的。

**不重跑、不改 cap 让它变绿。** 建议 round4 前按本轮实测重设（并注意 `minutes_span=21`
仍在 30 分钟内，wall-clock 侧没问题）。

## 五、备选方案与未采用理由

| 备选 | 未采用理由 |
|---|---|
| 代签裁决记录 | 等于由机器伪造人类签名。校验器只看声明字段，**伪造不会被报警** —— 这是整套设计唯一真正脆的一环 |
| 发现 F26 后直接把 AD-01 判为「越权」并冻结其产出 | 它做的事正是它的职责要求的。判它错等于宣布「审计席位不得对比上一轮」，那第 1/3 查就永远无法完成 |
| 修 F25 后重新生成 round3 的包并重跑六席 | 会得到一个「干净的」第 3 轮，但它不再是真实观测。保留已知污染并如实记录，比制造一次无瑕重演更可信 |
| 把 `note` 列的类别标注删掉再跑 | 实测类别标签**不参与打分**（`categories` 判据是 `present`）。删它不改变任何结论，只增加一次重跑成本 |
| 把 round3 的 exit 4 通过调高 cap 改成 0 | 报警是真实的。把阈值调到刚好不报警，与删掉报警没有区别 |
