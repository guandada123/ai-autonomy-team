# 01 · 架构：单写多读 + 双裁判 + 分歧守恒

> 本文件是机制的定义源。任何席位提示词、脚本、审计清单都不得与本文件冲突；若冲突，以本文件为准，并须走决策日志修订。

## 0. 一句话

**读并行、写单线程、硬裁判有否决权、软裁判只提示、辩论强制保分歧。**

## 1. 为什么是这个架构（不是偏好，是证据的结论）

| 设计选择 | 依据 | 若不这样做会怎样 |
|---|---|---|
| 写单线程 | Cognition：并行写入的 Agent 各自做出「合理」的隐含决策，合起来互相冲突（典型：一个画马里奥背景、一个画风格不兼容的小鸟） | 产出表面完整、内在不一致，且不一致无法被下游发现 |
| 读并行 | Anthropic：编排-工作者模式下读密集型的宽度优先任务相对单 agent 提升 90.2%，且 token 消耗单独解释方差 80% | 放弃唯一被验证有效的并行收益来源 |
| 硬裁判必须非 LLM | LLM-as-Judge 实测：两个各自准确率 87% / 83% 的评委彼此一致率 94%，误差独立时应为 74.4% —— 约 20 个百分点的共享误差，任何交叉检查都照不出来 | 评委变成「同意的机器」，共享盲区永久不可见 |
| 审计只驳结构不驳结论 | MAST：验证失效是独立一类（错误验证 9.1% + 无/不完整验证 8.2%），且**验证者 Agent 继承同样的失效模式** | 审计开始「制造确定性」而不是「发现不确定性」，且披着独立审计的外衣更难被发现 |
| 强制保分歧 | 受控实验：提升推理质量（0.72→0.84, d≈2.0）与夏普比率 r=0.07(p=0.29)、收益 r=0.03(p=0.70) **无统计关系**；而显式保护分歧的干预使夏普 +0.14(p=0.028)、索提诺 +0.25(p=0.026) | 优化了一个与结果无关的量，并把它当作改进 |
| 证据制而非投票制 | 同上；另：鞅分析证明无方向性干预的辩论**只保持原有期望值**，即辩论本身不具纠正性 | 多数票会把「谁更自信」当成「谁更对」 |

## 2. 三个角色层的权限边界

```
读并行区（只读 · 只提案）
  EX-01 事实与数据 | EX-02 对立面(异族) | EX-03 落地与成本
         │  产出：结论 + 证据指针 + 证伪条件 + 读取申报（reads[]）
         ▼
写单线程
  PM-01  唯一写权限。只能追加「决定 + 理由 + 风险边界」元数据，
         不得改写任何原始结论（含少数派结论）
         │
         ├──▶ 硬裁判 JD-01（非 LLM · 有否决权 · 不可静默覆盖）
         └──▶ 软裁判 XJ-01（跨家族 · 仅提示 · 权重为 0 于决策）

贯穿全程
  AD-01 结构审计（与 PM 不同家族 · 干净上下文 · HOLD 权 · 无否决权）
```

## 3. 四条不可协商的硬约束

1. **写权限唯一化。** 任何时刻只有一个主体能写入共享产物。其余一律只读、只提案。
   **「只读」不只是权限，更是读取范围** —— 席位能读什么，由 `config/read_domains.json`
   显式声明，并由结构审计**第 9 查**检测（定义见 `06-写入域与判据分层.md` 第三节）。
   注意两者强度不对称：写入有前后快照可比（第 8 查），读取不改变任何东西，
   故第 9 查只能检出**申报的**与**用作证据的**路径，无法发现未申报的读取。
   **写入域**（允许/禁止目录）见 `06-写入域与判据分层.md` 与 `config/write_domains.json`；
   由结构审计**第 8 查**自动判定是否被违反 —— 「只读」不能只是文本约束。
2. **裁判优先于人数。** 聚合规则：`硬裁判通过 > 有独立证据支持的少数 > 无证据的多数`。无独立证据时，「多数」权重为零。
   **硬裁判只对算术层有否决权**；判断项交人类闸门（见 `06-写入域与判据分层.md`）。
3. **分歧守恒。** 不设「必须达成一致」的终止条件。轮次用尽时**强制保留多数与少数两份结论**，各自附证伪条件。禁止为收尾好看而抹平分歧。
4. **硬闸门不可静默覆盖。** JD-01 判 fail 的动作禁止推进；PM 若要推进，必须按固定格式留痕（见 `04-双裁判规范.md`）。

## 4. 独立性分级（决定每个信源的权重）

独立性不是「措辞不同」而是「误差不相关」。按实测排序，权重自高至低：

| 级别 | 信源 | 独立性 | 权重 |
|---|---|---|---|
| S | 可执行校验器（脚本、回算、单测、A/B） | 最高：规则式/执行式检查器 buys the most independence | **有否决权** |
| A | 跨家族模型评委（与产出者不同厂商） | 有限但真实 | 仅提示，决策权重 0 |
| B | 同家族但匿名 + 乱序 + 长度归一化 | 接近零（同模型换提示词 ≈ 无效） | **禁止作为决策依据** |
| C | 自评 / 自我打分 | 负值（Goodhart：长度与胜负相关性 0.98、先出现者胜率 63%） | **禁止出现** |

> **实测状态（2026-10-16 本机）**：跨家族路由已通过 L0 验证（子代理被成功路由至智谱 GLM），故 A 级信源**真实可用**，无需降级。
> 核验工具：`scripts/inspect_agent_routing.py`

## 5. 本架构明确不接受的东西

- ❌ 「Agent 数量越多越智能」——MAST 处方是用**最少**的 Agent 数和划定边界的角色
- ❌ 同族自评作为质量判据
- ❌ 「我们已经达成一致」作为完成信号（共识可能是相关误差的高置信度表现）
- ❌ 无显式终止条件的开放辩论
- ❌ 审计输出「对/错」判断
- ❌ PM 改写原始结论
