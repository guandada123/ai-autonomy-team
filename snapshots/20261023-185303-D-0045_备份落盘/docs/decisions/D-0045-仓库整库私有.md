# D-0045 · 本仓库整库私有，不对外发布

- **日期**：2026-10-23 18:50
- **决策者**：用户（原话「整库私有，不用对外」）
- **操作分级**：🟢 低（只改声明与文档，不动代码、不动仓库结构）
- **状态**：已采纳，即刻生效

## 决定

**整库私有。不做公开仓库，也不做「脱敏拆库」。**

三条具体含义：

1. **不配公开远端**，也不为发布而裁剪目录；
2. `snapshots/`、`real-runs/`、`docs/交接文档*`、`audit/` **照旧入库**——
   它们本来就是证据的一部分，私有前提下没有理由为了「万一公开」而牺牲；
3. `scripts/redact_report.py` 保留，但**降级为按需工具**：只有在确实要把某份报告
   发给第三方时才用，不再是「发版必经步骤」。

## 为什么

| 理由 | 依据 |
|---|---|
| 库里有真实账户信息，公开等于自曝 | 实测：A 股代码形状六位数命中 18 个非快照文件，绝对路径 28 个；`real-runs/` 含券商名与账户金额 |
| 脱敏会破坏证据价值 | `real-runs/` 的意义是「真实账本对过账」；把代码换成「标的A」后，读者无法复核，只剩结论 |
| 使用场景只有本人 | 没有外部协作者、没有公开演示需求 → 私有不影响任何功能 |
| 拆库的维护成本高于收益 | 两套路径意味着两套 MANIFEST、两套回归基线，本项目已因「同一语义多副本」踩过四次 |

## 不做的事（明确排除，避免下次又被提出来）

- ❌ 不删 `snapshots/`「降低暴露」——**删副本不降暴露**：它们是 `docs/` 与 `scripts/`
  的副本，正本仍在库里。暴露面 = 内容 × 可达性，副本数量是假指标（见 §八）。
- ❌ 不为发布而把 `real-runs/` 移出仓库。
- ❌ 不加「公开/私有」双轨构建（两份 MANIFEST 必然分叉）。

## 已知风险（本决策的直接副作用，如实记录）

**私有 + 无远端 = 只有一个副本。** 仓库位于外置盘（`/Volumes/ZHITAI/...`），
盘坏 / 误删 / 目录被清 = 永久丢失，且没有任何异地副本。

这不是本次能顺手解决的事（需要选备份介质与加密口径），但要写下来，
否则「私有」会被误读成「安全」。

### 2026-10-23 已做的一半（只覆盖「外置盘坏了」这一种）

内盘有空余，先落了一份**经过还原验证**的副本：

| 产物 | 大小 | 覆盖什么 | 怎么验的 |
|---|---|---|---|
| `~/Backups/ai-autonomy-team/*.bundle`（`git bundle --all`） | 2.1 MB | 全部 git 历史（13 提交 / 1581 个受版本控制文件） | `git clone` 到临时目录，比对 HEAD / 提交数 / 文件数三项一致 |
| `~/Backups/ai-autonomy-team/snapshots-archive-*.tar.gz` | 24 MB | `_trash/snapshots-archive/`（81 个历史快照，6231 个文件；被 gitignore，**不在 bundle 里**） | `tar tzf` 条目数 = 源文件数；抽一个文件解包后 sha256 相同 |

**仍未覆盖的**（不要误以为已经安全）：

- **未加密**：内盘上就是明文，整机丢失或被盗时与仓库本体同等暴露；
- **同一台机器**：只防外置盘损坏/误删，不防系统性故障、误格式化、勒索软件；
- **未周期化**：这是手工一次性动作，下次改完不会有新备份 —— 需要一条定期任务，
  或至少把「改完顺手 backup」写进发版清单。

> 若要真正解决，需要一块异地介质或对象存储 + 加密口径（口令不能与备份放一起）。

## 重新评估的触发条件

出现下列任一情况，本决策需重开：

1. 要交给第三方（外包 / 审计 / 开源）→ 届时走 `redact_report.py` 生成对外版，本库仍不公开；
2. 要接 CI 跑到云端 → 需先决定 runner 是否可信；
3. 要放到公开代码托管做展示 → 只推 `scripts/` `docs/protocol/` `templates/`，且**重建**仓库而非脱敏现库。
