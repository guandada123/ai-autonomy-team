# 题库 v2 · 判断类（设计稿，2026-10-24）

> **为什么需要 v2**：v1 是事实核查题，天花板效应决定了它**测不出多席位的价值**——
> 三个和尚都会数数，数对了也说明不了"三个人比一个人强"。
> `D-0058` 早已写明这条定位限制；`D-0059` 又证明 v1 连"数得准"都做不到（8/27 真值失效）。
> 要回答「要不要开三席」，只能换题型。

## 一、题型：三选一裁决 + 风险 + 证伪条件

每题给一份**材料包**，要求每席输出：

```json
{
  "verdict": "do | dont | defer",          // 做 / 不做 / 延期（三选一，不许骑墙）
  "reasons": ["..."],                      // 支撑理由，每条须指向材料里的具体事实
  "top_risk": "如果这个裁决错了，最可能是因为什么",
  "falsification": "在什么条件下我这个裁决是错的",
  "confidence": "high | medium | low"
}
```

**为什么强制三选一**：允许"看情况"的题无法判分，也测不出分歧。

## 二、判分：不比"对错"，比"与参考裁决的关系"

| 指标 | 定义 | 权重 |
|---|---|---|
| **一致** | `verdict` 与参考裁决相同 | 主指标 |
| **反向且未提示风险** | verdict 相反，且 `top_risk` 未提到参考裁决里最担心的那条 | **危险失误**（单列，不折算成分数） |
| **理由覆盖** | `reasons` 是否命中参考裁决的「关键理由」清单 | 副指标（覆盖率） |
| **可裁决性** | 是否给出 `falsification` | 门槛（缺则整题不计分） |

**判据（双向，不做"非劣效"）**：

```
增益成立    ⟺  多席一致率 − 单席一致率 ≥ +10pp
无差异      ⟺  |差值| < 10pp
多席更差    ⟺  差值 ≤ −10pp
```

> ⚠️ **必须先说清的限度**：判断题噪声远大于事实题。12 题规模只能**看方向**，
> 不能判显著（要判显著需要 40+ 题 × 多轮）。任何报告都必须带这句限度。

## 三、参考裁决从哪来（这是 v2 的成败点）

**不能用模型自己产出的结论当参考**，否则等于自评。合格来源只有两类：

| 来源 | 说明 | 可用性 |
|---|---|---|
| **A 用户裁决过的决策** | `docs/decisions/` 里用户参与拍板的（如 D-0049/0050/0057/0058/0059） | ✅ 首选 |
| **B 有真实结局的动作** | 做了之后结果可观测（如 round34 备份清理：清理后是否丢数据） | ✅ 次选 |
| ~~C 模型单方裁决~~ | 无人复核的自动结论 | ❌ 自评，禁用 |

## 四、材料隔离协议（不做到位，题目全部废）

v2 的题都来自本仓库历史，**结论就写在仓库里**（`runs/*/adjudicated.json`、`docs/decisions/`）。
因此每席必须满足：

1. 材料包**物理复制**到 `audit/baseline/v2/materials/<题号>/`，只含：背景、候选方案、约束、可读数据；
2. 席位**只准读材料包**，禁止访问仓库其余部分（含 `runs/`、`docs/decisions/`、`audit/baseline/`）；
3. 每席须回报 `reads`（实际读过的路径），出现禁止区路径即该席作废；
4. 参考裁决与关键理由**只存于** `adjudication.json`，不进材料包。

> 这条是 v2 唯一的硬要求。做不到隔离，v2 会退化成"谁更会搜答案"。
