# 多席位对照实验 · 首轮执行记录（2026-10-24）

- **设计**：`D-0058`（1 轮 / 3 席 / 27 题配对 / 判据 `c − b ≤ 1`）
- **题面**：`questions-v1.md`（本轮首次落盘）
- **作答**：`seat-S1.json` / `seat-S2.json` / `seat-S3.json`（三席独立上下文、无工具、无项目路径）
- **汇总**：`aggregate_seats.py` → `multi-answers.json`
- **判定**：`paired_compare.py --multi`

## 一、结论先行

| # | 结论 | 强度 |
|---|---|---|
| 1 | 判定器给出「非劣效不成立」（`c=20, b=0, −0.741`, exit 1），但 **`c` 全是"没答"，不是"投错"** | 已实测 |
| 2 | 根因一：两臂**信息条件不等价**（基线带整段会话记忆，席位是全新进程） | 已实测 |
| 3 | 根因二（更硬）：**题库 v1 已有 8/27 题真值失效**，今天任何一臂的上限是 19/27 < 基线 20/27 | 已实测 |
| 4 | 因此本轮**判定"不可判定"**：不是多席位不行，是这把尺子过期了 | — |

## 二、判定器输出（原文）

```
[paired] n=27  单agent对=20  多席位对=0
  一致：都对 0 / 都错 7
  不一致：b（多席位赢）=0  c（多席位输）=20
  差值 (b−c)/n = -0.741   判据 ≥ −0.05 → **非劣效不成立**
  ⚠️ 多席位未作答 27 题（按错计）：Q11, Q12, Q13, Q14, Q15
  （另有 4 题作废，不参与）
```

退出码 **1**（不是 2）→ 自校验通过：它算出的单 agent 成绩复现了冻结的 20/27，n=27。
**工具没坏，它忠实地报告了一个含义错误的数字。**

## 三、根因一：三席在 26/27 题上一致弃答

| 席 | 作答题数 | 作答内容 | 自述 |
|---|---|---|---|
| S1 | 0/27 | 全 `null` | 「上下文无该项目信息，不编造」 |
| S2 | 0/27 | 全 `null` | 「无该私有工程任何历史信息」 |
| S3 | **2/27** | `T08=9.75`、`T09=10.9` | 「仅这两题由**题干数字**直接算出」 |

三席独立给出的唯一两题，恰好是**不需要任何项目知识**的两题：`(90−70.5)/2`、`−5.44−(−16.34)`。
这是「信息为零」的指纹，不是「能力不足」的指纹。

而基线自己的 `_note` 写着：「不查资料、不看答案，**全部凭本轮会话内的记忆**作答」——
那段会话里它跑过 `make backup`、数过决策、跑过覆盖率。**三席没有这段会话。**

```
c = 「单agent对 且 多席位错」= 20 = 单agent对的题数 × 多席位无信息
```

若三席真答了而投票投错，`c` 是聚合损失；本次 `c` 精确等于基线全部答对题数，
说明失分是**整体、无差别**地来自"没答"。

## 四、根因二（更硬）：题库真值已过期，8/27 道题今天没有正确答案

> 这一条与席位无关。**即使给席位整个仓库 + 无限时间，今天也答不对这 8 题。**

审计方法：对每道题按其 `measured` 字段的命令重跑，与冻结真值逐项比对。

| 题 | 冻结真值 | 冻结提交时点（`33b9418`） | 今天实测 | 失效性质 |
|---|---|---|---|---|
| T02 | 35 个提交 | 已非同一备份 | **39** | 备份已清理，最新备份换成 0633 |
| T03 | 121.2 MB（四份） | 已非四份 | **73.7 MB（两份）** | round34 清掉两组 |
| T04 | 53 份决策 | **57** | **58** | 决策在增加（冻结时已不符） |
| T05 | 53 项回归 | **54** | **54** | 加了 1 项幂等守门（冻结时已不符） |
| T10 | `6353/5bba/972c` | 对象已删 | **不可复现** | 三个旧 bundle 已清理 |
| Q11 | `D-0055` | **`D-0058`** | **`D-0059`** | 最后一份决策在变（冻结时已不符） |
| Q14 | 15 条经验 | **16** | **18** | 经验在增加（含本轮 2 条） |
| Q19 | 633 个 md | **646** | **654** | 文档在增加（含本轮 5 份新文档 + 快照副本） |

**8 题 / 27 = 29.6%。** 推论：

```
今天任何一臂的理论上限 = 27 − 8 = 19/27 (70.4%)
冻结基线             = 20/27 (74.1%)
→ 必然 c ≥ 1、b = 0
```

也就是说：**这把尺子今天是朝多席位那一侧倾斜的**。哪怕换成全世界最强的模型、给它全部权限，
它也会因为"答对了今天的数"而被判错。`D-0058` 的判据 `c − b ≤ 1` 在这种情况下不可能公平给出结果。

### 为什么会这样：冻结哈希保护的是"卷子没被改"，不是"卷子还对不对"

`D-0057` 的风险表里其实写了这一条：

> 「冻结导致题库老化（时点型题目会过期）」，处置是「老题的真值仍按冻结时点成立」。

**这条处置在判分链上无法成立**：题面里没有任何时点（「有多少份决策记录」没有"截至 X 日"），
判分器只拿冻结值比对。所以"按冻结时点成立"这句话，只存在于文档里，
**没有任何一处代码或题面去执行它**——正是本项目反复记过的"写在文档里却零载体"。

而 `D-0057` 自己定的出题标准第一条就是「问数量必须带时点」。
**题库 v1 的 15 道计数题，一条都没带时点。**

## 五、顺带查出的两个实现缺口

### 5.1 题面此前从未入库

`frozen-v1.json` 锚的是「两轮作答 + 两份真值 + 判分脚本」5 份文件；
`D-0057` 又明确写「**不冻结** `REVIEW-清单-白话版.md`：措辞可以改」。
→ 「题库已冻结」只冻了答案侧，**题目本身既没冻结、也没落盘**，只存在于上一段对话里。

本轮补 `questions-v1.md`（逐字转录、不改措辞、不动任何冻结文件）——第一次把题面变成可复用资产。

### 5.2 席位作答策略未受控，朴素多数票会被瞎猜统治

实测出现两种策略：**弃答**（S1/S2）与**全猜**（S3）。若按"投票数当分母"：

```
T08 原始票 = [None, None, 9.75] → "唯一一票" = 9.75 → 会被判为多数票
```

一个瞎猜值因为另外两席诚实弃答反而获得多数票地位。
→ `aggregate_seats.py` 加两道闸：**有效票 ≥2 席**、**多数票须占有效票过半**；
合成用例已验证（3 席 3 个值 → 歧义；仅 1 席作答 → "不构成多数票"）。

这条不只是实现细节：**多席位框架里"弃答"和"猜"必须被区别对待，否则诚实会变成劣势。**

## 六、本轮真正的产出

1. **否决了一个看起来完美的结论**：`c=20 / exit 1 / 自校验通过` 三者都指向"多席位不行"，
   实际指向"卷子过期"。这类"数字还在、含义没了"的腐坏，是本项目最警惕的一类。
2. **查出题库 v1 的结构性缺陷**：15 道计数题全部无时点，8 题已失效，且**没有任何机制会告警**
   ——没有一处代码会在真值失效时重算或报错。回归第 53 项比对的是 sha256，只能证明"文件没被改"。
3. **补了两个可复用件**：`questions-v1.md`（题面首次落盘）、`aggregate_seats.py`（多数票 + 两道闸）。
4. **两条经验**：`L-0017`（两臂必须同信息条件）、`L-0018`（哈希冻结不保鲜）。
