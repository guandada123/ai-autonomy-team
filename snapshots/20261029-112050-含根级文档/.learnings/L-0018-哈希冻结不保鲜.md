# L-0018 · 哈希冻结不保鲜：真值必须可重算，否则冻结那一刻就开始腐烂

- **日期**：2026-10-24
- **发现场景**：`D-0057` 冻结题库 v1（5 份文件 sha256）→ 7 小时后执行 `D-0058` 对照实验，审计发现 8/27 真值已失效
- **性质**：跨项目通用（数据/基准治理）★ 升级候选

## 现象

`D-0057` 的冻结做得很扎实：5 份文件的 **sha256 + 字节数**锚进 `frozen-v1.json`，
回归第 53 项逐个比对，「改一个字就红」。冻结后回归一直绿。

7 小时后按 `D-0058` 跑实验，实测发现：

| 题 | 冻结真值 | **冻结那一刻**的实际值 | 现在 |
|---|---|---|---|
| T04 决策份数 | 53 | **57** | 58 |
| T05 回归项数 | 53 | **54** | 54 |
| Q11 最后一份决策 | `D-0055` | **`D-0058`** | `D-0059` |
| Q14 经验条数 | 15 | **16** | 17 |
| Q19 md 文档数 | 633 | **646** | 651 |
| T02 备份提交数 | 35 | 35（旧备份） | 39（备份已换） |
| T03 tar 总体积 | 121.2 MB | 121.2 MB | 73.7 MB（清到两份） |
| T10 三个旧 bundle SHA | `6353/5bba/972c` | 存在 | **对象已删** |

**5 条在冻结那一刻就已经与仓库不符**，另外 3 条在 7 小时内因清理动作失去测量对象。

## 真实原因

冻结校验的是**文件有没有被改**，不是**内容还成不成立**：

```
hash 一致 ⟺ 卷子没被改过          （D-0057 做到了）
hash 一致 ⇏ 卷子上的答案今天还对  （从来没检查过）
```

而 v1 的 15 道计数题**题面里没有时点**（「有多少份决策记录」，不是「截至 10-24 有多少份」），
判分器只拿冻结值比对。于是"按冻结时点成立"这句话只存在于文档里，**零载体**。

更糟的是：题库的"被测对象"（本仓库自身）**在实验期间还在长**——
每写一份决策、每加一条经验、每加一个 md，都在让若干道题的真值变错。
**记录实验这个动作本身，就在使实验失效。**

## 为什么这类坑特别危险

1. **绿灯是假的**：回归第 53 项一直 PASS，因为它检查的是"文件没变"——文件确实没变；
2. **失效是静默的**：没有任何一处代码会重算真值，所以没有告警，只有"分数莫名变低"；
3. **它会伪装成能力问题**：本次若不做审计，结论就是"三席比单 agent 差 74 个百分点"；
   真相是"任何一臂今天上限只有 19/27，基线却有 20/27"——**尺子朝一侧倾斜**；
4. 与 `L-0012`（假事实闸门）、`L-0017`（两臂不同信息条件）同族：
   **测量系统本身出错时，输出的数字最像结论。**

## 结论（基准治理纪律）

1. **凡真值会随外部状态变化，必须带时点并写成"时点 → 真值"的映射**，
   判分时按**答题时点**取值，而不是拿一个冻结标量比一辈子；
2. **冻结必须配一条"重算检查"**：定期（或每次使用前）按 `measured` 命令重跑，
   与冻结值比对，不一致就报"已过期"——**hash 检查替代不了重算检查**；
3. **被测对象与测量工具不能同时演进**：要么冻结被测对象（打快照，题目锚到快照），
   要么接受真值会漂移并显式管理；
4. **计数型题目优先改成"关系型/因果型"**（"决策数多还是经验数多"），
   或直接换判断类题目（v2 方向）；
5. 看到"分数下降"时，**先查尺子，再查能力**。

## 可迁移到哪里

- 基准数据集 / eval 集（模型能力分数随时间失真，业界通病）；
- 覆盖率基线、性能基线（代码变了，基线数字没变）；
- 文档里的统计数字（本项目已有 `sync_doc_numbers.py`，但题库真值不在其中）；
- 任何"冻结一份数据当金标准"的场景：**金标准必须能被重算验证，否则它只是历史记录。**

## 落地动作（本项目）

- `audit/baseline/multi/RESULT-multi-20261024.md`：逐题漂移审计表（可直接当重算检查的样例）；
- `questions-v1.md`：题面首次落盘（此前只冻结了答案侧）；
- 建议：把"重算真值"做成回归项（`recompute_truth.py`），失败即红——**这才是"没漂移"的证据**。
