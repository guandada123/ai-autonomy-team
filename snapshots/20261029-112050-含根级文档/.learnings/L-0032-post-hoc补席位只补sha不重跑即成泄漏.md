# L-0032 post-hoc 补入的席位只补 sha、不重跑聚合，就是泄漏的温床

**日期**：2026-10-27
**标签**：聚合 / 溯源 / 时序错位 / 假缺席
**性质**：本项目专用（多席辩论 + PM 唯一写入者架构）
**状态**：已实测（D-0073，round13 S8-1-LEAK）

## 发生了什么

round13 的时间线是错的，但每一环单独看都"合理"：

1. PM-01 拍快照时，`EX-02.json` / `EX-03.json` **确实还没落盘**（席位交付晚于 PM 快照）。
   PM 当时如实把它们登记为「阻塞 / 缺席」，只聚合了 EX-01 —— **这一步是对的**。
2. 编排方事后发现文件落盘了，于是往 `answer-final.json → aggregation_inputs[]`
   **补了两条 sha256**，标注 `provenance: post_hoc_by_orchestrator`，并注明「PM 当时行为正确」。
3. 但**聚合结果没有重跑**：`summary` / `diffs` 仍是 EX-01 一席算出来的，
   而 `aggregation_inputs[]` 却声明"我聚合了三席"。
4. 更糟的是，事后 `seat-check` 判 EX-03 **invalid**（读取域越界）并列入 `aggregation_blocked`，
   于是同一个 sha256 在一处被判无效、在另一处被标 `valid` —— 数据自相矛盾。

同一个 sha256 两种身份，这就是 S8-1-LEAK。**根因不是"有人违规"，是"补登记 ≠ 重跑"。**

## 教训

1. **补 sha 不是补聚合。** `aggregation_inputs[]` 声明的是"我聚合了谁"，不是"盘上有谁"。
   事后补登记会把这一个字段从**聚合声明**偷换成**文件清单**，语义变了但字段名没变 ——
   于是校验器继续按"聚合声明"读它，读到的是谎言。
2. **"席位晚于快照落盘"是常态，不是异常。** 只要有并发交付，就一定会有人迟到。
   因此规则不能是"PM 必须等到所有席位"，而必须是：
   **凡不是当场聚合进来的席位，事后一律走"重跑"，不允许"补登记"。**
3. **假缺席会两头错。** 本轮 EX-02 被登记为「不在盘、仅 team-lead 转述、不进聚合」，
   而文件其实在盘且 valid —— 于是一个**真实存在的少数意见**被降级成了转述，
   差点永久丢失（本轮重跑时才被发现并原样恢复进 `diff_preserved[]`）。
   登记"缺席"之前必须回读盘面，不能凭目录列举的时序快照下结论。
4. **修的时候别只删引用。** 只把 EX-03 从 `aggregation_inputs[]` 删掉会让闸门变绿，
   但 `summary` 仍是三席的产物 —— 那是把"检测到泄漏"改成"检测不到"，比留着更危险。
   正确动作是**重跑聚合**，让数值与声明重新对齐。

## 可复用的判据

- 断言：`aggregation_inputs[].seat` 必须**全部**出现在该轮的**同一次**聚合调用里；
  凡带 `provenance: post_hoc*` 的条目，视为未聚合（应触发重跑，而不是放行）。
- 校验器交叉核对"被否决席位不得出现在 `aggregation_inputs[]`"是**有效**的 ——
  本轮就是它抓出来的。缺的是"post-hoc 补登记"这一条。
