# L-0042 用例必须被反证过才算覆盖——变异验证 + 负样本要像真实故障

**日期**：2026-10-31
**标签**：测试 / 变异验证 / 负样本 / 假闸门 / 可复现性
**类型**：跨项目通用
**性质**：凡是"用例通过即视为覆盖"的守门场景（判据闸门、schema 校验、接线检查）
**状态**：已实测（`audit/kit/test_item_review.py` 39 例；两条变异各使目标用例变红）

## 规则句（★升级候选，待用户确认后进 MEMORY.md 铁律区）

> **新增/修改守门用例后必须做一次变异验证——把判据朝错误方向改一处，确认用例真的变红；
> 负样本要像真实故障（改内容不改形状），只报绿灯不算覆盖。**

（本条只落仓库级经验，未改 `MEMORY.md`，未填 `docs/learnings-upgraded.json` 的 `rule_line`——
升级为铁律属用户级决定，不得由实现方或测试方自行宣布。）

## 发生了什么

`item_review.py`（出题质检闸）验收套件写完后 39/39 全绿。但"全绿"本身不构成覆盖证据：
一套永远绿的用例和没有用例，在下游看来完全一样。这一轮做了两次变异验证，确认用例
对实现有**鉴别力**，并顺手发现两类"看起来在验证、实际验不到"的断言。

## 根因与教训

1. **绿灯只能证明"当前实现没被这些用例否证"，不能证明"用例能否证"**。变异验证把判据
   朝错误方向改一处，看目标用例是否变红——红则证明鉴别力，不红则证明该用例是装饰品。
   两个实测：
   - C3 长度泄漏是**合取**（"正确项最长" 且 "长度 ≥ 其余均值 ×1.3"）。把 `and` 改成 `or`
     （倍数达标就拦）后，反例用例 `test_a9_conjunction_not_longest_miss`（正确项 50 字、
     其余 100/1/1）立刻 4/4 变红。若没做这次变异，"合取"只是注释里的一句话。
   - "`options` 的键不归一化"是 P0 冻结件。把实现改成"键也 strip"后，
     `test_a10_option_keys_not_normalized`（键 `{" A","B"}` + `correct=" A"`）从期望的
     exit 2 变成 exit 0，当场变红。

2. **负样本要像真实故障（改内容不改形状），否则测不到失效模式本身**。C0（题面哈希绑定）
   最初只造了 `"0" * 64` 这种假哈希——它能证明"哈希不符会被拦"，但证明不了 C0 存在的
   理由。真实失效是**有人手改了档案但长度不变**（C3/C4 都看不出来），所以换成"选项改一个
   字、长度不变"的等长篡改用例，才真正覆盖"改内容不改形状"这个模式。
   同理，"两选项题写 `blind='D'`（键不存在）"比"写 `E`"更能区分实现：前者区分
   「必须 ∈ options 键」与「必须是 A–D 之一」两种写法，后者两种实现都拦。

3. **变异要改在承重处；只改一半往往不是错判而是崩溃**。验证"键不 strip"时，先试了
   "只在比对处 strip 键、`clean` 里仍存原键"——结果不是 exit 0/2 的错判，而是直接
   `KeyError: 'A'` 崩在判据 `lens[correct]` 里。说明这条不变式在**校验**与**判据**两处
   都吃紧，任何一侧单独归一化都会炸。教训：变异位置选错会得出错误结论（"用例没红，
   看来覆盖不到"），实际上是被测代码先崩了。

4. **单因夹具：一个用例只该让一个判据能红**。写"合法值应通过"的用例时用了单题批，
   结果盲答 1/1 = 100% 触发 C6 饱和 WARN，红在 C6 而以为是目标判据 —— "能红"和
   "红在对的地方"是两件事。此后凡单题批必饱和处都显式断言 `warns == ["C6"]`，
   让"红在对的地方"变成可验证的，而不是靠记性。

5. **验证手段也要可复现：不可 grep 的文案等于不可验证**（本轮最贵的一课）。
   `blind.verdict` 越界报错文案原先由跨行 f-string 拼成，整句 grep 不到，
   导致**三个人（测试、实现、主理人）各误判过一次"该功能未落地"**，白跑一轮核对。
   文案改为单行常量后 `grep '不在 options 键内（格式错误'` 精确命中。
   判据的文案是给人看的接口，**搜不到的接口等于没有接口**；同时这也说明
   "用 grep 判断某功能是否实现"是不可靠的验证手段——它是线索，不是证据。

6. **断言别写快照派生数字**（同族反模式，本轮各清理一处）：
   `test_kit.py` 曾写死 `assert "声明 1121" in detail`，本批新增文件后包变 1122，
   用例变红——而 `chk_manifest()` 本身工作正常。写死派生数字的真实代价不是"改一次数字"，
   而是**每次正常变更都要改测试，久而久之大家顺手把数字改大，不再看断言在验什么**，
   回归保护就这样失效。改为解析出两个计数并断言相等（`声明数 == 实际数`），
   包多大都成立，且仍能抓住"声明≠实际"的真故障。
   同类：`ARCHITECTURE.md` 用裸行数背书模块，改一行注释就要同步改文档——有闸门校验时
   成本可控，但方向仍是"别在断言/文档里写快照数字"。

## 一句话

**绿灯证明不了任何事，能红才对；要证明用例能红，就把判据朝错的方向改一处——改不动或不敢改的地方，就是覆盖的盲区。**
