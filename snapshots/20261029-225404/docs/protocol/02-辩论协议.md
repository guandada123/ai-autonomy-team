# 02 · 辩论协议

> 目标不是「达成一致」，而是**把所有分歧都变成可裁决的问题**。
> 一个好的辩论结果不是「大家同意了」，而是「原来有 3 个隐藏分歧，现在这 3 个分歧各自被写成了可判断的命题」。

## 1. 单轮四阶段

| 阶段 | 执行者 | 动作 | 产出 |
|---|---|---|---|
| ① 提案 | EX-01/02/03（并行） | 各自独立产出，互不可见 | 结论 + 证据指针 + 证伪条件 |
| ② 交叉质询 | 全体 | 匿名、乱序、长度归一化后互评；**每席必交 1 条反对意见 + 其反证条件** | 反对清单 |
| ③ 裁判 | JD-01 → XJ-01 | 先跑硬裁判；无可执行裁判时走软裁判提示 | pass/fail + 证据；或分歧清单 |
| ④ 收敛或保留 | PM-01 | 收敛 → 拍板写盘；未收敛 → 保留多数 + 少数双结论 | 决定 + 理由 + 风险边界 |

AD-01（结构审计）**贯穿全程**，任一阶段发现结构缺陷立即 HOLD 并冻结该分支。

## 2. 参数表（可直接抄进配置，落盘于 `config/params.json`）

| 参数 | 取值 | 理由 |
|---|---|---|
| 最大辩论轮次 | `3` | 「步骤重复」占失效 15.7%，是最常见单一失效模式 |
| 每席每轮发言 | `1 次提案 + 1 次质询` | 压制「冗长对话」类低效（MAST 未覆盖但真实存在） |
| 呈现方式 | 匿名 + 随机顺序 + 长度归一化 | 位置偏差：先出现者胜率 63%；长度与胜负相关性 0.98 |
| 强制反对 | 每轮每席必交 1 条反对 + 反证条件 | 辩论本身不具纠正性，须外部注入方向性干预 |
| 分歧熵下限 | 全体一致且无独立证据 → 触发魔鬼代言人轮 | 共识可能是相关失效产生的高置信度错误共识 |
| 翻边率告警线 | `> 40%` 触发重启 | 翻边率过高 = 谄媚传播已完成 |
| 空转判定 | 连续 2 轮无新证据指针 → 终止该分支 | 直接对治「步骤重复」 |
| 单任务 token 预算 | 按任务价值设定，硬上限 | 多智能体约为单轮对话 15 倍 token |

> ★ **上表中「翻边率」「空转判定」「分歧熵下限」三项在本文件里只有阈值与动作 —— 那是历史遗留。**
> 它们的**操作化定义式**（立场如何记录、分母怎么取、熵怎么算、独立证据怎么判、轮次类型如何豁免）
> 见 `07-轮次与指标.md`，实现见 `scripts/metrics.py`。
> 本文件保留阈值与动作作为**参数的语义说明**；`config/params.json` 是数值的唯一源。

## 3. 终止条件（四选一，必须显式声明）

1. **硬裁判通过**（且无未解除的 HOLD）→ 结束
2. **轮次用尽**（达到 3 轮）→ 结束，保留双结论
3. **边际信息增益为零**（新一轮未产生任何新证据指针）→ 结束
4. **预算耗尽**（token 或 wall-clock）→ 降级结束

> 「未识别任务已完成」占失效 12.4%。**终止条件必须显式写出，不能靠感觉。**

## 4. 聚合规则（证据制，不是投票制）

```
硬裁判 pass  ──────────────────────────────▶ 采纳
有独立证据支持的少数（硬裁判不可用时）─────▶ 采纳，并保留多数结论备查
无证据的多数 ─────────────────────────────▶ 权重 0，不得作为决策依据
```

**关键**：人数不产生权重，证据才产生权重。三个 Agent 一致但没有独立证据，权重仍为 0。

## 5. 防谄媚六条（technical，不是态度）

1. **匿名化** —— 不暴露发言者身份（可几乎完全消除身份驱动的谄媚与自偏好）
2. **随机化顺序** —— 消除位置偏差
3. **长度归一化** —— 防止「更长 = 更好」的伪信号
4. **强制反对** —— 每席必须产出对立面
5. **魔鬼代言人轮** —— 一致性过高时强制注入
6. **翻边率监控** —— 翻边率是健康指标，不是收敛指标

> 反直觉但必须遵守：**EX-02（对立面）的 KPI 是论证质量，不是「被说服」。它若被说服，算失职。**

## 6. 输出契约（每席每轮必须返回）

```json
{
  "conclusion": "一句话结论",
  "evidence": [{"pointer": "可回读的外部实体（文件/数据/接口）", "what_it_shows": "..."}],
  "falsification": "在什么条件下我这个结论是错的",
  "reads": [{"path": "你实际读过的文件", "purpose": "读它做什么"}],
  "dissent": [{"against": "反对谁的哪一条", "reason": "...", "reverse_evidence": "..."}],
  "confidence": "high | medium | low",
  "needs_more_data": ["若为 data_insufficient，列出缺口"]
}
```

**缺 `falsification` 字段的结论，视为不可裁决，AD-01 直接 HOLD。**

> **`reads` 与 `evidence` 不是一回事**：`reads` = 「我读过什么」（实际读取全集），
> `evidence` = 「我用什么支撑结论」。读了但没当证据的，也必须写进 `reads`。
> 字段级要求、`stance` 立场向量、以及「不合格则不得进入聚合」的执行机制，
> 完整定义见 `07-轮次与指标.md` 第五节。

## 7. 失败归因纪律

必须区分两种表现相似、处置相反的情况：

| 归因 | 表现 | 处置 |
|---|---|---|
| 模型失败 | 有能力但判断错 | 换模型/换提示词/加裁判 |
| 数据不足 | 信息缺口 | 补数据，**不得**归为模型问题 |

不确定时标注 `data_insufficient`，不得默认记为模型失败。
