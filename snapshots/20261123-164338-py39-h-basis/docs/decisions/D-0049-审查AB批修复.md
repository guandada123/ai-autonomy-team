## 为什么

六项都是**静默失效**：不报错、不降级告警，只让人以为检查还在。

| 项 | 审查证据 |
|---|---|
| A1 | 从仓库根按 README 开轮：`EXIT=0`、日志**零行 `[preflight]`**、轮次写进 `./runs/` |
| A2 | 注入「8,123,456 字节」后 A 项仍报「校验 18 处」——假数字完全没被看见；当前 7.93 MB，距 8 MB 仅 0.9% |
| A3 | `scan_text('sk-proj-'+'A'*48)` 未命中。AI 项目里最可能出现的密钥形态整类漏检 |
| B1 | 包内注入 `import httpx` → 仍返回「第三方依赖命中 0」 |
| B2 | 每次 push 固定 17.29 s（1,724 对象，逐 blob 起进程） |
| B3 | 36 处 `write_text`、0 处原子写；截断的 `round-manifest.json` 会让 `round_task()` 静默回退 task 001 |

## 备选与弃因

| 备选 | 弃因 |
|---|---|
| `auto` 保留「自动关闸 + 打印警告」 | 警告在 hook/CI 里没人看；今天的 C-1 正是这样活下来的 |
| 依赖检查继续扩黑名单（加 httpx/rich/…） | 黑名单永远漏下一个；白名单才是闭合的判据 |
| 36 处全部改原子写 | 触碰面大、收益集中在 JSON 状态；其余是提示词/报告，可重生成 |
| 原子写失败时 `os.unlink` 清理临时文件 | **违反「删除的唯一去向是 _trash」**，`regress` 第 20 项当场拦下；改为固定临时名、失败不删（每路径最多留一个 `.tmp`，下次写覆盖） |
