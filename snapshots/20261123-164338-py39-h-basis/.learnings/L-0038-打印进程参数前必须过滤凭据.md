# L-0038 打印进程参数前必须过滤凭据——`ps`/`lsof` 输出里躺着 Bearer token

**日期**：2026-10-29
**标签**：凭据泄漏 / 会话记录 / 诊断工具 / 安全
**类型**：★ 升级候选（跨项目通用） 〔🔁auto-promote-2026-11-22·✅已评估·同族覆盖→「打印进程参数/环境前滤凭据」〕
**性质**：跨项目通用（任何在会话里执行 `ps aux`、`lsof`、`env`、`docker inspect` 的诊断场景）
**状态**：已实测（2026-10-29 本会话，7 个连接器 token 明文进入对话记录）

## 发生了什么

排查「哪个并行会话在写仓库」时，执行了 `ps aux | grep codebuddy --serve` 并把输出原样贴进会话。
该命令行包含 `--mcp-config` 的完整 JSON，其中有 **7 条 `Authorization: Bearer …` 明文**：

| 连接器 | token 形式 |
|---|---|
| connector-proxy / lighthouse-ops / agent-mail / genie-baas / space-library / tushare / github | `Bearer <22~44 字符>` |

它们随即进入会话记录（jsonl）与 trace 文件，并可能被截图、转发、或随会话导出外泄。
仓库侧 `E 项密钥扫描` 通过（没落进 git），所以**门禁不会报**——这类泄漏只有人看得到。

## 根因

诊断类命令的输出被当成「无害的进程列表」。实际上现代 CLI 会把**完整配置（含凭据）写进命令行参数**，
而 `ps`/`lsof` 的默认行为是原样显示。

## 判断规则

1. 贴 `ps`/`lsof`/`env`/`docker inspect`/`kubectl describe` 输出前，先过一层掩码：
   `sed -E 's/(Bearer|token|password|secret|key)[=: ]+[A-Za-z0-9._~+/=-]+/\1 ***/gi'`。
2. 只要任务是「看哪个进程/哪个会话」，用 `ps -o pid,comm` 或 `lsof -p PID | awk '{print $4,$NF}'`，
   **不要全字段输出**；需要参数时用 `ps -o args=` 再手工截断到前 N 字符。
3. 一旦发现明文进入会话记录：按「疑似泄漏」处置——列受影响凭据、建议轮换、在项目日志留痕，
   并检查是否有截图/导出副本。
4. 门禁通过 ≠ 没泄漏：密钥扫描只管仓库，管不了对话与终端历史。

## 边界

MCP 代理 token 多为本机 loopback、session 级、短时效，实际风险低于云端长期密钥；
但「低风险」不等于「可不处置」——处置成本是一次轮换，漏处置的尾部风险是不可控的。

## 补充：快照会把字面量复制进历史（2026-10-29 同日实测）

修 mask_secrets.py 时先写了字面量假 token，被 E 项密钥扫描抓红；改成运行时拼接后，
**推前扫描又红了**——命中的是 `snapshots/<时间戳>/scripts/mask_secrets.py`：
快照是整树复制，修复前的版本被复制进历史目录，此后一直随树推送。

处置顺序（都很反直觉，记下来）：
1. **不改快照内容**——快照是 sha256 锚定的历史产物，改写会同时破坏 H 项三向比对；
2. 用**轮转**把它挤出保留集（`make snapshot` 几次，保留最近 3 份，旧的进 `_trash`），
   然后提交「删除」动作；
3. 若污染已进入**未推提交**，`git reset --soft origin/main` 压成一个干净提交——推前扫描
   扫的是待推提交的全部内容，不是最终工作树。

推论：任何"源码里曾有真凭据"的时刻，都会在快照里留副本。**凭据永远不要先写字面量再改**，
第一版就用运行时拼接/环境变量——这比事后清理便宜一个量级。
