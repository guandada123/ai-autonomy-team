## 审计发现

1. **数值不敏感**：两席与三席聚合结果**逐字段全等** → EX-03 的泄漏是来源层缺陷，未污染数值。
   这不是「泄漏无害」的充分证据（EX-03 与主流的差异点恰是 amount/excluded 切分，而该切分由人类裁决决定），只说明本轮结构上看不见影响。
2. **旧版 falsification 自相矛盾**：旧版第⑦条称「0.55 在字段中无落点」，但同一文件 `summary.fee_diff_total=0.55` 已承载，且 `TASK.md` §C 明文定义了该字段算法。本版作废该表述。
3. **旧版对 EX-02 的登记是错的**：「不在盘、仅转述、不进聚合」——文件实际在盘且 valid。
   根因是席位交付晚于 PM 快照落盘，事后补登记只补了 sha、没有重跑聚合（见 L-0032）。
4. **修上游，下游首曝**：泄漏修好后，`--verify-final` 的下一条 FAIL 变成 HASH-CHAIN-BROKEN
   （`answer-status.json` 记 `85b5d03a…`，实际 `7cadd3fd…`；spec sha256 同样失配）。
   红的总数未增加，**红的成因换了**。该项处置仍为 B（声明失效、不重判），需用户单独决策。
5. **CI 不可用**：本轮改动无法获得 GitHub Actions 验证（额度耗尽），只有本地门禁结果。
