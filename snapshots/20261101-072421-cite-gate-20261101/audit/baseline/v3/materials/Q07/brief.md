# Q07 · 六席机制保留到什么程度

## 情形
「多席位评审」机制的定位（V2-14）此前由我裁决为「保留为参考实现、停止在合成任务上继续投入」，记录为「用户追认」。现在请你直接定。

## 事实
- 机制实际产出：判据（硬校验）、前提探针（结构化检查）、审计流程。这三样不依赖席位。
- 席位本身在合成任务上**无增益**：四臂全部 26/26，零分歧；单模型环境下独立性按 0 计。
- 保留成本：每轮跑 4—8 个 agent，消耗可观；维护要跟模型与 prompt 变化。
- 砍掉席位不影响判据与探针，只是以后不再有「多视角分歧清单」。

## 选项（选一个）
- `A` 保留为参考实现（维持现状）
- `B` 砍掉席位，只留判据与探针
- `C` 保留席位但明确只用于「列分歧」，不再跑任何打分对照
