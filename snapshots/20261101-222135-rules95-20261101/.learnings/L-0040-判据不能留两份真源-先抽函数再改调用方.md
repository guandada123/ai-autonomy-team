# L-0040 判据不能留两份真源——先抽函数再改调用方，用"同源同值"用例钉死

**日期**：2026-10-30
**标签**：判据 / 真源 / 重构 / 降级路径 / 测试
**类型**：跨项目通用
**性质**：凡是"实现 A 复用实现 B 的判定逻辑"的场景
**状态**：已实测（route_gate v0→v0.1，17/17 验收通过）

## 发生了什么

route_gate v0 的 S1 偏斜预筛（标签占比 > 0.5 报红）是**本地复制的判定逻辑**，
因为宿主 item_gate.py 的常数基准判定内联在 main() 里无法导入。v0 用"可用性探测
import"兜底并写明过期条件。v0.1 把常数基准抽成 `constant_baseline(labels)` 后，
S1 改为 import 真复用，并用一条"同源同值"用例（A9）把两处判定钉死在同一函数上。

## 根因与教训

1. **降级路径不是终点**：v0 的本地实现是有意降级（当时判据不可导入），但降级
   必须带"何时消除"的过期条件，否则第二份真源会静默存活——两处阈值/口径一旦
   各自演化，判据就出现分叉，"同一语义值须单一真源"被破坏。
2. **抽取顺序**：先在宿主抽出纯函数（加性改动、原行为零变化，用原有测试验证），
   再改调用方切过去，最后加"同源同值"用例（两个调用方对同一输入产出相同结果）。
   顺序反了（先改调用方再抽函数）会出现中间态双实现并存。
3. **不可导入≠不可复用，但也不该硬凑**：v0 没有为了"表面复用"去复制 item_gate
   的判分流程，而是明确降级并留痕——这比假装复用更诚实。真正要修的是宿主的
   可导入性（抽出函数），而不是在调用方侧绕。

## 修复动作

- `audit/kit/item_gate.py`：抽 `constant_baseline(labels)`，main() 改调用（实测常数基准仍 0.700，kit 87 项全绿）
- `audit/routing/route_gate.py`：S1 改 import 复用，删除本地占比实现
- `test_route_gate.py` A9：断言 route_gate 的 S1 与 `constant_baseline` 对同一分布同源同值

## 一句话

**复制判据的那一刻就在制造未来的分叉；要修的是让判据可被导入，而不是让第二份副本看起来像复用。**
