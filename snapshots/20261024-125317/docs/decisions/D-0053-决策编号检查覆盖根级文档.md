# D-0053 · 决策编号检查（F 项）补上根级文档，并允许"编号故意留空"

- **日期**：2026-10-23 23:55
- **决策者**：用户（"继续推进"——改方案文档时 F 项当场所红，暴露两个缺口）
- **操作分级**：🟢 低（只改门禁的扫描范围与豁免规则；不改判定语义）
- **状态**：生效

## 起因：写一句实话反而让门禁红了

订正《自治团队方案》首段的"事实底座"时，我照 README 的写法补了
"决策 51 份（编号到 D-0052，其中 **D-0017 标注留空**）"。该文档在 `docs/` 下，
F 项立刻判红：`缺文件: D-0017`。

**门禁是对的，但它只对了一半**：同样一句"D-0017 标注留空"在 README / ARCHITECTURE 里
写了很久，却一次都没红过——因为 F 项只扫 `docs/**`、`scripts/` 与包内三个目录，
**根级四份文档从未进入扫描范围**。根级文档引用了 6 个编号，全部处于盲区。

## 决定

1. F 项扫描范围加入根级 `README.md` / `ARCHITECTURE.md` / `DEPENDENCIES.md` / `M4-接续指南.md`；
2. 新增豁免：编号被标注为**故意留空**（`D-XXXX 未建 / 未创建 / 缺失 / 不存在 / 保留编号 / 未使用`，
   规则文档里的示例一律用 `D-XXXX` 占位——**不能用真编号**，否则本文档自己就成了永久豁免源）
   时不算缺文件；**只有标注过的才算**，没标注的仍然红；
3. 输出里带上豁免清单，让"哪些编号是故意空的"可见，而不是静默跳过。

第 2 条是本条的要点：豁免的门槛是**必须显式标注**。
想留空一个编号，就得在文档里写明它未建——这本身就是一条约束，
不会退化成"任何引用都能靠改个词蒙过去"。

## 可证伪（实测）

| 场景 | 期望 | 实测 |
|---|---|---|
| 现状（三处都写了留空标注） | F 绿 | ✅ 全覆盖（D-0017 已标注未建） |

| 在根级 README 里引用一个**不存在的编号**（本次用 D-00xx，不写真号，否则会被本项自己抓到） | F 红（证明根级已进扫描） | ✅ 指名该编号缺失 |

## 附带的效果

这次是**我自己的注释**先红了一次：改 `pre_release_check.py` 时我在注释里写了
"（D-0053）"，而 D-0053 当时还没建档 → F 判红。这条门禁对维护者本人也生效，
不会因为是"自己人写的注释"就放行。

## 明确不做

- ❌ **不为 D-0017 补一份文件**：它是历史跳号，补一份内容为空的决策只会制造假证据；
  保留"编号留空 + 文档标注"更诚实；
- ❌ **不扩大到 `snapshots/` 与 `_trash/`**：历史归档里的引用不参与当前验收，
  与 P4「不回溯改判历史」一致。
