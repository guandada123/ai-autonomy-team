# 03 · 结构审计（九查）

> 文件名保留「七查」是历史原因；**正文实为九查**（第 8 查「写入域」、第 9 查「席位读取域」为后续新增）。
> 改名会波及 `_build_xlsx.py` 与 `outputs/` 两个既有交付物，churn 过大，故只修内容不改名（见 D-0003）。

> **AD-01 只能驳回「结构」，不能驳回「结论」。**
> 它没有真值，所以不得输出「这个方案是错的」。一旦允许它输出对错判断，它就会开始**制造**确定性而不是**发现**不确定性——而且披着「独立审计」的外衣，更难被发现。
>
> 正确措辞：❌「这个结论不对」 → ✅「这个结论目前**不可判定**，原因是 X；若要变得可判定，需要补齐 Y」

## 为什么是「结构审计」而不是「内容审计」

同源审计看不到共享盲区。共享盲区对所有成员同等不可见——它**无法通过内容层面的检查发现**，但**可以通过结构层面的推理发现**：分析「谁在验证谁、验证器是否与产出同源、有没有外部钩子」，而不是分析「这段文字对不对」。

**因此 AD-01 的产出不是判决，是「待外部裁决的假设清单」。**

## 九查清单

| # | 检查项 | 不合格判据 | 判定 |
|---|---|---|---|
| 1 | **谁在验证谁** | 验证者与产出者同模型家族 → 该验证不产生独立性，只产生信心 | PASS / HOLD |
| 2 | **外部钩子** | 结论无法对应到任何可回读的外部实体（文件 / 数据 / 接口返回） | PASS / HOLD |
| 3 | **终止条件** | 没有显式的四选一终止条件 → 必然落入「未识别完成」失效 | PASS / HOLD |
| 4 | **分歧留存** | 只上交一份结论；少数派意见无记录；分歧熵低于下限却无魔鬼代言人轮 | PASS / HOLD |
| 5 | **规格假设** | 存在未声明的隐含假设（典型表现：「默认用户想要 X」）。**自动判定**：分层 spec 的 `adjudication` 层有未决项 ⇒ HOLD | PASS / HOLD |
| 6 | **失败归因** | 把「模型失败」误记为「数据不足」，或反之 | PASS / HOLD |
| 7 | **无裁判推进** | 存在已在推进、却未标注裁判状态的动作 | PASS / HOLD |
| 8 | **写入域** | 本轮发生对共享/禁止目录（`fixtures/`、`outputs/`、`docs/` 等）的写入，且无 PM 授权留痕 | PASS / HOLD |
| 9 | **席位读取域** | 席位的申报读取或证据指针落在禁读清单（`read-domain-check.json` 的 `verdict == "HIT"`），且无 PM 授权留痕 | PASS / HOLD |

> ★ 第 9 查修的是 F5：席位读取域此前**从未被声明过**（六个模板只约束「不可写什么」），于是席位读了含硬裁判真值的 `fixtures/truth.json` 再据此「独立得出结论」。检测只能覆盖「申报的」与「用作证据的」——**CLEAN 是下界，不是证明**（见 06 文档第三节诚实边界）。

## 三档动作

| 动作 | 性质 | 触发 | 后果 |
|---|---|---|---|
| **PASS** | 放行 | 九查全部通过 | 分支继续 |
| **HOLD** | 软闸门 | 任一查不合格 | 冻结该分支，输出假设清单；补齐后自动解冻 |
| **ESCALATE** | 升级 | HOLD 超预算，或「延迟×成本×不可逆性」超阈值 | 升级至硬裁判；无可执行裁判时升级至**人类闸门** |

**AD-01 不持有否决权。** 它自己也在同一分布内——给它否决权，等于换一个同样有盲区的人垄断真相。

### 第 1 / 7 查的时序前置（契约 v2.1）

第 1 查「谁在验证谁」与第 7 查「无裁判推进」都要求审计者**在裁决产出之后**下结论。这条纪律不能只靠口头，故契约 v2.1 起：

> **`audited_inputs` 定义式**：AD-01 的输出必须含 `audited_inputs[]`，逐项抄录本轮
> `verdict-layered.json`（`verdict` / `spec_layer` / `ts`）与 `pending-adjudication.json`
> （`verdict` / `spec_layer` / `summary.pending` / `ts`）。任一项与文件不符 ⇒
> `E_AUDIT_INPUT_STALE`，该席位判 invalid，挡在聚合之外。

**为什么用 `ts` 而不是 mtime**：`ts` 由裁判脚本在文件**写完之后**生成，审计者若在裁决前写完结论就不可能抄到；而 mtime 在 `cp -r` / `git clone` / 网盘中转后会被重置，跨机不可用（转移包正是跨机场景），且一旦写进模板正文就会让模板无法逐字节重现（回归第 33 项）。

**流程约束**：JD-01 必须在 AD-01 之前运行；AD-01 锚定之后**不得重算 JD-01**，若重算则 AD-01 须重跑（否则锚点指向旧版）。

## 共识失效代价判据（决定何时必须保分歧）

```
失效代价 ≈ 反馈延迟 × 判错成本 × 不可逆性
```

三项乘积高的地方，必须强制保分歧 + 人类闸门：

- **反馈延迟高**：结论几周/几月后才可见真伪（策略选择、渠道投入、长期规划）
- **判错成本高**：错了要赔钱/惹合规/伤客户（对账差异、合规报送、佣金发放）
- **不可逆**：发出去的邮件、报出去的文件、打出去的款

三项乘积低的地方（快速可回滚、可 A/B、错了无成本）→ **允许多数快速推进，不必保分歧**。保分歧是有成本的，不该无差别套用。

**每个决策在进入辩论前必须先打这个三维分。**
