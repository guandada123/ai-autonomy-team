v2 的本质改动是**把它从"出分后验尸"挪到"入库前门票"**。

## 二、不变量管线（无论选哪个方向，这六步是硬的）

1. **出题人/裁决人分离**：素材改写成题的人（我）不得知道/暗示参考答案；裁决只由你做
   （或你 + 独立模型双裁算 Kappa，< 0.6 的题回炉改题面——v3.1 规则 6）；
2. **选项均衡预筛**：入库前先跑常数基准 + 单席小样——常数基准 ≥ 最强臂的题**不入库**
   （v3 死因的直接解药：参考答案在选项上的分布必须均衡，出题时即检查）；
3. **准入三闸前置**：`item_gate.py` 在入库时跑，不是出分后跑；"答案不可从仓库反推"单测；
4. **pass^k**：每席每题独立跑 k=3，报 pass^1 与 pass^3，差距 > 0.2 的题判"靠运气"不计分
   （τ-bench 教训：单次通过高估能力）；
5. **canary + 20% 留出**：每题嵌唯一串；两成题只在本地跑；
6. **实验协议照抄**：禁读边界 v1 标准段（PROTOCOL §六）、两臂同信息条件（L-0017）、
   席位原件只写一次（L-0032/33）、判分复用 `paired_compare.grade` + 多数票聚合（不复制）。

## 三、三个方向（选一个）

### 方向 A · 真实裁决迁移题（**推荐**）

**素材**：`migration-package/runs/*/adjudication-record.json`——已有 **5 条真实人类裁决**
（round2 的 ADJ-001/002/003、round13 的 ADJ-001/002），每条都带你的 rationale
（如「少报不可逆——计入」）。把"台账×账单×某笔差异"这类场景**改写抽离**（换数字、换皮、
不指名本项目），问"这笔差异该不该计入"，真值 = 你的裁决迁移。

- **优点**：真值来自**已发生的人类裁决**（不是设计者自造，绕开 L-0030）；两面天然可辩护
  （这正是当初要 ADJ 的原因）；rationale 可以进解析；素材随轮次增长可持续供给；
- **风险**：改写后若仍能从仓库反推原案 → 触发"不可反推"闸，须再抽离；
- **规模起步**：5 条种子 × 3 个变体 = 15 题，加 5 题留出 = 20 题。

### 方向 B · 运营判断题（投资/风控/运维处置）

**素材**：你的真实决策场景——止损触发时先卖哪只、告警先处置哪个、仓位超限怎么再平衡。
每题给材料 + 3~4 个选项，你裁决。

- **优点**：最贴近"多席辩论的真实用途"（投资搭档），判分 = 你未来的真实裁决习惯；
- **缺点**：每题都要你亲自出素材与裁决（20 题 ≈ 一小时级别投入）；选项设计偏斜风险最高
  （v3 死因重现概率大，均衡预筛必须严格）。

### 方向 C · 冲突材料题

**素材**：故意给两份**互相矛盾**的材料（数字/规则/时间戳冲突），问"采信哪个、如何处置"，
真值 = 预注册的信源优先级规则。

- **优点**：判分可完全机械化；直接测多席"互相纠错"的核心场景；
- **缺点**：构造矛盾材料的工时最高；"预注册信源规则"本身可能被席位从题面推理出来（饱和风险）。

## 五、验收线（v2 成功长什么样）

1. 入库的每道题都能出示：准入三闸通过记录 + 选项分布表 + Kappa（若启用）；
2. 出分时 `item_gate.py` 不红（常数基准 < 最强臂、非饱和、非全错）；
3. 产出**至少一个** b≠0 或 c≠0 的不一致对——即"多数票 vs 单席"第一次有信息；
   若仍然 b=c=0，结论升级为"该素材类也无区分度"，换方向或停线（预注册止损）。
