# L-0027 · "目标不存在"只 warn 不 fail = 静默 no-op，退出码骗人

- **日期**：2026-10-25
- **发现场景**：`sync_score.sh` 首次运行，默认目标路径算错嵌套层级 → 3 个目标全部跳过，但退出码 **0**、结尾打印"完成"
- **性质**：跨项目通用（任何"批量写多个目标"的脚本）★ 升级候选

## 现象

```
[sync] ⚠ 跳过不存在的目标：/Volumes/.../2026-10-19-22-33-38/Claw
[sync] ⚠ 跳过不存在的目标：/Volumes/.../2026-10-19-22-33-38/StockInsight
[sync] 完成。        ← 一个都没同步，却说"完成"
SYNC_EXIT=0          ← 退出码也是 0
```

## 两个错误叠在一起

1. **路径基准错（表层）**：默认目标写成 `REPO_ROOT/../Claw`，但本仓库嵌在
   `WorkBuddy/<日期>/ai-autonomy-team`，目标在 `WorkBuddy/` 下 —— **多一层**，
   应为 `REPO_ROOT/../../Claw`。
2. **静默降级（真凶）**：脚本对"目标不存在"只 `echo ⚠ ...; continue`，
   循环结束后无条件打印"完成"并 exit 0。**"一个都没同步"与"全部同步成功"在退出码上完全一样。**

第 2 条才是要命的：它让第 1 条这种低级错误**没有任何外部信号**。
若不是随后去 `ls` 目标目录核对，就会以为什么都同步好了。

## 判据 / 修法

批量写目标的脚本，必须满足：

- 统计 `SYNCED` 与 `SKIPPED`；
- **`SYNCED == 0` → 视为失败，exit 1**，并把常见原因写进错误信息；
- 结尾报告"成功 N 个，跳过 M 个"，不要无条件说"完成"。

`sync_score.sh` 已按此修。

## 可证伪性（必须实测两条路径，不能只看代码）

```bash
bash audit/kit/sync_score.sh                       # 真跑：3/3，exit 0
cp score.py sync_score.sh /tmp/synctest/audit/kit/ # 故障注入：默认目标全不存在
bash /tmp/synctest/audit/kit/sync_score.sh         # → ❌ 成功同步 0 个，exit 1
```

**只跑成功路径不算验证**。必须注入一个"什么都不该同步"的场景，确认它真的变红。
