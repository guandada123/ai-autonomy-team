# L-0033 修转录不要改写席位原件：在读取侧归一，原件只写一次

**日期**：2026-10-28
**标签**：原始产物 / 不可复原 / 转录修正 / 假原件
**性质**：跨项目通用（任何"多来源产出 → 汇总"的流程）
**状态**：已实测（v1.2 对照实验，S3 键名归位，D-0078）

## 发生了什么

v1.2 四席重跑，S3 交回的 JSON 里有 4 个键写成了 `T11/T12/T13/T20`（题号本身是 `Q11/Q12/Q13/Q20`，
同批其他键都是 `T02…T09` 与 `Q1x` 混排，故容易混）。我判为**转录笔误**，
于是**直接改写了 `seat-S3.json`**：把 4 个键改名、补一个 `_note` 解释。

语义确实无损（键值一一对应，evidence 里指向的题号本来就是 Q 组），评分也照常。
问题在别处：**原文件字节被覆盖了，而且覆盖前没有留副本。**

于是一天后的审计只能写：「语义无损、字节不可复原」。想复原时才发现会话记录访问受策略限制
（2026-10-28 实测拒绝），也就是**连"当时的原文长什么样"都只能靠我的陈述**。

## 教训

1. **原件是证据，不是工作副本。** 席位产出、审计意见、外部接口原始响应，都属于"别人交来的东西"。
   它一旦被自己改写，就同时失去了两个属性：可核对的原文、以及"这是它自己说的"。
   后者更贵 —— 争议时你要证明的不是"我改得对"，而是"它原本说了什么"。
2. **能不改就不改，改读取侧而不是改原件。** 键名不一致是**消费方**的问题：
   聚合/判分按题号别名解析（`T11 → Q11`，仅当 `Q11` 在真值集且 `T11` 不在时映射），
   并在输出里记录 `key_aliases`。这样席位文件永远是它交来的样子，别名关系反而比改名更透明 ——
   改名会**抹掉**"曾用过错键名"这个事实。
3. **确需改，先留副本再改，并逐字节校验。** 与 S8-1 处理 `answer-final.json` 同一做法：
   `cp -p` → 校验 sha256 一致 → 再写新版 → 旧版改名 `*.superseded.json` 且写进 git。
   本轮 `answer-final` 就是这么做的（sha `dfc43bb7…` 留存可查），S3 却没做 —— **同一会话里两种标准**，
   说明这不是"没想到"，是"没形成规则"。
4. **别用 `_note` 当免责声明。** 在被改过的原件里写"我只改了转录"，
   等于让未来的审计者**通过当事人的证词**判断当事人是否诚实。记录要落到**另一个文件**里
   （`seat-S3.rename-record.json`，机读、可 diff、不进原件）。

## 可复用的判据

- 口径：**凡"原件"目录，只允许追加（新文件），不允许就地改写**；
  需要修正就在同级写 `*.rename-record.json` / `*.superseded.json`，并让二者都能被 diff。
- 自检：`git log --diff-filter=M -- <原件目录>` 应只有"新增"记录；出现 `M`（修改）即需解释。
  本轮若早跑这条，S3 的那次改写会在当场被抓住，而不是在次日审计里被追认。
- 反面判据：如果审计只能引用"当事人说改了哪些"，那就等于没有留痕 —— 判据必须能脱离陈述自证。
