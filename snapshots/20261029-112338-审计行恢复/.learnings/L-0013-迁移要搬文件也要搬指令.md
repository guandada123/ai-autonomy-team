# L-0013 · 迁移要搬文件，也要搬「怎么找到这个文件」的指令

日期：2026-10-23 ｜ 出处：M4 遗留项复核 ｜ 关联：`L-0009`

## 现象

2026-10-23 把冻结基线从 `_trash/backup-pre-P5/truth.json.frozen` 迁到
`fixtures/frozen/truth.json.frozen`（`regress` 第 8 项随之改指新路径）。

迁移动作做了两步：**复制 → 验证 sha256 一致**（`03b41c49…`，逐字节相同）。

但审计清单把旧副本记为「死文件，可随时删」。删前 grep 一次才发现：**三份活文档仍在
教人去 `_trash/backup-pre-P5/` 找它**，其中一份还专门写着

> ⚠️ **不要删除工作区里的 `_trash/backup-pre-P5/truth.json.frozen`**

三处分别是：`M4-接续指南.md`（说明交付物包含什么）、
`migration-package/README.md`（接收方须知）、
`migration-package/docs/目标机-人工确认清单.md`（第 8 项红的排障指引）。

而 `_trash/` 是 `.gitignore` 里的目录 —— 新机器 clone 之后那份旧副本**根本不存在**。
照指令排障的人会找不到文件，而且**不会怀疑指令本身错了**。

## 为什么审计判错

判据是「有没有代码引用」：`git grep` 搜的是 `.py` 里的路径常量，搜到了 0 条就判死。
漏掉的载体是**文档里的指令**——它不进任何测试，删了不会红，所以属于
「删了才知道」的一类，只能靠删前把 grep 范围从代码扩到 `*.md` 来兜。

代码引用与文档指令的区别很关键：代码引用错了会崩（可观测），
文档指令错了只会让下一个人多花两小时（不可观测）。

## 修法

1. 三处活引用改指 `fixtures/frozen/truth.json.frozen`，并注明旧副本「已不再是依赖」。
2. **旧副本不删**：4KB，且 `D-0003` / `D-0005` 以它为回滚依据，删了历史不可复核。
   死文件不一定该删 —— 它可能已经从「运行依赖」降级为「历史凭证」。
3. 「迁移」的定义从两步扩成四步：
   **搬文件 → 改代码引用 → 改文档指令 → 最后才删源**。
   前三步任缺其一，源就不能删。

## 通用化

一次迁移/清理有四种载体，前三种可 grep，第四种不可：

| 载体 | 查法 | 漏掉的后果 |
|---|---|---|
| 文件本身 | `ls` | — |
| 代码引用 | `git grep -n <path> -- '*.py'` | 运行时崩（可观测） |
| **文档/清单指令** | `git grep -n <path> -- '*.md'` | **新机照指令找不到文件，且不怀疑指令** |
| 人的记忆 | 无 | 下一个人重踩 |

**通则：凡"删/移"动作，grep 范围必须包含 `*.md`；两者都 0 命中，才配得上"死"这个字。**
