# D-0024 · TASK.md「若无则填 `[]`」与机器断言「非空」的冲突

- **日期**：2026-10-20（补落为正式文件）
- **依据来源**：`migration-package/judges/verify.py:361` 注释；`runs/round20/answer-final.json` 备份中的席位 note
- **操作分级**：🟡 中（断言类型变更，影响 20 份 spec）
- **状态**：已执行（`present` → `present_or_note`）

## 决策

`excluded_categories` 的单路径 `present` 断言改为**双路径 `present_or_note`**：

| 情形 | 判定 |
|---|---|
| 非空 | **pass**（不论是否有 note） |
| 空/缺失 + `excluded_categories_note` 非空 | **pass** |
| 空/缺失 + note 缺失或空白 | **fail** |

## 依据

| # | 依据 | 来源 |

| 1 | TASK.md §C 明写「`excluded_categories`｜…列表（**若无则填 `[]`**）」，但 `arithmetic.json` 的 `present` 把空数组判 fail —— **按文档做会被机器判错** | `fixtures/tasks/*/TASK.md` |

| 4 | 席位 note 实证：「零金额类别充数是二十轮以来事实标准」——旧断言在**逼人编造类别** | `runs/round20/answer-final.json`（备份） |

## 备选方案与未采用理由

| 备选 | 未采用理由 |
|---|---|
| 直接允许空数组（不加说明要求） | 「空」与「漏填」仍不可区分，等于放弃这条闸门 |
| 保留 present，改 TASK.md 为「必须至少一项」 | 会逼人编造类别（依据 4 已实证这是现状），方向反了 |

## 审计发现

**断言与文档冲突时，未必是文档错**。此处文档「允许空」是对的（确实存在无类别可排除的任务），
断言「要求非空」才是错的 —— 它把「没填」和「确实没有」混为一谈。

判断方法：看**实际数据有没有踩到**。26 份产出全部非空，说明断言从未真正拦住过错误，
只是在逼人凑数；而一旦出现真实无需排除的任务，文档口径就是唯一正确的。
