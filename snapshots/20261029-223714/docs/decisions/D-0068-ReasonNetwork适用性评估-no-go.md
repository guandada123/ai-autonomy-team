# D-0068 Reason Network 适用性评估 —— 不采纳（附复访条件）

**日期**：2026-10-26
**触发**：用户转来一篇介绍 Reason Network 的小红书笔记，问"学习这个技能能否对本项目有优化"
**性质**：外部工具引入评估（go / no-go）

## 一、它到底是什么（已查证，非凭笔记摘要）

`reason-machines/reason-network`，Rust 编写的**常驻守护进程**，2026-10-16 建仓，Apache-2.0/MIT，约 1.1k stars。

- **定位**：跨**机器**、跨**人**的编码 agent 会话**消息层**（P2P，iroh 直连 + 加密中继兜底）。
- **给 agent 的 MCP 工具**：`list_team`（谁在线/哪个仓库分支/忙闲）、`send_message`（可带 ≤10 个文本文件，单文件 256KB、合计 512KB）、`ask_user`（弹窗请求人类批准）、`check_inbox`（无法推送时轮询）。
- **接入对象**：Claude Code、Codex、Cursor、Gemini CLI、Copilot CLI、Grok CLI、opencode、pi、DeepSeek Harness、Reason。
- **明确不是什么**：不是模型、不是推理框架、不产出任何智能。它只解决"寻址 + 传话 + 归属批准"。

**它的卖点**：减少人在多台机器之间搬运消息、重复讲解背景的精力。

## 二、本项目的实际瓶颈（已量化，非感觉）

| # | 瓶颈 | 量化证据 |
|---|---|---|
| B1 | **席位同源，独立性≈0** | 席间 κ 0.855 vs 臂内 κ 0.817，差 +0.038 → 换一个席位 ≈ 同一席位再答一次 |
| B2 | **出题人=裁决人**导致天花板 | v2 四臂全 26/26，标签对调 36/36 动作一致，偏斜假说被证伪 |
| B3 | **价值判断题席位不可用** | 常数全答 A = 0.700 > 最佳臂 0.600/0.556 |

而 `docs/自治团队-最终方案-20261022.md` 早已定案：

> **独立性来自模型家族而非 prompt**；当前环境下六席实为同一模型的多视角，独立性应记 **0**。

## 三、逐条适用性判定

| 它的能力 | 对本项目是否命中瓶颈 | 判定 |
|---|---|---|
| 省掉"人搬消息" | 本项目全部席位**由主 agent 单进程调度**，人工搬运成本 ≈ 0 | ❌ 省一个不存在的成本 |
| 跨机器寻址 + 人工批准 | 单人单机单仓库，无"别人的会话"可寻址 | ❌ 无寻址需求 |
| 提高席位独立性 | **通信层不产生独立性**（独立性来自模型家族）——已定案 | ❌ 触及不到 B1 |
| `ask_user` 不可伪造归属 | 概念上契合"裁决必须真人做"，但用户本人已在对话中，直接问即可 | ❌ 边际价值 0 |
| 跨设备异构模型族编排 | 唯一理论价值点，但**不需要它**：CatRouter 已可直连多模型族（Claw 侧可见 gpt-5 / deepseek-v4-flash / qwen2.5:7b 等） | ❌ 有更短路径 |

## 四、反向成本（不采纳的另一半理由）

1. **新增常驻 daemon**：本机已有 80+ 自动化；且本机教训明确——**launchd 后台进程在 macOS TCC 下访问外置卷会失败**，而本项目就在 `/Volumes/ZHITAI` 上。新 daemon 大概率踩同一个坑。
2. **可见性外扩**：加入团队后，你的**姓名、电脑、仓库、分支、忙闲状态**对队友可见；默认中继由 n0（iroh 公司）运营；需 Reason 账号登录。本项目仓库含真值、门禁、快照等审计资产，与"最小暴露面"冲突。
3. **归因纪律反向**：昨天刚出现"08:24 来源不明快照无法归因"，我为此给 `snapshot_sources.py` 加了 caller 痕迹。**再引入一条跨机写入通道 = 再开一条更难归因的路径**，与刚立的纪律反向。
4. **单真源冲突**：刚建立 `score.py` 单真源 + `sync_score.sh`。多一层跨机消息只会增加副本漂移风险（L-0016 同源）。

## 五、决策

**不采纳（no-go）。不安装、不接入、不新建自动化。**

## 六、复访条件（满足任一即重新评估，判据预注册）

- **R1**：有**第二个人**参与出题或裁决（真正需要"对方 agent 把题面/裁决送进来 + 不可伪造归属"）→ 此时它是正确工具。
- **R2**：席位需要在**不同物理机**上运行（例如一台跑本地 qwen、一台跑云上 Claude Code），且需要跨机会话寻址。
- **R3**：出现"agent 需要向另一个 agent 的**活会话**提问"（而非重新起一个进程）的刚需——本项目当前无此场景。

## 七、想提升独立性，正确路径是这个（不需要任何新工具）

用 **CatRouter 把席位路由到不同模型家族**（≥3 家族），重跑 v3 的 10 题。**预注册判据**：

- **主判据**：席间 Fleiss κ 是否显著低于当前 0.855，且「臂内 κ − 席间 κ」是否 > 0.038（独立性真的上升）。
- **副判据**：常数基准（全答 A = 0.700）是否仍高于最佳臂。若仍高于 → 佐证"价值判断本就不该由席位答"，应转 D-0064 已定的"人裁"路线。
- **对照组必留**（消融铁律）："同家族多席"必须与"跨家族多席"同场跑，否则无法归因。

> 注：该实验**优先级低于 36 条盲标**（盲标是唯一能区分"规则正确"与"实现符合规格"的杠杆，且零成本、工具已就绪）。
