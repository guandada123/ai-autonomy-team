# D-0044 · 计划前置：任何任务先出计划 → 讨论 → 审计计划 → 才执行

- **日期**：2026-10-22 17:30
- **决策者**：用户（原话「任务第一步都要先做计划讨论过了再审计一遍」）
- **操作分级**：🟡 中（改变工作流程，不改机制代码）
- **状态**：已采纳，即刻生效

## 决定

任何任务，**第 0 步不是开工，是出计划**。流程固定四段：

```
① 出计划：目标 / 步骤 / 验收判据 / 风险 / 不做的事
② 讨论：把计划摆出来，等你说"行"或"改哪"
③ 审计计划：用同一套清单审这份计划本身（不是审成果）
④ 执行：审计通过才动手
```

**谁审**：可用 8 角色中的子集，默认 **3 席**（前提审查 + 风险不可逆 + 度量证伪）——
这三席专门回答"这计划该不该做 / 会怎么坏 / 怎么知道做对了"。

> 📌 口径说明：这里的「3 席」是**8 角色清单的抽样**，不是「6 席编制的削减」。
> 其中「前提审查」在 6 席里没有常设岗位，正是本决策要补的缺口。
> 三套数字（6 席编制 / 8 角色清单 / 3 席默认子集）对照见 `docs/角色映射表-6席与8角色-20261022.md`。

## 为什么

| 理由 | 依据 |
|---|---|
| 今天多次返工，根因都是"没先说清要做什么就动手" | 例：D-0034 的闸门改在产物上而非源头，白做一轮 |
| 计划成本远低于返工成本 | 计划 10 分钟，返工 1 小时起 |
| 审计计划能提前发现"问错了问题" | 例：四轮探针全测收敛题，事后才发现 |
| 与已有机制一致 | 项目本就有"前提三问"，本文把它提前到任务开始处 |

## 审计计划的五问（固定）

| # | 问 | 不合格的表现 |
|---|---|---|
| 1 | 目标写清了吗 | "优化一下""完善机制"这类没有终点的目标 |
| 2 | 步骤能照着做吗 | 只有方向没有动作 |
| 3 | **怎么算做完了** | 说不出判据，或判据不可观测 |
| 4 | 会怎么坏、怎么退 | 没写风险或没写回滚 |
| 5 | **这份计划自己漏了什么** | 空话或"暂无" |

## 例外（唯一）

**不可逆或紧急**的情形可以先做后补计划，但必须当场说明"为什么不能等"。
除此之外没有例外。
