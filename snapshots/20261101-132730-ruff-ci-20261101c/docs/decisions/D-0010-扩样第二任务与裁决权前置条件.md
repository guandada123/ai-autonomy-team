## 判据设计（与 001 同构，机制侧零改动）

**ADJ-001**：交易费用（佣金 + 印花税 + 过户费）是否计入"成本差异"金额？`count` / `exclude`
- `count` → `amount_diff_total = 4543.17`，`excluded = 0`
- `exclude` → `4480.00` / `63.17`（夹具默认口径）
- 风险不对称：计入 = 逐笔核费用明细；不计入 = 真实摩擦成本永久从收益计算里消失（长期最易被低估的一项）

**ADJ-002**：差异清单含哪些条目？`7` / `6` / `5` / `4`（四选项并列）
- 恒在项 4（T202、T204、T207、T209）+ 权益变动类 2（T206 送转、T210 现金分红）+ 交割跨日类 1（T205）
- 组合计数 **7/6/5/4 互不相同** —— 满足 001 修过的那条（四种组合必须给出四个不同条数，否则人只能签出机器已算出的那个数，见 `D-0006`）

**算术锚点**：行数、成交金额合计、总额差、去重笔数/金额 + 三项 `present`。

## 审计发现

- 端到端验证：`verify.py --spec-dir fixtures/002/spec` → **算术层 10/10 pass、判断层 2 项 pending、退出码 3**（未裁决 ≠ 通过）。**判据侧**确实零改动。
- ★★ **但 002 尚未接入开轮器，本决策不构成"可以拿它跑一轮"**。三处硬编码使任务不可插拔：
  1. `new_round.py:408` —— 判断项 spec 路径写死 `fixtures/spec/adjudication.json`，002 的 ADJ 项进不了提示词与裁决模板；
  2. `new_round.py:469` —— 提示词「你的读取域」段由 `read_domains.json` 的 **allow 全局**拼出，不分任务；
  3. `templates/*.md` 的输入说明指向根 `fixtures/`。
  故 002 目前的状态是：**判据与夹具就绪、可硬裁判验证，但不能开轮**。
- ★ 我自己踩了一次并已回滚：初次把 002 加进 `allow`（以为是"补配套"），结果会污染**所有**轮次的提示词——下一轮提示词会同时列出两个任务的 TASK.md / ledger.csv / bill.csv，席位不知道该核哪个。已改为**只补 deny、不补 allow**，并把这条理由写进 `read_domains.json` 的 `_why_each_entry`。教训：**改配置前先看它下游是谁在消费**，allow 的下游是提示词生成器，不是"能读什么"的登记表。
