# L-0005 · 没有定义式的阈值是装饰品

- **日期**：2026-10-16
- **类型**：★ 升级候选（跨项目通用） 〔🔁auto-promote-2026-11-22·⏳待固化(容量不足)→「计数骤降先疑口径;grep -c=0先验模式」〕
- **发现方式**：多轮辩论机制操作化（第 3 轮工作）

## 现象

项目里 `migration-package/config/params.json` 自称「**唯一参数源**」，其中写着：

```json
"flip_rate_alert_threshold": 0.40,
"flip_rate_action": "restart_round",
"dissent_entropy_floor": {"trigger": "...", "action": "force_devils_advocate_round"},
"idle_detection": {"consecutive_rounds_without_new_evidence": 2, "action": "terminate_branch"},
"max_rounds": 3
```

协议文档也逐条复述了它们，验证报告里还把它们列成了「已配置的机制」。

**但全库 grep 的结果是：`scripts/` 与包内所有 `.py` 中，对这些键的引用数为 0。**
没有脚本计算翻边率，没有脚本算分歧熵，没有编排器消费 `max_rounds`。
**那个 `0.40` 从未参与过任何一次判断。**

## 根因

**阈值与动作不是机制。** 机制 = 定义式 + 实现 + 消费者。

这三者中间缺了最关键的一环：**操作化定义**。
- 翻边率：分子是什么？**分母取席位数、轴数、还是可比对的对数**？跨轮怎么对齐？
- 分歧熵：在什么域上算？**下限是多少**（原文只有 trigger 条件，没有数值）？
- 空转检测：什么算「一个新证据指针」？两轮之间怎么比对？
- 「无独立证据」：**怎么判定独立**？

没有这些，代码写不出来；写不出来，阈值就只是文档里的一行字。

## 更值得记的一层：**「已配置」会被当成「已实现」**

这个缺陷之所以存活了两轮而不是被立刻发现，是因为它**在文档层面是完整的**：
有阈值、有动作、有协议条目、有验证报告里的「KPI 与门限」表。
任何只读文档的人都会认为机制已经就位。

> **完整性错觉**：当一份规格把一个机制描述得足够详细（阈值、动作、触发条件），
> 读者会默认它已被实现 —— 而**恰恰是它缺的那部分（定义式）无法从描述中看出来缺了**。

## 判定方法（可复用）

对每一条「机制」，问三个问题，缺一即视为**未实现**：

1. **定义式**：它怎么算？给出公式，且公式里的每个量都能用现有数据算出来吗？
2. **消费者**：有代码读这个参数吗？（`grep` 参数名，命中数为 0 = 装饰）
3. **可观测产出**：跑一次会产出什么文件/字段？跑完能看到吗？

第 2 条是最省事的探测器：**参数名在代码里出现几次**。

## 本轮连带发现的四个同源缺陷

| 缺陷 | 形态 |
|---|---|
| 「无独立证据」子句与席位契约**互相矛盾** | 契约要求 `evidence ≥1`，而子句要求「无任何证据指针」→ **合规席位永远不满足 → 机制永不触发**。定义式必须与类型约束联立检查 |
| 契约是第 2 轮才引入的 | 第 1 轮产出 0/4 合规 → **翻边率不可算**。后加的契约会让历史数据不可用；契约必须从第一轮生效 |
| 匿名化只剥离结构字段 | 实测正文仍残留 `EX-01`、`AD-01` 等席位名。**结构层净化 ≠ 内容层净化** |
| 源目录 `judge/` vs 包内 `judges/` | 同一条相对路径两侧指向不同 → 同类笔误连发两次。**命名不一致是 bug 的温床** |

## 另一条独立教训：审计真的能抓到执行者的遗漏

本轮第 2 轮演练里，我（PM）开轮时写了第 8 查的**基线**，却**忘了跑比对** ——
产出文件 `write-domain-check.json` 根本不存在。

**这是 AD-01（异族、干净上下文的结构审计）抓出来的**，我自己从头到尾没意识到。

> 这说明结构审计这个角色**不是仪式**：它检查的是「该有的产出在不在」，
> 而执行者恰恰对自己漏掉的那一步**没有记忆** —— 你不会去检查你以为自己做完了的事。
>
> 同时也说明**「跑一遍流程」比「读一遍流程」有效得多**：这个缺口只有真跑才会暴露。
