# L-0011 语义指纹不得包含格式噪声（但也不该装作消掉了全部噪声）

- **日期**：2026-10-19
- **触发**：核对 `pointer_id` 实现与协议定义式，发现两者不一致
- **缺陷编号**：F17

## 现象

协议 `07 §4.5` 写的是：

```
pointer    = {file, selector, file_sha256}
pointer_id = sha256("<file>|<selector>")[:16]
```

实现是：

```python
pointer_id = sha256(整条 pointer 字符串)[:16]
```

于是同一份文件的同一条证据，只要写法不同就是不同 id：

| 写法 | 旧实现的 id |
|---|---|
| `fixtures/ledger.csv#T104,T105` | A |
| `./fixtures/ledger.csv#T104,T105` | **B**（≠A） |
| `fixtures/ledger.csv:26-27` | **C**（≠A） |

`metrics` 用 `pointer_id` 集合差来判断「本轮是否带来新证据」（`idle_detection`）。
把同一批证据换个写法重投一遍，就会被判为「有新证据」→ **空转检测被无意义地绕过**。

## 根因

**把格式噪声编进了语义指纹。** 指纹本应只反映「指向哪个观测」，
却被「怎么写的」污染了。

同类前科：`DIFFSET` 曾用 `wide/medium/narrow` 别名（会随数据漂移）；
`shared_pointer_count` 曾把 `#T104,T105` 与 `:26-27` 判成不同证据源。

## 修法（两层）

1. **词法归一**：`resolve_pointer_path` 去 `./` 前缀、折叠连续斜杠。
   关键点：这一步**不依赖文件是否存在**。原先只在「探测到文件真实存在」时才做相对化，
   于是指向「将来才生成」或「夹具占位」的路径永远归一不了。
2. **指纹定义**：`sha256(sorted("<file>|<selector>"))[:16]`。
   `sorted` 保证多指针的书写顺序不影响结果（顺序不是语义）。

## 必须同时说清的**残余绕过**（不可省）

本修法只消掉**路径写法**噪声。把 `#T104` 改写成 `:26` **仍是不同 id** ——
换「选择子写法」依然可以伪造新证据。脚本无法区分「真的取了一个新观测」
与「把同一个观测换了个写法」。

因此 `metrics.json` 额外输出 `new_file_keys`：当
`new_count > 0` 但 `new_file_keys == 0` 时给一条 note（「本轮新证据全部来自已有文件」）。
**该提示不触发动作**，只用来避免「有新指针 = 有新观测」这个错觉。

> 不宣称「已修复兜底」比宣称了更好：宣称了会让人停止怀疑。

## 通用化

> **指纹只该含语义分量。** 任何进哈希的东西，都要问一句
> 「换一种等价写法，它变不变？」变了就是噪声。

配套的两条纪律：

1. **归一化要在入口做，不要等到比较时补**（否则每处比较都要记得带归一）。
2. **归一化不覆盖的部分，要显式写进协议**，并在产出里给一个可观测的提示字段 ——
   让「未覆盖」可见，而不是让它看起来像「已覆盖」。

## 代价与边界

- 词法归一不处理 `..`（向上跳目录）与符号链接；这两者会让「同一个文件」有更多别名。
- `sorted` 对多指针只保证顺序无关，不保证「合并写 vs 分开写」等价
  （`a#1 + b#2` 与 `a#1,b#2` 后者解析为单指针两个选择子），这是**已知不等价**。
