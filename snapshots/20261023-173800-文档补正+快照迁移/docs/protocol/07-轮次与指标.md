# 07 · 轮次与指标

> 本文件把「防谄媚机制」从**只有阈值与动作**变成**可计算**。
> 在此之前，`flip_rate` / `dissent_entropy` / `devils_advocate_round` / `idle_detection`
> 在 `params.json` 里有阈值、有动作，但**代码侧没有任何消费者** —— 那些数字只是装饰。
>
> 本文件定义式 + `scripts/metrics.py` 实现 = 让它们成为真参数。

---

## 一、★ 一条不可绕过的架构事实（先读这条）

> **子代理只能由主会话通过 Agent 工具发起。Python 脚本无法调用 Agent 工具。**
>
> 因此本项目的「编排器」在物理上只能是**约束层 + 记账层 + 校验层**，
> **发起动作必须人工**。任何声称「全自动多轮编排」的设计在本环境都是假的。

对应地：`new_round.py --emit-prompts` 产出的是**提示词文件**，不是「已发起的会话」。
第 4 步永远需要人。

## 二、轮次目录约定

```
runs/round{n}/
  round-manifest.json        # round, role, expected_seats, prev_round, seed, introduces_new_evidence
  wd-baseline.json           # 第 8 查写入域基线（★ 只在开轮时建一次，重跑不重置）
  inputs/pack-<ANON>.json    # 匿名化后的同伴产出（脚本写，交给席位）
  presentation/anon-map.json # 匿名映射（脚本写，★ 不交给任何席位 —— 它是匿名化的密钥）
  presentation/order.json    # 确定性乱序 + seed
  prompts/<seat>.md          # 本轮提示词（脚本写）
  <SEAT>.json                # 席位产出（席位写）
  AD-01.json  PM-01.json     # 审计 / 项目经理产出
  seat-check.json            # 契约校验（脚本写）
  metrics.json               # 轮次指标（脚本写）
  pending-adjudication.json | adjudicated.json
  verdict-*.json             # 硬裁判裁决
  write-domain-check.json    # 第 8 查结论
  answer-final.json          # 聚合产物（PM 写，须含 aggregation_inputs[]）
```

**轮次间状态传递载体**：第 n+1 轮的输入 = ① `runs/round{n}/metrics.json`（决定动作）
+ ② `new_round.py` 基于 `runs/round{n}/` 席位产出重建的**匿名重呈现包**。

> 写它的人是**脚本**，不是 PM、不是席位。理由：载体若由席位写，它就能决定同伴看到什么。

## 三、轮次类型与终止条件适用范围 ★

若不处理这一条，第 2 轮会被自己的终止条件杀掉 —— 协议规定「边际信息增益为零 → 终止」，
而质询轮按定义不引入新证据。

| 轮次类型 | 允许新证据 | `idle_detection` | 「零边际增益」 | 成功判据 |
|---|---|---|---|---|
| `evidence_round` | 是 | **适用** | **适用** | 新证据指针数 > 0 |
| **`revision_round`** | **否** | **不适用** | **不适用** | 立场变动 + 新反对边 |
| `devils_advocate_round` | 否 | 不适用 | 不适用 | 少数立场被物化为完整产出 |

`revision_round` 的新信息操作化为**「新反对边」**：三元组 `(axis_id, target_stance, direction)`。
新边喂 `dissent_entropy`，**不喂**证据计数器。
`metrics.json` 必须显式输出 `notes`，说明「round_role=X → idle/zero-gain 不适用」，避免读报表的人误以为漏判。

**备选未采用**：把「反对意见」也算新证据 → 任何一轮都必然「有新证据」，`idle_detection` 永远不触发，机制失效。

## 四、操作化定义

### 4.1 立场 = 两坐标向量

**设计原则**：防谄媚指标的自变量必须是**机器可算**的量，**不能是被检测者的自述**。
谄媚正是通过自述通道传播的 —— 用自述算翻边率，等于让被测者决定自己有没有翻边。
故立场以**从产出数字反推**为主，自述仅作交叉校验。

由 `fixtures/spec/adjudication.json` 的 `options[].implies` 机械反推：

| 坐标 | 取值域 | 反推规则 |
|---|---|---|
| `ADJ-001` | `count` / `exclude` / `abstain` | **任务相对**：取本任务 `spec/adjudication.json` 的 `options[].implies`，答案 summary 与某选项 implies 精确相等（Decimal，scale=2）→ 该选项 id；全不匹配 → `abstain`。★ 常量随任务而变（001 是 680.02/500.02，T-0X 各不相同；2026-10-20 修订轮实测：把任何一组数值写死在协议里都会误导席位与审计） |
| `DIFFSET` | `"7"` / `"6"` / `"5"` / `"4"` / `abstain` / `out_of_space` | 取 `summary.diff_count` |

**★ 2026-10-19 结构修复（F15）**：`ADJ-002` 与 `ADJ-003` 曾各自改写 `diff_count`/`diffs`，
而 `implies` 是**静态值** —— 四种组合里只有一种不自相冲突，且「跨月与口径差都不算差异」
应得 **4 条**而 4 根本不在选项空间里。结果：**人的真实判断无法表达**，闸门只能承载
机器已经算出的那个答案。现合并为**单轴四选项**（`ADJ-003` 退役）：

| 选项 | 跨月类单号 | 口径差类单号 | 清单条数 |
|---|---|---|---|
| `7` | 列入 | 列入 | 7 |
| `6` | 不列入 | 列入 | 6 |
| `5` | 列入 | 不列入 | 5 |
| `4` | 不列入 | 不列入 | 4 |

**★ 任务相对（D-0023，2026-10-20）**：上表「跨月/口径差」指本任务 diffs 中的对应**类别**，
单号与条数基数随任务而变（T-09/T-12/T-14 等无跨月单号的任务，其选项空间由生成器
按夹具结构另行给出，如 [6,5,4,3]）——席位必须以**本任务提示词与 spec 的选项空间**
为准，本表只描述 001 的历史形态。

> 注：本注原插在表格中间，把 4 行表拆成「3 行 + 孤立 1 行」，2026-10-21 修正为表后注。

选项由**定义式**生成（`make_fixtures.emit_layered_specs` 的 `_diffs`），不手写；
生成器断言 `len(diffs) == int(option_id)`，不等即拒绝出包。

**为什么 `DIFFSET` 的取值用数值字符串而不是 `wide/medium/narrow`**：
四个取值就是 `summary.diff_count` 本身，中间加一层别名只会多一处漂移的地方。

`diff_count` 落在 `{4,5,6,7}` 之外 → 记 `out_of_space` 并告警（`E_STANCE_OUT_OF_SPACE`）。

**自述与反推不一致 → `W_STANCE_MISMATCH`（warning，不是 error）。**
这正是 EX-02 的形态（自述乙、为甲写 steelman），**它本身是最有价值的信号**，不能当错误抹掉。

**金额轴 × 清单轴的语义一致性（`W_STANCE_SEMANTIC_CONFLICT`，warning）**：

```
money_counts_caliber := ADJ-001 所选选项的 excluded_amount_total == 0
list_counts_caliber  := ADJ-001 的 affected_ids ∩ DIFFSET 所选选项的 diffs ≠ ∅
冲突 := money_counts_caliber AND NOT list_counts_caliber
```

即「金额里算了口径差，清单里却没有它」。两个数字各自都能过校验，合起来不自洽。
★ 依赖一个显式假设：`excluded_amount_total` 的非零部分**只来自口径差**（由夹具构造保证：
跨月项两边金额都是 4800.00）。若将来出现「跨月且金额不等」的样本，此判据会误报，
须同步修正判据，而不是放宽它。

### 4.2 翻边率 flip_rate

```
可比对 := 两轮取值均 ∈ options(axis)（非 abstain、非 out_of_space）
分子 N = 可比对且 s_r != s_{r+1} 的 (seat, axis) 对数
分母 D = 可比对的 (seat, axis) 对数
flip_rate = N / D      若 D == 0 → null（未定义，绝不当 0）
告警 := flip_rate > flip_rate_alert_threshold（严格大于，对齐协议「> 40%」）
```

**分母为什么取 pair 而不是席位数或轴数**：
- 取**席位数** → 全程弃权的席位会被算成「稳定」或「翻边」，两种都是假的
- 取**轴数** → 一席改变即整轴翻边，随席位数增加饱和到 1
- 取 **pair** → 唯一同时满足「弃权不惩罚」「多轴不等权」的取法

**小样本缓解**：报告 `D`；`D < 2` 时标 `low_confidence: true`，**不按阈值硬判重启**。

**`restart_round` 的语义**：新建 `round{n}b`，以 `round{n-1}` 的**干净产出 + 新种子**重跑。
- **不是就地重跑** —— 同样的输入与顺序会复现同样的翻边，等于没有干预
- 二次失败 → `restart_exhausted` → `ESCALATE` 人类闸门
- 重启不是无限权利，否则会掩盖「输入本身有歧义」这一更深原因

### 4.3 分歧熵 dissent_entropy

**域**：立场向量逐轴。**不对连续数字算熵** —— 强行分箱会把「0.01 的差别」与「180.00 的差别」等同。

```
H(a)      = -Σ (n_i/N_a)·log2(n_i/N_a)
H_norm(a) = H(a)/log2(K_a)      （K_a<2 或 N_a<2 → N/A）
round_mean = 有值各轴的均值
```

**★ 下限数值及其如实标注的局限**：`params.json` 的 `dissent_entropy_floor.value = 0.10`。

> 当前所有轴都是 2 选项。2 选项轴上「1 票异议 + (S-1) 票多数」的 `H_norm = 0.918`（S=3）；全票一致 = 0。
> **因此任何落在 (0, 0.72) 的下限，此刻都等价于「一致性探测器」—— 取 0.10 与取 0.50 无差别。**
> 选 0.10 是为未来出现 3 选项轴留空间（那时 2:1:0 的 `H_norm=0.5` 应算「有分歧」而非「一致」）。
> **不得让这个下限看起来比它实际更精细。**

### 4.4 ★ 「独立证据」的操作化（两次实现期修正）

**第一次修正（第 2 轮）**：原设计写作「该一致立场的席位**无任何 evidence 指针**」。
**这与席位契约冲突**：契约要求 `evidence ≥1` 项，故合规席位**永远不可能**满足该子句 ——
**机制永不触发**。于是改为「存在某席位，其至少一条指针不被其他席位引用」。

**第二次修正（第 4 轮，缺陷 F6）**：上述实现的去重键是**证据指针整串的 sha256**。
实测第 2 轮三席**都指向 `fixtures/ledger.csv`**，但写法不同
（`ledger.csv#T104,T105` / `ledger.csv:26-27` / `ledger.csv`）→ 得到三个不同 id →
`shared_pointer_count = 0`、三席全被评「独立」。**判据被写法打败了。**

改为**文件级**归一化：

```
normalize_pointer(ptr) -> {kind, file_keys[]}
  单指针     → 文件键（相对包根、正斜杠；目录补尾斜杠）
  多指针     → 以 " + " / " 与 " / "、" / "；" 切分后逐个解析
  记录坐标   → #T104 / :26-27 一律丢弃，只保留文件层
  解析失败   → 保守回退为整串（宁可判为不同文件）

独立证据          := 存在某席位，其某条证据的 **文件键** 不被其他席位引用
shared_file_count := 被 ≥2 席引用的文件键个数
```

**为什么取文件级而非记录级**——两类错误的代价不对称：

| 粒度 | 错判后果 | 性质与代价 |
|---|---|---|
| 粗（文件级） | 多触发一轮魔鬼代言人轮 | **干预**，代价是一轮 token |
| 细（记录级） | 让共享盲区冒充已验证的真相 | **污染**，代价是结论本身不可信 |

**★ 一条不能违反的划分**：`pointer_id`（整串 sha256）**只服务空转检测**（判断两轮之间
是否带来了新证据）；`file_key` **只服务独立证据**。二者混用会打穿空转检测 ——
同一文件第 10 行与第 20 行是「新证据」，但不是「独立观测」。

```
devils_advocate_required := round_mean < floor
                          AND 存在某轴全部可比对席位取同一选项
                          AND NOT 独立证据
```

**诚实边界**：脚本据此判断的是「**文件键**是否被共享」，**无法验证该指针的内容是否真的提供了独立支撑**。
两席引同一文件的不同段落，仍可能只是各自摘取对自己有利的部分。

**执行方式**：不新增席位。在 `runs/round{n}/devils-advocate/` 下，要求持多数立场的每席
按反立场产出**完整合规**的 answer。它**不计入 `debate.max_rounds`**（是干预，不是辩论轮）。

### 4.5 「新证据指针」的操作化

```
pointer      = {file, selector, file_sha256}
pointer_id   = sha256(sorted("<file>|<selector>"))[:16]   # 不含内容哈希 → 跨轮可识别
new_pointer(r) := pointer_id ∉ 所有 < r 轮的 pointer_id 集合
idle(r)        := new_evidence_count(r) == 0
idle_detected  := 连续 >= consecutive_rounds_without_new_evidence 轮 idle
```

**为什么是 `sorted(...)`**：多个指针的**书写顺序不是语义**，排序后哈希让
`A + B` 与 `B + A` 得同一个 id。

**★ 残余绕过边界（不可删）**：本式只消掉**路径写法**噪声
（`./fixtures/x` 与 `fixtures/x` 视为同一证据）。但把 `#T104` 改写成 `:26` 仍是**不同 id** ——
**换「选择子写法」依然可以伪造「新证据」**。脚本无法区分「真的取了一个新观测」
与「把同一个观测换了个写法」。

因此 `metrics.json` 的 `evidence` 段额外输出 `new_file_keys`：
当 `new_count > 0` 但 `new_file_keys == 0`（本轮「新证据」全部来自已有文件）时，
在 `notes` 里给出提示。**该提示不触发任何动作**，只用来避免「有新指针 = 有新观测」的错觉。

**与 `file_key` 的分工（铁律）**：
- `pointer_id` → **空转检测**（是否带来新的观测单元）
- `file_key` → **独立证据**（是否与他人共享同一证据源）

二者混用会互相打穿：把 `pointer_id` 降到文件级，两件事就变成同一件了。

**round1 无 `evidence[]` 怎么办**：**不对它做文本挖掘** —— 正则捞 `ledger.csv`/`T101`
会引入歧义（「提到」≠「作为证据」）。处置：标 `evidence_schema_absent: true`，
移出 idle 计数历史，`evidence_history_available_from: 2`。此事实必须写进 `metrics.json` 的 `notes`。

### 4.6 匿名化 / 随机顺序 / 长度归一化

| 机制 | 操作化 | 实现 |
|---|---|---|
| 匿名化 | 剥离身份标签字段，替换为 `ANON-A/B/C`；映射写入**不交给席位**的 `presentation/anon-map.json` | 字段白名单剥离 |
| 随机顺序 | `seed = sha256("<round>|<prev>|<params_sha>")[:8]`，**确定性可复现** | `random.Random(seed)` |
| 长度归一化 | **不是「等长化」**：① 提交时字段长度预算，超限 → `W_OVER_LENGTH`；② 轮后诊断 `length_spread` | — |

**三条必须写明的诚实边界**：

1. 脚本能删**身份标签**，删不掉**文风指纹**。三个席位长期各自写 `evidence` 的措辞习惯是可辨识的。
   故匿名化降低的是「**显式身份驱动**」谄媚，**不是**「文风驱动」谄媚。
2. **真·长度归一化在本场景不可实现且不该实现**：纯标准库做不了同义压缩；
   截断到最短席位长度会**按篇幅惩罚论证更充分的席位**（奖励写得少的人），是反向偏置。
3. 长度偏置的实测证据（长度与胜负相关性 0.98）来自**打分/评判**场景。本架构里
   **没有任何席位给别的席位打分**，`XJ-01` 决策权重为 0，`JD-01` 是脚本 ——
   作用通道已被结构性削弱，但**未被消除**（质询轮的说服力部分靠篇幅）。

## 五、席位输出契约

**硬闸门（缺失即不合格，不得进入聚合）**：`seat`、`round`、`conclusion`、`evidence`（≥1 项，每项含非空 `pointer` 与 `what_it_shows`）、`falsification`。
**软项（warning）**：`confidence`、`dissent`、`needs_more_data`、`stance`。
**豁免 `stance` 的席位**：`AD-01`（审计不得持立场）、`PM-01`（只拍板）、`XJ-01`（决策权重 0 不得表态）。

### 5.1 「不合格则不得进入聚合」的执行机制

**不使用「把不合格文件挪走」** —— 那会销毁证据（违反分歧守恒），且让工具替人做判断。
改用**三重执行 + 一处硬门**：

1. **记名**：`seat-check.json` 的 `aggregation_blocked` 列出被否决席位及 `sha256`
2. **指标拒绝**：`metrics.py` 见 `aggregation_blocked` 非空 → **拒绝计算**该轮指标，
   `metrics_status: "blocked_by_contract"`，**exit 5**
   （理由：从被否决的产出里算翻边率，会把契约污染带进指标）
3. **写入者硬门**：PM 的 `answer-final.json` 必须含 `aggregation_inputs[]`
   （每项 `seat`/`sha256`/`seat_check_status`）；`seat_check.py --verify-final` 交叉核对，
   凡 `status != "valid"` 的席位其 `sha256` **不得**出现，出现即 **exit 1**

> **为什么第 3 条有效**：`PM-01` 是唯一写入者。把闸门装到「写入者必须自助产出的元数据」上，
> 就能在**没有物理隔离**的环境里，让「引用了被否决席位」**必然留下可检出的痕迹**。
> 这与 `06` 文档 §1.4 是同一个思路：**把不可见变成可见，判断留给人**。

## 六、退出码

| 工具 | 码 | 含义 |
|---|---|---|
| `seat_check` | 0 / 1 / 2 / 3 | 全合规 / 存在不合格 / 用法错误 / **该轮找不到任何席位产出（fail-closed：没东西可校验 ≠ 通过）** |
| `metrics` | 0 | 无需动作 |
| | 1 | 需 `restart_round`（翻边率超阈值） |
| | 2 | 输入/用法错误 |
| | 3 | 需 `force_devils_advocate_round` |
| | 4 | 需 `terminate_branch`（`evidence_round` 连续无新证据 **或** 申报预算超限） |
| | 5 | `blocked_by_contract`（存在被否决席位，指标不可信） |
| | | **严重度序 5 > 1 > 3 > 4**，同时命中取最严重 |

★ 预算（F18）与空转共用退出码 4，但来源不同：`metrics.json` 的 `budget.status` 三态为
`exhausted`（超限，真动作）/ `unverifiable`（有席位未申报，**不等于超支**）/ `ok`。
**未申报不得被当作超支** —— 否则所有历史轮次一上线就被判终止。

### 6.1 预算的计量定义式（阈值不得脱离定义式单独存在）

```
tokens_total  = Σ int(usage.tokens)  over 本轮【全部席位】
                → 与 per_task_token_hard_cap 比较（求和，不是单席上限）
minutes_span  = max(usage.minutes)   over 本轮【全部席位】
                → 与 per_task_wall_clock_hard_cap 比较（取最大，不是求和）
missing       = 未申报 usage 的席位集合，记入 missing，**不记 0**
```

**为什么 minutes 取最大而不是求和**：PM-01 的 `minutes` 按定义就是**本轮整体跨度**，与各辩论席的时间是同一条时间轴上的重叠区间，求和会把同一段时间重复计入。

**`per_task_*` 的名字**：其中「任务」= 一轮完整的六席流程。多任务并行时按轮次分别计量，**不得跨轮相加**。不改名的理由：改名会打穿 `REQUIRED_PARAM_PATHS`、自检字面量与决策日志引用，且不产生任何新信息 —— 用 `params.json` 的 `cost_budget._semantic` 把语义写成可执行的定义式即可（`L-0005`：阈值必须与定义式同时落盘）。

**当前值（P10 起）**：`per_task_token_hard_cap = 160000`，来源为 round3 六席实测 126100 + 26.9% 余量后取整。历史轮次 `runs/round3/metrics.json` 记录的是 `cap=80000` 下的 `exhausted`（exit 4），那是**当时的真实观测，不得据此重算或改写**。

★ 两个校验点是第 4 轮新增（缺陷 F10）：原流程只在辩论席位产出后校验一次，

## 八、演练成功的可检验判据

**不是「看起来跑通了」**，而是：

- **S1** `seat_check` exit 0 且 `aggregation_blocked == []`
- **S2** `flip_rate.value` 是**具体数字（非 null）**，`dissent_entropy.round_mean` 有值
- **S3** `flip_rate.alert` 的布尔值**被计算出来**，`actions` 明确含/不含 `restart_round`，且 `notes` 说明依据 —— **判据是「机制被计算过」，不是「告警响了」**
- **S4** 分歧熵触发被计算；若满足条件，`actions` 必须含 `force_devils_advocate_round` 且产出 `devils-advocate/`
- **S5** `write-domain-check.json.verdict == "CLEAN"`（若 HIT，须有 `docs/decisions/` 授权留痕）
- **S6** `verify.py --spec-dir` 退出码记录在案；**若为 pass，前提是真人签署了裁决记录**
- **S7** 全量回归（项数随版本增长，2026-10-20 时为 50）全绿，且**连跑两次仍全绿**（幂等；否则只是「重建 MANIFEST 后第一次是绿的」）
- **S8（证伪条件 —— 演练失败长什么样）** 出现任一即判失败，须如实记录而非解释掉：
  1. `seat_check` 否决了席位，但 `answer-final.json` 仍引用其 `sha256`
  2. 所有轴 `comparable` 全为 false → `flip_rate.value == null`（说明立场反推设计需重做）
  3. 第 2 轮被 `idle_detection` 终止（说明轮次类型豁免规则没生效）
  4. 数字与上一轮完全一致且**没有任何** dissent 边（不是「稳定」，是「空转」）
- **S9** 决策日志落地，含工作协议要求的四段
- **S10（第 9 查）** `read-domain-check.json` 存在且 `verdict ∈ {CLEAN, HIT}`；
  若为 `HIT`，被越界的席位**不得**出现在 `aggregation_admissible` —— 否则「检测到了但没拦住」= 检测只是装饰
- **S11（六席全覆盖）** 阶段 A 与阶段 B 都有 `seat-check` 产出，
  `AD-01` / `PM-01` **各自**都有校验结果（不能只校验辩论席位就宣称「席位契约已生效」）
