# L-0039 软链掩盖物理分布——判断"副本是否冗余"必须按卷取证，不能看路径

**日期**：2026-10-29
**标签**：备份 / 软链 / 物理卷 / 取证 / 误判纠正
**类型**：★ 升级候选（跨项目通用） 〔🔁auto-promote-2026-11-22·✅已评估·同族覆盖→「冗余按物理卷取证」〕
**性质**：跨项目通用（任何评估"数据安全性/副本冗余/异地备份"的场景）
**状态**：已实测（2026-10-29 本会话，纠正了本会话上一轮自己的错误评估）

## 发生了什么

上一轮状态评估里我写下「仓库 + 备份同盘无异地副本」，并据此把"备份异地副本增强"
排进后续计划。这一轮动手前按纪律复核实况，`df` + `readlink` 取证的结果把这句话
**两半都推翻了**：

| 路径（人看到的） | 真实物理卷 | 结论 |
|---|---|---|
| `~/WorkBuddy/2026-.../ai-autonomy-team`（仓库） | 外置盘 `/dev/disk5s1` | — |
| `~/Backups/ai-autonomy-team`（备份） | **内置系统盘** `/dev/disk3s5` | 备份本就**跨盘**，不是同盘 |
| `~/.workbuddy`（MEMORY 本体+快照） | **软链到 `/Volumes/ZHITAI/workbuddy_data`** = 外置盘 | 与仓库**同盘** |
| `~/WorkBuddy/Claw`（claw MEMORY） | **软链到 `/Volumes/ZHITAI/WorkBuddy`** = 外置盘 | 与仓库**同盘** |

真实结论不是"仓库+备份同盘"，而是：**MEMORY 全线（3 份本体 + 14 份 memory_snapshots
+ 20+ 个 .bak）压在单独一块外置盘上，且私有远端按隔离策略不含 MEMORY**——这才是真单点。

## 根因

判断"两个路径是不是同一份物理存储"时，我用了**路径字符串的直觉**：
`~/Backups` 和 `~/WorkBuddy` 看着都在 `~` 下，就想当然认为同盘。但 Mac 上
`~/.workbuddy`、`~/WorkBuddy` 都是指向外置 SSD 的**软链**，而 `~/Backups` 不是。
软链让"看起来在同一目录树下"和"实际在同一块磁盘上"彻底脱钩。

这是"声明腐烂"的同族但更隐蔽：**不是数字错，是拓扑判断错**——而且错的方向
恰好相反（以为缺冗余，实际冗余在别处；以为安全，实际单点在别处）。

## 铁律（候选）

1. **判断副本冗余/同盘/异地，唯一可信的是卷**:`df <每个路径>` 比对 `Filesystem`
   设备号（`/dev/diskXsY`），外加 `readlink` 逐段拆软链。绝不看路径前缀。
2. **"清理/备份评估"动手前必须重新 `df`+`readlink` 取证** —— 软链结构会随外置盘
   挂载、账号迁移、重装变化，历史结论会静默失效。
3. **表述冗余要落到"哪块物理盘"**：写"有两份副本"不算，写"一份在 disk3s5、
   一份在 disk5s1、远端 GitHub"才算。聚合的"N 份"会抹平物理分布差异
   （同族于"聚合稳定≠状态稳定"）。
4. 软链目录里的资产清点，要 `Path(x).resolve()` 拿到真实落点再判断，
   不能用相对/别名路径。

## 触发本条的判据（可证伪）

`df ~/.workbuddy ~/Backups ~/WorkBuddy <仓库>` 四行里只要出现 ≥2 个不同
`Filesystem`，且其中某资产（如 MEMORY）的所有副本都落在同一设备号，即命中。
本次实测 disk5s1 上 MEMORY 全集中、disk3s5 上只有 bundle/tar 备份，命中成立。

## 处置（已落地）

`make_backup.py` 增加 `memory-*.tar.gz` 产物：把 3 份 MEMORY.md 备份到**内置盘**
`~/Backups/`（disk3s5），逐份全量 sha256 校验、权限 600、与快照归档各自独立
retention；绝不入库/上云（半敏感信息隔离）。实测还原验证 3/3 通过。详见 D-0045
「MEMORY.md 本地跨盘备份」节。
