## 决策

1. **S1 门控实测通过，不降级**：跨家族子代理路由可用，软裁判 XJ-01 权重保持设计值（提示级，决策权重 0）。
2. **硬裁判实现方式**：纯 Python 标准库 + `run.sh`/`run.cmd` 薄封装（探测解释器后转发）。
3. **规格消歧三次后定稿**：把 `amount_diff_total` / `excluded_amount_total` 改为**可操作定义**（一律取 `abs(台账−账单)` 原始差额、重复项不参与），并新增 3 个纯算术锚点。
4. **判据与命名解耦**：删除所有按**类别名**精确匹配的检查（类别名由执行体自定，会误判），改为只判数字与 txn 集合。
5. **污染处置**：`fixtures/recon.py` 与 `runs/round1/_ex02_compute.py` **不移除而是移入 `evidence-boundary-violation/` 留证**（它们是 F2 缺陷的证据，销毁证据比保留污染更糟）。
6. **本轮不创建任何定时自动化任务**（沿用 D-0001 决策）。
7. **验证报告如实披露未覆盖部分**：多轮辩论、翻边率、魔鬼代言人轮、XJ-01 均未演练。

## 备选方案与未采用理由

| 备选 | 未采用理由 |
|---|---|
| S1 假定跨家族可用、跳过实测 | 软裁判是双裁判架构的一半；假定错了后续验证全白做。实测成本仅两次短调用 |
| 硬裁判用 openpyxl/python-docx | 目标机（macOS）没有这些库，硬裁判将在唯一有否决权的部件上失效 |
| 硬裁判改用 Node | 引入第二套运行时；M4 的 Node 版本未确认 |
| 保留按类别名匹配的判据 | 类别名由执行体自定（如「税务口径差异」），精确匹配会把正解误判为错——不公平判据 |
| 直接删除越权写入的脚本 | 会销毁 F2 缺陷的证据。改为移入 `evidence-boundary-violation/` 留证 |
| 收紧 `truth.json` 使期望值可自动裁决 | **未采用——因为这正是 F1 要暴露的问题**。把判断塞进判据不是修复，是把问题藏得更深 |
| 判基线 v1/v2 为「被测方失败」 | 两者失败均源于我方规格歧义（依据 3），归因错误会导致错误的改进方向 |
