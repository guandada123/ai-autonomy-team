# D-0023 · DIFFSET 选项表是任务相对的，协议表只描述 001 的历史形态

- **日期**：2026-10-20（补落为正式文件；实施早于此）
- **依据来源**：`migration-package/protocol/07-轮次与指标.md:95` 注释
- **操作分级**：🟢 低（文档口径澄清）
- **状态**：已执行

## 决策

`protocol/07` §4.1 的 DIFFSET 选项表（7/6/5/4）**只描述任务 001 的历史形态**，
不是跨任务通用的口径。席位必须以**本任务提示词与 spec 的选项空间**为准。

## 依据

| # | 依据 | 来源 |
|---|---|---|
| 1 | 选项空间由夹具结构决定：`counts = {all, g1, g2, none}`，随各任务 g1/g2 类的条数而变 | `make_tasks_20.py` `counts` 构造 |
| 2 | 实测 20 个任务的选项空间**恒为 `['6','5','4','3']`**（equity=2、settlement_day=1 → 基数 3），与协议表的 7/6/5/4 不同 | 契约 3.0 裁定记录 §8.2 ④ |
| 3 | T-09/T-12/T-14 等无「跨月」单号的任务，其选项空间由生成器另行给出 | `protocol/07` D-0023 注释 |

## 备选方案与未采用理由

| 备选 | 未采用理由 |
|---|---|
| 把协议表改成通用表 | 各任务的类别基数不同，无法用一张表覆盖；通用化必然失真 |
| 删除协议表 | 001 是历史基线任务，保留原表供追溯，加限定说明成本更低 |

## 审计发现

**协议文档里的具体数值容易被当成跨任务标准**。本决策的处理方式（保留 + 加限定说明）
比删除更好：既保留历史可追溯，又明确「这不是通用口径」。

配套措施：ADJ-002 的 question 文本**自带本任务的条数**（`「equity」类（2 条）`），
席位不必依赖协议表 —— 这才是真正的防错机制。
