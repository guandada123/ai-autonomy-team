# 口径库 v1 · 审查员使用手册（2026-10-31）

> 给 R1 数据核查员 / R2 逻辑审查员 的**口径证据源**。
> 机读版：`audit/baseline/v2/caliber-library.json`（同一内容的唯一真源；本文件是人读摘要，冲突以 JSON 为准）。

## 一、为什么需要它

上一轮二审实验证明：审查员只查"题面是否自洽"，**不知道用户已确立的处理口径**，因此对"同一证据支持两个选项"这类问题拿不出证据，二审 75 次作答 **0 改动**。本库把用户历史裁决（ADJ 记录 + 2026-10-31 题级裁决）固化成可引用的条目。

## 二、引用规则（强制）

1. **必须带条目 id**：`[C-003]`、`[E-001]`。只写"建议复查""口径可能不唯一"而无 id 的，视为**口径证据不足**。
2. **必须同时判断优先级**（M-001）：**题级最新裁决（exception）> 通用原则（principle）**。原则与例外冲突时以例外为准。
3. **引用例外必须说明命中范围**（M-002）：例外只在 `applies_to` 内成立；超出范围仍按原则。写法：`[E-001，命中：差额根源为系统缺字段且可工程化修复]`。
4. **异常要落到具体选项**：说明"按 [C-004]，选项 C 与本口径一致；选项 A/D 属于单边结案，与本口径冲突"——审查员仍不给出最终答案，只给口径映射。

## 四、判定流程（四步）

1. **定位问题类型**：是"该不该计入/该不该留/该不该结案"，还是"题面自相矛盾"？前者查口径，后者查事实。
2. **先找例外**（E-xxx）是否命中：命中则按例外，并写明范围；未命中进第 3 步。
3. **按原则**（C-xxx）给映射：说明哪些选项与本口径一致、哪些冲突。
4. **输出**：`{"qid","type","caliber_refs":["C-004"],"mapping":{"D":"与口径一致","A":"单边结案，冲突"},"detail"}`。**不给最终答案**（那是 R4 的职责），只给口径映射。

## 四点五、M-004 专章：归档与转办是"合规"还是"逃避"

用户裁决看着矛盾：V2-21 选归档、V2-06 选全留。区分点不是"留不留"，而是**归档的性质**：

| 判据 | V2-21（零金额归档 ✓） | V2-06（已说明存档 ✗） |
|---|---|---|
| ① 有无未完成核实 | 无（金额为 0，无可核对的钱） | 有（缺勤是否成立未核实） |
| ② 分类是客观属性还是结论 | 客观（金额=0） | 结论（"已说明"=已解释） |
| ③ 是否逐条保留 | 逐条搬运，条目与分类都在 | 只显示 3 条，其余退出视野 |

三条全中 → **应当归档**（不无限期占待办）；缺一条 → 回落「保留至闭环」，但保留须标注矛盾点（第⑤条），裸保留不算。

**推论**：转月报附注 / 合并汇总 / 记入背景说明 → 违反 ③；"已解释/已确认"类存档 → 违反 ②；转办给采购但账实核对义务仍属本清单 → 转办不成立（V2-07）。

## 五、常见误用（会被判"证据不足"）

- ❌ 只写"存在口径歧义"不引 id —— 上一轮 R2 的 25 条 issue 有 19 条属此类，对判断无帮助。
- ❌ 只引原则、不检查例外 —— 会把"系统缺字段"的场景错判成"必须计入"（M-001 违反）。
- ❌ 把例外当普适原则 —— "转归档表"只在有承接载体时成立，不能推广成"凡是零金额都可归档"（M-002 违反）。
- ❌ 用口径库直接给答案 —— 口径库说明"什么处理与用户口径一致"，最终作答仍归 R4；审查员越界会把判断题变成抄答案。

## 六、维护

- 新增用户裁决 → 先加 JSON 条目（id/type/statement/applies_to/overrides/source/date），再同步本表；`python3 audit/kit/caliber_lib.py --check` 校验（id 唯一、source 文件存在、overrides 指向存在条目）。
- 条目不删，只加 `status: superseded`（保留可追溯性）。
- 反泄露纪律：条目只描述规则与场景，**不复述具体题目的答案字母**。
