# 04 · 双裁判规范

## 0. 为什么必须是双裁判

**单一裁判不可靠**，因为：
- 同源裁判与产出者共享预训练分布 → 同样的知识缺口、同样的误解、同样的风格偏好
- 实测：GPT-4 评委与人类一致率 87%，GPT-3.5 评委 83%，但两者**彼此一致率 94%**（误差独立时应为 74.4%）→ 约 20 个百分点的共享误差
- 自偏好指数均值 +0.14（GPT-4o 达 +0.21），且 4 个受测模型中**只有 1 个能识别自己的输出**，却全部自偏好 → 偏见是隐式的，针对「自我识别」去纠偏会完全落空

因此裁判必须**结构不同源**，且分为两级。

## 1. 硬裁判 JD-01

| 项 | 内容 |
|---|---|
| 实现 | **非 LLM**：脚本 / 回算 / 单测 / A/B |
| 权限 | **有否决权** |
| 独立性等级 | S（最高） |
| 实现路径 | `scripts/judges/verify.py`（纯标准库，跨平台） |

### 三条铁律

1. **不得只检查「能不能跑通」**
   MAST 案例：生成的国际象棋程序能编译，但不遵守规则。必须检查「跑通了**是否正确**」。

2. **判 fail 不可被静默覆盖**
   禁止推进。PM 若要推进，必须按固定格式留痕：

   ```
   覆盖 JD-01 的 fail 判定。
   风险评级：高 / 中 / 低
   不可逆：是 / 否
   理由：____
   承担人：PM-01
   ```

3. **输出必须含可回读证据 + sha256**
   这是「外部钩子」要求的具体化，也是结构审计第 2 查的判定依据。

### 输出契约

> ⚠️ 本契约必须与 `scripts/judges/verify.py` 的 `build_result()` **逐字段一致**。
> 历史版本曾缺 `judge` / `judge_impl` / `summary` / `override_policy` / `checks[].type` /
> `checks[].weight` / `evidence[].label` 七个字段，属文档与实现脱节，已修正。

```json
{
  "task_id": "...",
  "verdict": "pass | fail | pending_adjudication | adjudicated",
  "judge": "JD-01",
  "judge_impl": "scripts/judges/verify.py (non-LLM, stdlib-only)",
  "spec_layer": "arithmetic | adjudication | all | legacy",
  "summary": {"total": 14, "passed": 14, "failed": 0, "pending": 0},
  "checks": [
    {"name": "...", "type": "decimal_equals", "ok": true,
     "expected": "...", "actual": "...", "weight": 1}
  ],
  "pending": [
    {"id": "ADJ-001", "question": "...", "paths_affected": ["..."], "options": ["count", "exclude"]}
  ],
  "adjudication_source": "none | human",
  "evidence": [
    {"label": "spec", "path": "...", "sha256": "..."},
    {"label": "answer", "path": "...", "sha256": "..."},
    {"label": "adjudication_record", "path": "...", "sha256": "..."}
  ],
  "ts": "2026-10-16T15:36:48+08:00",
  "override_policy": "本裁决不可被静默覆盖。PM 若要推进 fail 的动作，必须留痕：..."
}
```

### 退出码

| 码 | 含义 |
|---|---|
| `0` | pass |
| `1` | fail |
| `2` | 错误（输入缺失 / 格式错误 / **spec 违规**：判断项混入算术层、金额未用 `decimal_equals`、人类闸门记录不合规） |
| `3` | **pending_adjudication**（存在未裁决的判断项） |

> **「未裁决」必须是非零退出。** 若 pending 返回 0，上游会把「没裁决」当成「通过」——
> 那正是「硬裁判携带被争议判断」这个缺陷要消除的假信心。
>
> 📌 本表只覆盖**判据侧**（`verify.py`）。`4 = preflight_blocked` 属**开轮闸门**
> （`new_round.py --preflight`），不在本表，理由见 `05-工作协议.md` 退出码总表。

### 判据分层（硬裁判的裁决范围）

硬裁判只对**算术层**有否决权。判断项一律交人类闸门，机器不裁决。

- 分层规则、算术层路径白名单、金额检查闸门、人类闸门往返与防伪 → 见 `06-写入域与判据分层.md`
- 结构审计第 5 查（规格假设）据此自动判定

### 写入域（谁可以写）

硬裁判所在目录（`scripts/`、`judges/`）属于**禁止写入域**。
写入域清单与第 8 查见 `06-写入域与判据分层.md`。

## 2. 软裁判 XJ-01

| 项 | 内容 |
|---|---|
| 实现 | **跨家族**模型评委 |
| 权限 | 仅提示，**决策权重 0** |
| 独立性等级 | A（有限但真实） |
| 必守条件 | 匿名 + 随机顺序 + 长度归一化 |

### 为什么权重是 0

因为即使跨家族，独立性也是**有限**的：按误差相关性重加权后的集成，相对朴素多数投票也只有约 4.5% 的额外增益。「独立模型家族」比看上去更不独立。所以它提供的是**线索**，不是**判据**。

### 强制约束

- 不得输出单一分数作为决策依据
- 不得固定呈现顺序
- 不得由同家族模型担任
- 未做长度归一化的评分**视为无效**

## 3. 独立性折扣记录法

当理想条件不满足时（例如目标机无跨家族权限），**必须显式记录折扣，不得假装独立性存在**。

在验证报告与 `config/params.json` 中记录：

```json
{
  "independence_discount": {
    "cross_family_judge_available": true,
    "discount_note": "",
    "soft_judge_weight": 0,
    "weight_transferred_to": "JD-01"
  }
}
```

### 本机实测状态（2026-10-16）

| 项 | 结果 |
|---|---|
| 跨家族路由 | ✅ **可用**（子代理成功路由至 `glm-5.1`，智谱 GLM 家族） |
| 证据 | 运行时记录 `providerData.requestModelId` = `glm-5.1`；对照组 = `deepseek-v4.1-flash` |
| 核验工具 | `scripts/inspect_agent_routing.py` |
| 结论 | **无需降级**。A 级信源真实可用。 |

> ⚠️ 注意：核验**必须读运行时记录**，不得采信子代理自述。本次探针 A 自述「GLM-5.1」虽恰好正确，但模型未必知道自己被路由到哪，自述不构成证据。

### 目标机（Mac mini M4）待确认

跨家族可用性取决于**账号权益**，文件无法证实。迁移后须在 M4 上**重跑**：


若判定 FAIL → 按折扣记录法降级：`soft_judge_weight = 0`，权重全部转移至 JD-01。
