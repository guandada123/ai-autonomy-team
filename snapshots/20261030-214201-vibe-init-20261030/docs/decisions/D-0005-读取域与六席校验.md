## 一、决策

| # | 决策 | 一句话理由 |
|---|---|---|
| 1 | 读取域用**四层声明式清单**（`deny_absolute` / `allow` / `deny_default` / `allow_extra_by_seat`），不做路径搬迁 | 单层 allow/deny 无法表达「AD-01 必须读机器产出、辩论席位必须禁读」；路径搬迁是隐蔽不是隔离 |
| 2 | 席位契约新增 `reads[]`（**实际读取全集**），按 `contract_version` 门控：v≥2.0 硬、历史轮次软 | 纯 required 会把 `round2` 从 4/4 打成 0/4，**摧毁「round2 可作第 3 轮基线、D=5」这一结论** |
| 3 | 越界判定为 `E_READ_DOMAIN_VIOLATION` → 该席位**挡在聚合外** | 「检测到了但没拦住」等于检测是装饰 |
| 4 | 「独立证据」升级为**文件级**归一化；`shared_pointer_count` → `shared_file_count` | 旧实现用整串 sha256 去重，三席同指 `ledger.csv` 因写法不同被判「各自独立」 |
| 5 | ★ 铁律：`pointer_id` 只服务**空转检测**；`file_key` 只服务**独立证据**，二者不混用 | 混用会打穿空转检测（同一文件第 10 行 vs 第 20 行是「新证据」，但不是「独立观测」） |
| 6 | `contract_version` 写入 `round-manifest.json`；`flip_rate.status` 四态 | 原先「未传 `--prev`」与「传了但基线 0 合规」共用一句 note，**无法区分** |
| 7 | 流程 12 步 → **14 步**，阶段 A（EX+XJ）/ 阶段 B（AD+PM）两个校验点 | AD-01/PM-01 产出晚于校验时点，是**时序缺陷**而非配置缺陷 |
| 8 | PM-01 的硬校验落在 `--verify-final`（**产物验收门**），不进 `aggregation_blocked` | 后者是「聚合**输入**门」，而 PM 产物就是聚合本身，塞进去会让指标计算误短路 |
| 9 | 回归扩到 **30 项**，新增第 30 项「幂等守门」 | 「11 项全绿」若只在重建 MANIFEST 后第一次成立，那不是全绿，是巧合 |
| 10 | 夹具目录名**必须含数字**（`round8` / `round9`，不用 `round-stage-b`） | 读取域的 `{n}` 靠 `round(\d+)` 解析，名字不合规会让正向夹具自己红 |

## 三、备选方案与未采用理由

| 备选 | 未采用理由 |
|---|---|
| 把 `truth.json` / `spec/` 搬到不可猜路径（`_judge_only/`） | 本质是**隐蔽**而非隔离。脚本可遍历目录，隐蔽只提高门槛，且会让人误以为已有边界 —— 比没有边界更危险 |
| `reads[]` 一律设为 required | 会把历史轮次（含 `round2`）判为不合规，直接摧毁 F7 的修复价值。故按版本门控：**新轮次硬、旧轮次软** |
| 独立证据用**记录级**（解析 `#T104` / `:26-27`）粒度 | 两类错误代价不对称：粗粒度错判只多跑一轮（**干预**），细粒度错判会让共享盲区冒充真相（**污染**） |
| 重建 `round1` 使其合规 | 篡改历史产物以让指标好看，违反「不改写原始结论」。改法是用**三态显式标注**承认「那轮不可作基线」 |
| PM-01 也进 `aggregation_blocked` | 域不对：那是聚合输入门。PM 不合格的正确处置是「本轮不验收、重做聚合」，落在 `--verify-final` |
| 保留第 22–29 项空缺、让第 30 项编号自然顺延 | 编号即索引，跳号会让「计划 30 项」与「实跑 22 项」长期不一致，且掩盖「夹具已备而无人消费」 |
| Windows 上尝试物理隔离（`attrib +R` / ACL） | 两者都是软屏障，进程可自行清除。**不得视为安全边界**；物理隔离只在 macOS 用文件权限 + 低权限运行用户实现 |

## 六之二、F14：回归套件曾依赖未随包转移的临时夹具

**发现方式**：转移包生成后，**在解压副本上**（而非源目录）跑 30 项回归 → **28/30**。

| 项 | 失败原因 |
|---|---|
| 第 6 项（闸门 1） | 依赖 `_trash/tmp-regress/bad-arithmetic-judgment.json` |
| 第 7 项（闸门 2） | 依赖 `_trash/tmp-regress/bad-arithmetic-money.json` |

这两个坏 spec 是**手工建在 `_trash/` 里**的，`_trash/` 不进转移包 → 解压后文件不存在 → 退出码 1（而非期望的 2）。

**为什么源机上一直是绿的**：源机的 `_trash/` 里恰好留着它们。**「回归全绿」在源机成立，在交付物上不成立** —— 这是最典型的「测试不可迁移」。

**修法**：由 `scripts/make_round_fixtures.py` 产出 `fixtures/regress/bad-gate1-judgment.json` 与 `bad-gate2-money.json`，第 6/7 项改指 `fixtures/`（随包转移）。已重跑：源机 30/30、解压副本 30/30。
