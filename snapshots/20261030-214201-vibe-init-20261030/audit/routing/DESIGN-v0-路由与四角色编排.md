### 2.1 任务路由三档判据表

| 档位 | 名称 | 准入判据（全部满足才入档） | 依据 |
|---|---|---|---|
| L1 | 单席核查 | 题面含可重算锚点（recompute_kind ≠ attested，或 attested 有 verifiable_source 字段）；答案空间二元或数值；不依赖人工裁决 | v1.3 三轮两臂满分、零不一致对——事实类无多席增量 |
| L2 | 多角色评审 | 开放判断题（答案不可从仓库反推，item_gate 闸）；选项化（2–4 个）；人工裁决可得（出题人/裁决人分离，D-0064）；选项分布偏斜预筛通过（S1） | v3 证明判断类需要多视角 + 偏斜是真实死因 |

S1 偏斜预筛（L2 必过）：参考答案在各选项上的占比上限 0.5，超限报红不入库；常数基准臂必须先跑，常数基准 ≥ 最强臂的题不入库。

## 四、成员产出 B · 四角色编排方案 v0（agent-app-engineer 安智体，原文）

### 4.1 角色定义表

| 角色 | 职责 | 输入（消费 / 禁读） | 输出 schema（结构化） | 触发条件 |
|---|---|---|---|---|
| R1 数据核查员 | 只核事实与口径：题面引用的数字/规则/时点是否可从**合法来源**（非禁区）测得；标记"题面事实与证据不符" | 消费：题面 + 仓库合法文件；禁读：`audit/baseline/` 一切内容（禁读边界 v1 标准段原样粘贴） | `{"role":"verifier","qid":"","claims":[{"claim":"","verdict":"corroborated/contradicted/unverifiable","evidence":"cmd+数值"}],"forbidden_paths_read":bool,"unknown":""}` | 每题必跑 |
| R2 逻辑审查员 | 只审推理链：题面选项间是否互斥完备（L-0010）、选项是否可从题面反推真值（饱和风险）、推理是否有跳步 | 消费：题面原文；禁读：R1 结论、真值、其他席作答 | `{"role":"logician","qid":"","issues":[{"type":"ambiguity/non_exhaustive/reverse_inferable","detail":""}],"answer":null,"note":""}` | 每题必跑 |
| R3 风险裁判（硬否决） | 只做程序性否决：判据是否可证伪、口径是否唯一、禁读是否违规；**不判断答案对错** | 消费：R1+R2 的**结构化输出原文**（含分歧）；禁读：真值、任何席位答案倾向 | `{"role":"referee","qid":"","veto":bool,"basis":"unfalsifiable/ambiguous_gate/forbidden_read","reason":""}` | 每题必跑（含无分歧题——否决不依赖分歧） |
| R4 独立分析席 | 唯一给答案的席位：基于题面独立作答，与判分/聚合对接 | 消费：题面原文；禁读：R1/R2/R3 输出、真值 | 现有席位 JSON 格式不变（answers + forbidden_paths_read + unknown），保证 aggregate/grade 兼容 | 每题必跑 |

**防同源污染四手段**：① 四套系统提示词差异点写死——R1 只许输出证据、R2 只许输出结构问题、R3 只许输出程序判定、R4 只许输出答案，角色提示词各带"你不评估 X"的负向约束；② 四席各自独立会话、零共享上下文（星型中转：成员间禁直连，主理人只转发**原文**不转述——转述即二次加工，违反 L-0033 精神）；③ P1 阶段 R1–R4 并行独立作答，任何一方在作答完成前不得接收他方输出；④ R3 收到的 R1/R2 输出标注"仅供程序审查、不得据此作答"。

### 4.2 消息流转（P0–P4）

```
P0 口径确认：主理人 → 四席各发同一份题面 + 各自角色提示词（L-0017 两臂同信息条件）
P1 独立作答：R1/R2/R4 并行；各席写席位原件，只写一次（L-0032/33）
P2 交叉比对：主理人取 R1+R2+R4 原件原文比对
   ├─ R1 corroborated 且 R2 无 issue 且与 R4 不冲突 → 直通 P4
   ├─ 有分歧 → 仅分歧题进辩论：主理人将 R1、R2 原文转发 R4
   │   （R4 作答已冻结，辩论只更新 rationale 不改 answer）
   └─ 写盘：辩论记录单独落盘，不改任何原件
P3 过判据门禁：R3 对每题出 veto 判定；veto=true → 本题标记 VOID
P4 汇编：主理人汇总 decision-table.json → 喂 aggregate_seats + paired_compare
```

### 4.3 风险裁判否决判据（预注册，R3 不得事后新增）

| 判据 | 触发条件 | 否决后走向 |
|---|---|---|
| 判据不可证伪 | 题面真值依赖"出题人解释权"或循环论证 | 标 `VOID-basis`，回炉改题 |
| 口径不唯一 | 同一证据链支持 ≥2 个选项（含单位/时点歧义，L-0005） | 标 `VOID-gate`，进 ambiguous 单列 |
| 禁读违规 | 任一席 forbidden_paths_read=true 且证据晚于暴露事件 | 该题按错计；整席丧失独立性则该席整轮作废 |

### 4.4 与现有资产衔接

- 判分：R4 原件经主理人汇编成 seats JSON → aggregate_seats.py（四席输入）→ paired_compare.grade，判分脚本零改动。
- v2 六不变量分工：①②③属题库层；④ pass^k 由编排层对 R4 执行 pass^3；⑤ canary+20% 留出编排层透传；⑥ 协议照抄由编排层保证（L-0017、L-0032/33、禁读边界 v1）。
- 编排层新增保证：角色间上下文隔离 + R4 作答冻结后才可见 R1/R2。

### 4.5 超时与降级

| 阶段 | 建议超时 | 降级路径（均留痕） |
|---|---|---|
| P0/P1 各席 | 10 分钟/席 | 超时记 null（aggregate 天然处理），重试 ≤1 |
| P2 辩论 | 5 分钟/题 | 超时保留 R4 原答案，分歧标记未解决 |
| P3 裁判 | 5 分钟/题 | 超时/失败 → 该题 VOID（主理人裁决，见 §五） |
| 全程 | wall-clock 检查，LLM 步超时即降级不挂起 | 超时事件写 run-log |

### 4.6 独立性局限声明（须写入协议原文）

单模型环境（D-0035）下四角色 = 同一模型的四次不同提示词实例，不构成四个独立意见；L-0019 对四角色同样成立。期望收益只能表述为**审查维度覆盖**（事实/逻辑/程序/作答四类错误各有专职检查）；**不能宣称**：上限抬升（L-0020）、角色多样性等价于模型多样性、四席多数票优于单席。预注册止损：若 pass^3 四角色臂相对单席臂仍无 b≠0/c≠0 不一致对，结论同 v2 验收线——"该素材类亦无区分度"。
