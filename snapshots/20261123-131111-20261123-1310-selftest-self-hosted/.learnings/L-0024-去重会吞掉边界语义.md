# L-0024 · 去重时把专用逻辑换成通用函数，边界语义会静默丢失

- **日期**：2026-10-24
- **发现场景**：`audit/kit/` 的多数票逻辑原本在 `score.py` 与 `item_gate.py` 各写一份，去重时合并成一个函数
- **性质**：跨项目通用（任何"把重复实现抽成公共函数"的重构）★ 升级候选 〔🔁auto-promote-2026-11-22·✅已评估·同族覆盖→「去重换通用函数会静默丢边界语义」〕

## 现象

`item_gate` 原来内联的判定是：

```python
counted = [v for v in votes if v in valid]
if len(counted) > 1:            # 多票 → 走多数制
    per[name] = 1.0 if 多数派 == gold else 0.0
else:                            # ★ 单票 → 直接采用
    per[name] = 1.0 if counted and counted[0] == gold else None
```

去重时我把两处都接到 `score.decide()`，而 `decide` 的语义是**多数制**：

```python
if len(counted) < 2:
    return None                 # 多数制在 1 票上没有意义
```

结果：单席臂（只有一个作答文件，每题只有 1 票）每道题都被判"未成票"。

| | 重构前 | 重构后 |
|---|---|---|
| v3 单席准确率 | **0.500** | **0.000** |

`0.000` 不是崩溃，是一个**看起来正常的成绩**。如果不看数字只看"跑通了"，会直接拿去写报告。

## 根因

公共函数是按"多数派"这个**出现频率最高的场景**设计的，单票路径是某一家调用方的**特例**。
去重时只对齐了"主流语义"，特例语义没地方落脚——它原本靠 `else` 分支存在，合并后 `else` 消失了。

## 判断信号

重构后如果某个调用方的数字发生了**数量级变化**（0.5 → 0.0），先怀疑边界语义丢失，不要先怀疑数据。
数字"整块归零/整块满分"是典型的边界坍塌特征，不是业务波动。

## 做法

1. **抽公共函数时，先把各调用方的边界情形列出来**（空集、单元素、全无效值），逐个确认新函数的行为一致；
2. **边界语义不同就分成两个函数**，不要用一个函数加参数硬兼容。本次最终拆成：
   - `decide()`：纯多数制，<2 票返回 None
   - `resolve()`：单票直接采用，多票转 `decide()`
3. **重构必须配一条断言旧值的回归测试**，且该测试要在重构**之前**写好——否则只能靠肉眼比对输出；
4. 保留历史实现（`score_v2.py` 那份）不删，用**交叉验证测试**钉住两者一致。改一份另一份没改，测试立刻红。

## 附带

这次是**先写测试、再跑变异**才发现可证伪性的：三次故意改坏（严格过半改成含平票、
覆盖率 None 改成 0、段名归并撤销）全部被测试抓到。
第一次跑就全绿的测试不算通过，被改坏时会红的才算。
