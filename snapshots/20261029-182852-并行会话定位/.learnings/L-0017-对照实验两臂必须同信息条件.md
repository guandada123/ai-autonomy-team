# L-0017 · 对照实验的两臂必须同信息条件，否则「输」只是在测信息差

- **日期**：2026-10-24
- **发现场景**：执行 `D-0058` 多席位对照实验（3 席 × 27 题），判定器给出 `c=20 / b=0`、「非劣效不成立」
- **性质**：跨项目通用（实验设计纪律）★ 升级候选

## 现象

判定器输出**完全正常**：`n=27`、单 agent 对 `20`、多席位对 `0`、
差值 `−0.741`、退出码 `1`、自校验（复现冻结的 20/27）通过。

如果只看这段输出，结论是「三个席位不如一个 agent，差 74 个百分点」。

**但这个结论是假的。** 真相：

| 席 | 作答题数 | 作答内容 |
|---|---|---|
| S1 | 0/27 | 全 `null` |
| S2 | 0/27 | 全 `null` |
| S3 | 2/27 | 只有 `T08`、`T09`——**题干自带数据的两道算术题** |

三席唯一能答出的两题，恰好是不需要任何项目知识的两题
（`(90−70.5)/2` 与 `−5.44−(−16.34)`）。这是「信息为零」的指纹，不是「能力不足」的指纹。

## 真实原因

单 agent 基线自己的 `_note` 写着：「不查资料、不看答案，**全部凭本轮会话内的记忆**作出」。
那段会话里它跑过 `make backup`、数过决策文件、跑过覆盖率——**席位没有这段会话**。

于是：

```
c = 单agent对 且 多席位错 = 20 = 单agent对的题数 × 多席位无信息
```

`c` 本该测「三席把对的投成错的」（聚合损失），实际测的是「三席压根没答」（信息差）。
**同一个数字，两种含义，结论相反。**

## 为什么这类坑特别危险

1. **配对设计让人放心**：`D-0058` 已经把「同一批题、同一判分口径」写得很细，
   所以没人会怀疑还剩一个变量——**恰恰是漏掉的那个变量单独就能翻结论**；
2. **判定器不会报错**：它校验的是「单 agent 成绩能否复现」，校验不了「两臂信息是否可比」
   ——**它没有可以对照的第二份真值**；
3. **数字看起来像结论**：`−0.741` 有小数、有判据、有退出码，比「我不知道」可信得多；
4. 它和 `L-0012`（假事实闸门）同族：**呈现假事实，比没有结论更危险**。

## 结论（实验设计纪律）

1. 写对照实验设计时，**「信息条件」必须作为一个显式参数写下来**（谁能查什么、能不能用工具、
   有没有会话记忆），不能默认「大家都是同一个模型所以可比」；
2. **实验组与对照组的差异只允许有一个**（这里是"席位数"）。信息条件、提示词、作答时限、
   判分口径都必须逐项相同；
3. **聚合前先看「有没有票」**：若多数题无有效票，`b/c` 分析不成立，应先报
   「本条件无信息」而不是报「不成立」；
4. **判定器要打印"作答覆盖率"**（本次 0/27），而不是只打印对错统计——
   覆盖率是识别"信息差伪装成能力差"的唯一廉价信号。

## 可迁移到哪里

- A/B 测试：新流程 vs 旧流程，若新流程拿到的是另一份数据，比出来的不是流程优劣；
- 模型对比：一个给 RAG、一个不给，差值测的是检索而不是模型；
- 人机对比：人有时限与工具、模型没有（或反之），同理；
- 任何"评审 vs 单人"的对照：**评审者拿不到被评审者的上下文时，评审必然显得更差**。

## 落地动作（本项目）

- `aggregate_seats.py`：多数票加两道闸（有效票 ≥2 席、过半），防"瞎猜成多数"；
- `paired_compare.py` 的输出已含 `missing` 明细，本轮据此判"无信息"而非"不成立"；
- `questions-v1.md`：题面首次落盘（此前题库只冻结了答案侧）。
