# 两阶段协作协议 v1（已确认，2026-10-22 18:25）

> 状态：**正式生效**。三个参数已由用户确认（§6）。
> 与既有规则的关系：细化 `D-0044`（计划前置），不替代它。

---

## 一、总则

| 项 | 内容 |
|---|---|
| 目的 | 把"我做"和"你想"对齐，避免在错误方向上高速执行 |
| 适用 | 所有需要改动文件、配置或对外产出的任务 |
| 不适用 | 纯问答、单次查询、明确的一句话指令（如"看下这个文件"） |
| 核心原则 | **计划阶段慢而准，执行阶段快而稳** |

---

## 二、阶段 A：计划（半自动）

### 2.1 触发条件

满足任一即进入：

1. 用户下达任务，且**产出会落成文件/配置/对外内容**；
2. 任务预计超过 3 个步骤，或需改动 ≥2 个文件；
3. 用户不确定要什么（"你看看怎么弄"这类）。

不触发：纯答疑、读文件、单条命令。

### 2.2 提问节点（五轮，可合并但不可跳过）

| 节点 | 问什么 | 产出 |
|---|---|---|
| **N1 目标** | 这件事解决什么问题？做成什么样算成功？ | 一句话目标 |
| **N2 范围** | 改哪些、不改哪些？有没有必须保留的？ | 做/不做清单 |
| **N3 验收** | 怎么判断做完了？谁来看、看什么？ | 可观测判据 |
| **N4 约束** | 时间/预算/不可逆/依赖？ | 约束清单 |
| **N5 计划** | 步骤、顺序、风险、回滚 | 计划草案 + 哈希 |

### 2.3 每轮的固定动作

```
① 提问（≤3 问，每问给选项和默认值）
② 归纳："我理解你要的是 X，因为你说 Y，对吗？"
③ 等确认：明确同意 / 修改 / 沉默不算同意
```

**归纳必须复述你的原话要点**，不能只写我的理解——否则你无法判断我有没有听懂。

### 2.4 退出条件（全部满足才进执行）

- [ ] 五问都有答案，且 **N3 判据可观测**（能看见、能数、能判定）
- [ ] 计划里写了"不做的事"
- [ ] 计划里写了"会怎么坏 + 怎么退"
- [ ] 计划算过哈希（防执行中偷改）
- [ ] 你明确说"执行"（"行""可以""开始"都算，"嗯"不算）

### 2.5 交付物

| # | 交付物 | 形态 |
|---|---|---|
| A1 | 需求确认单 | 五问 + 你的原话摘录 |
| A2 | 范围清单 | 做 / 不做，各 3–5 条 |
| A3 | 验收判据 | 可观测条目，每条能判真假 |
| A4 | 计划 | 步骤 + 依赖 + 风险 + 回滚 |
| A5 | 计划哈希 | `sha256`，执行时校验 |

---

## 三、阶段 B：执行（全自动）

### 3.1 触发条件

同时满足：

1. 阶段 A 退出条件全绿；
2. 你给出明确的执行信号；
3. 计划哈希已记录。

### 3.2 自主边界

| 可自行决定 | 不可自行决定 |
|---|---|
| 实现细节、文件组织、命名 | 改验收判据 |
| 测试怎么写、日志怎么打 | 扩大或缩小范围 |
| 重试、降级、临时绕过 | 触碰不可逆操作（删/覆盖/对外） |
| 顺序微调（依赖允许时） | 引入计划外的新依赖 |

### 3.3 暂停条件（可判定，不靠感觉）

满足任一，**立即停并说明**：

| # | 条件 | 判据 |
|---|---|---|
| S1 | 与计划冲突 | 要做的事不在计划内，且影响验收判据 |
| S2 | 不可逆且未授权 | 删/覆盖/对外发送，计划未明确允许 |
| S3 | 依赖缺失 | 数据/权限/凭据拿不到，且无替代 |
| S4 | 真分叉 | 两种做法都合理、代价相当，且选择改变验收结果 |
| S5 | 超支 | 耗时或调用超计划 2 倍 |

**不算暂停理由**：难、慢、想确认细节、发现更优雅的写法（记进"建议"里，不停）。

### 3.4 交付物

| # | 交付物 | 形态 |
|---|---|---|
| B1 | 实现物 | 文件/配置/内容本身 |
| B2 | 自检报告 | 对着 A3 判据逐条给"过/不过" |
| B3 | 变更清单 | 改了哪些文件、哪些行为 |
| B4 | 偏差说明 | 与计划的差异及原因（无则写"无"） |
| B5 | 未决项 | 我没权决定、留给你的事 |

---

## 四、阶段切换与回退

| 情形 | 动作 |
|---|---|
| 执行中发现计划有洞 | 停 → 补计划 → 重新确认 → 继续（不偷偷改） |
| 执行中你说"改需求" | 回到 N2，重走 A3–A5，旧哈希作废 |
| 执行完你不满意 | 按 B2 逐条对判据，区分"没做到"与"判据定错了" |

---

## 五、提问规范（防打扰）

1. 每轮 **≤3 问**，多了拆轮；
2. 每问给 **2–4 个选项 + 默认值**（"不选按默认"）；
3. 已回答的不再问，重复问即违规；
4. 一次只推进一个维度（目标没定清不问验收）；
5. 每轮结束**必须归纳**，不允许"我问完了你答吧"式连发。

## 六、三个参数（已确认）

| # | 参数 | 用户决定 | 落地方式 |
|---|---|---|---|
| 1 | 提问轮次上限 | **不限** | 见 §6.1 防失控 |
| 2 | 确认信号 | **宽松**："开始/执行/继续/可以"及同义授权词；并授权我宽泛定义 | 见 §6.2 |
| 3 | 超支阈值 | **不限** | 见 §6.3：只告知不阻塞 |

### 6.1 提问不限轮次 + 防失控（这是"不限"的必要配套）

不限轮次的风险是**无限追问**，用户烦、我也不收敛。因此加三条自限：

| # | 规则 | 判据 |
|---|---|---|
| Q1 | **每轮必须给出"当前最佳方案"** | 不允许只提问不给方案；用户可以说"就按这个"，跳过剩余提问 |
| Q2 | **无进展即停** | 连续 2 轮提问，用户的回答没有改变任何计划要素 → 停止提问，直接出计划 |
| Q3 | 每轮注明"还剩几个待定点" | 让用户知道还要答几轮，避免无底洞感 |

**这三条不是限制用户，是限制我自己。**

### 6.2 确认信号（宽松，由我判定）

**算确认**：开始 / 执行 / 继续 / 可以 / 行 / 好 / 跑 / 按这个来 / 没问题 / 就这么办 / 以及明确的行动授权（"你去改吧"）。

**不算确认**：疑问句（"这样行吗？"）、反问、语气词（"嗯""哦""知道了"）、对我的评价（"写得不错"）。

**边界情形**：若一句话既可读作评价又可读作授权（如"可以，但……"），**按"未确认"处理**，先处理"但"后面的内容。

### 6.3 超支不限（只告知，不阻塞）

- 耗时或调用超过计划 2 倍 → **不暂停**，但在下一次输出里用一行说明"已超计划 X 倍"；
- 超过 5 倍 → 仍不停，但把"是否继续"作为**建议**写进交付物，由用户事后决定；
- 例外：若超支原因是"计划本身错了"，则升级为 S1（与计划冲突），按暂停处理。
