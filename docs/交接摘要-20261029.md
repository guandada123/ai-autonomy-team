## 6. 项目纪律（踩过的坑，务必遵守）

1. **不要为「加注释」改被 sha256 锚定的产物** → 留痕放旁挂文件（如 `runs/<rn>/integrity-notes.json`）。
2. **round 内 JSON 是 1 空格缩进**，不是 2。用工具默认格式重写会产生数百行无关 diff。
3. **改检查逻辑必须造正样本**（错的 sha、缺失路径）证明它仍会拦。
4. **「已冻结 / 已豁免」不是免检**：`problems` 非空时必须仍报 🔴。
5. **门禁绿 ≠ 全绿**：还要单独跑 `recompute_watch.py` 与 `audit/kit/test_kit.py`。
6. **删文件三原则**：先验证 → 再复制 → 再删源 + 删前确认。
7. **`_trash/` 不是垃圾**：`.gitignore` 第 5 行原文「不要把整个 _trash/ 当成可重建的垃圾：删了归档，历史时点就没了」。
8. **改包内文件后的固定联动**：重建 MANIFEST → 跑门禁（A 项会报交接文档字节数过期）→ 同步当前值 → 复跑。
9. **收尾前必须重新核实状态**，不能复用上一次会话的结论（10-29 收尾时差点用 10-27 的「四项全绿」，实际已变 10 个提交）。
10. **不要代提交别人进行中的工作**；判断依据：`git status` 有未提交改动 + 文件 mtime 是几分钟前 + 自测未全过。
11. **双写互斥（10-29 新增，同日实测补强）**：并行会话动手前先 `make sync`（pull --rebase --autostash + 回读 HEAD==origin/main），提交推送后再次回读；动仓库前先 `ps`/`lsof` 确认没有其他活跃会话在写同一仓库。**`make sync` 只保「拉得下来」，不保「改动归你」**——同日实测：改动挂在工作树里约一小时未提交，被并行会话收尾时一个 `git add -A` 整体捎走（内容完整、署名丢失，靠 `git log --name-status` 才追回）。故一批改动做完就提交，别长时间留未提交状态；发现工作树莫名变干净时，先 `git log -3` 查是不是被别人提交了，别急着重做。
12. **正文不写裸计数 + 诊断输出先脱敏（10-29 新增）**：交接摘要正文禁止裸易变计数（门禁 G 类拦；带时点「10-29 22:36 实测」或指向文末生成块才放行）；贴 `ps`/`lsof`/`env` 前先过 `scripts/mask_secrets.py`（L-0038：命令行里常躺着 Bearer token）。
13. **判断副本冗余按物理卷取证（10-29 新增，L-0039）**：`~/.workbuddy`、`~/WorkBuddy` 都是指向外置盘的软链，`~/Backups` 却在内置盘——"路径都在 ~ 下"≠"同盘"。评估同盘/异地/冗余必须 `df <每路径>` 比 Filesystem 设备号 + `readlink` 拆软链，绝不凭路径前缀直觉。MEMORY 含半敏感信息，只做本地跨盘备份（`make_backup.py --memory-only`），**绝不进 git、绝不上云**。
