## 一、版本号语义（重要，易误解）

`contract_version` **随轮次，不随工具**。`seat_check` 读取的是**该轮** `round-manifest.json` 里的版本，不是 `config/params.json` 里的全局值。

- `config/params.json` 的 `contract_version: "3.0"` 只是**新建轮次的默认值**；
- 历史 33 轮的 manifest 保持原值（`1.0` / `2.1`），不受影响；
- `metrics.py` 的基线版本读的是 `prev_dir/round-manifest.json`，**不读** `params.json`，故历史指标不被污染。

设计理由（v2.1 既有注释）：若用全局版本，重跑 `runs/round2` 会把它的 4/4 合规打成 0/4，摧毁「round2 可作第 3 轮合规基线」这一核心结论。

## 二、六项口径变更

| # | 变更 | 机器表现 | 回溯影响 |
|---|---|---|---|
| ① | 新增 `summary.fee_diff_total` | `MONEY_PATHS` 成员，需 `decimal_equals` + scale=2 | 无（历史 answer 已补字段） |
| ② | `excluded_amount_total` / `fee_diff_total` / `dedup_amount` 必须非负 | `E_MONEY_NEGATIVE` → **无条件 fail** | 无（**94 次有值读数**，负值 0 次；33×4=132 个席位-轮中 38 个无该字段） |
| ③ | 金额字段必须是 JSON number | `W_MONEY_STRING`；`--strict-money-type` 下转 fail | 无（仅告警，历史 5 轮不回溯改判） |
| ④ | `excluded_categories` 封闭枚举 + 空值需说明 | `W_CATEGORY_NOT_ENUM`；`present_or_note` | 无（历史 **45 种**写法仅告警） |
| ⑤ | 日期比对基准写死 `trade_date` | `truth.rules.date_basis` 声明 | 无（口径声明，不改数值） |
| ⑥ | 判据总数 13 → **14** | 算术 10 + 判断物化 4 | 历史 verdict 保持 13/13 |

### ① 为什么必须新增 `fee_diff_total`

费用差在 v2.x 的 summary 六字段中**无落点**（`amount_diff_total`/`excluded_amount_total` 都定义在 `amount` 列差上，费用属 `fee_total` 列）。旧实现把它塞进 `excluded_amount_total`，违反 TASK.md「费用不并入金额」易错点 1；D-0016 用「两选项 implies 同值」规避，代价是 **9/20 任务的 ADJ-001 变成中性轴**——机器无法反推立场，人闸门签字失去可验证性。

v3.0 给它独立落点后，两选项恢复可辨：

| 选项 | amount_diff_total | excluded_amount_total | fee_diff_total |
|---|---|---|---|
| `count` | `amount_gap` | `0.0` | **`fee_gap`** |
| `exclude` | `amount_gap` | `0.0` | **`0.0`** |

**闭合恒等式不变**：`amount_diff_total + excluded_amount_total == raw_total_gap`。`fee_diff_total` 是第三维，不参与该式。

## 三、兼容性

- 历史 33 轮的 verdict 文件**不改写**，仍为 v2.1 基线（13/13）；

### 交叉使用限制

**v3.0 前后的 spec 不可交叉使用。** 引用历史 verdict 时须同时标注其 spec 版本，否则 13/14 的差异会被误读为失败。

### 需要动作的迁移

若已有 v2.x 的 answer 需要跑 v3.0 判据，必须先补 `summary.fee_diff_total`（值 = 该任务的 fee 列差合计，含单侧缺失单整笔费用）。本次已为 26 份历史 answer 补齐。

## 六、已知操作陷阱

**`regress.py:853` 会调用生成器重新生成整个 `fixtures/tasks/`。**

任何直接手改夹具的动作都会被下一次回归覆盖——本次 T-09 的试点改动就是这样丢的（而 T-04 因在回归之后改所以保留，形成「部分生效」的假象）。

**规则**：夹具改动必须落 `make_tasks_20.py` 生成器，不能手改包内文件。

**次级陷阱**：改 `scripts/judges/verify.py` 真源后，必须先 `build_package.py --apply` 同步到包内，否则跑的是包内副本，会报「未知检查类型」等假错误。
