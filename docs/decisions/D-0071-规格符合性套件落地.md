# D-0071 规格符合性套件落地：把"判据对吗"换成"实现符合规格吗 + 盲区在哪"

**日期**：2026-10-26
**前置**：D-0070（原校准集标签与分组同构，F1=1.00 无区分力）+ L-0030（盲标路线被封）
**产物**：`audit/probes/premise/spec-cases.json`（20 张）+ `scripts/spec_conformance.py`

## 一、为什么不再叫"校准集"

原校准集要证明的是"判据抓住了语义"，但它需要**独立真值**，而本项目拿不到：

- 用户盲标 → 被封（设计者复述必然污染，同卡翻转 4/4，L-0030）；
- 我自己标 → 不是独立第三方，且实测有 **15% 手推错误率**（见四）。

所以改为**规格符合性**（spec-conformance）：期望值由**三条规则文本**推导，
检验**实现是否符合规格**。它能抓实现回归，**不能**证明规格正确——这一点写死在套件 README 里。

## 二、套件设计（针对 D-0070 的三个缺陷逐条反制）

| D-0070 缺陷 | 本套件的反制 |
|---|---|
| 标签与卡号前缀同构 | **id 打散**：`C01–C20`，正负例随机交错；`spec` 正类比例 45% |
| 缺"短但具体/长但空泛"样本 | 显式加入：`老张`、`王工`（2 字人名）、`我们团队自己用的那套报表工具`（去泛称后 8 字仍空泛） |
| 边界只靠 1–2 张卡撑着 | 显式放入**一字之差对偶**：`团队发布值班`（去词 4 字→拦）vs `团队发布值班人`（5 字→过） |

## 三、三层比对与结果

| 比对 | 含义 | 本次结果 |
|---|---|---|
| `actual` vs `spec` | 实现是否符合规格 | ✅ **20/20 一致**（exit 0） |
| `actual` vs `semantic` | 规则与"不带规则知识的评审者"是否一致 | ⚠️ **5 张不一致**（= 盲区清单） |
| 元信息基线 | id 奇偶 / 前半 → 拦 | F1 = **0.42 / 0.53**（原集为 1.00）→ 命名已打散 |

## 四、顺带测出：手工推导期望值的错误率 = 15%

首轮比对报"实现与规格不符 2 张"，逐张核查后发现**是我手推 spec 标错**（C01「系统」、
C06「团队发布值班」按规则明明该判拦）；另有 1 张（C16）我写的 semantic 与我自己写的说明自相矛盾。

**3/20 = 15%，且三处都不会报错**——只有做了三层比对才暴露。
含义：**"人工逐条推期望值"不能作为可信真源**，哪怕规则是纯机械的。
这同时解释了为什么原校准集的组标签能长期存在而无人质疑：错误是静默的。

## 五、盲区清单（本套件的真正产出）

规则与语义不一致 5 张，收敛为三类：

| 类型 | 卡 | 规则 | 语义 | 成因 |
|---|---|---|---|---|
| **误报·短但具体** | C05 王工、C15 老张 | 拦 | 过 | P-01 长度阈值把 2 字人名当泛称 |
| **漏报·键齐但内容空** | C09（method=「看情况」、后果=「可能出问题」） | 过 | 拦 | P-02/P-03 只查键在不在，不查值是否有信息量 |
| **漏报·长但空泛** | C11（去掉「我们/团队/自己」后剩 8 字，语义仍是自用） | 过 | 拦 | P-01 是"删除黑名单词后数长度"，长句能靠堆字过关 |
| **漏报·基线荒谬** | C03（指标「发布耗时」，基线 0） | 过 | 拦 | P-02 不检查基线是否与指标量纲相容 |

## 六、结论与处置

1. **不再追求"证明 P-01 的 5 是对的"。** 它是一个**代理指标**，盲区已具名、可枚举，
   这比一个虚高的 F1 有用。P-01 的 `_note` 已按 D-0070 加更正段。
2. **三类漏报属规格的有意取舍**（机械可判 vs 语义切题），不修；
   但必须在探针文档里写明：**P-02/P-03 通过 ≠ 指标合格**。
3. **误报类（人名）可以考虑修补**，代价最小：P-01 增加"若剩余串是 2–4 字且不含泛称字符，
   则要求同时满足 P-02 与 P-03 全合规才放行"——但这需要新样本验证，不在本轮做。
4. **本套件纳入日常**：`make spec-check`；任何改 P-01/P-02/P-03 的行为，先跑它。
5. **不把它接进 `regress.py`**：regress 是包内夹具套件（55 项），本套件是仓库侧规格检查，
   混进去会让"包内幂等"守门项的含义变模糊。

## 七、接下来若要真提升判据质量（成本高，需另行决策）

唯一能突破"代理指标"局限的路，是给每条盲区补**单卡真人裁定**：
一次只问一张、给全三字段、不解释、不评价、同一张不超过一次。
L-0030 已经证明"逐张口头复述"会污染，所以必须**直接给原始 JSON 字段**，不经任何中介。
这条路可行，但每次只解决一张卡，36 张就是 36 次——**值不值得，应由需求方决定**。
