# D-0045 · 整库推到**私有**远端（仓库权限必须 private）

- **日期**：2026-10-23 19:05（19:00 首版误记为「只在本地」，据用户澄清修正）
- **决策者**：用户（原话「上传 GIT 但本仓 GIT 权限私有」）
- **操作分级**：🟠 高（对外部系统产生可见影响，且「私有」一旦配错不可完全撤回）
- **状态**：生效

> 📌 修正记录：19:00 版把「整库私有」理解成「不配远端，只在本地」，据此写的
> 「不配公开远端」与备份方案一并作废。真实意图是**推上去，但仓库是 private**。

## 决定

**整库推到私有远端。三条不可动摇：**

1. **推全库**：`real-runs/` `snapshots/` `audit/` `docs/` 一并推，不裁剪、不脱敏、
   不做「公开版/私有版」双轨（双轨必然分叉，本项目已因多副本踩过四次）；
2. **权限必须是 `private`**：创建时显式指定，创建后**回读 `visibility` 确认**——
   这是全流程唯一不可出错的一步；
3. `scripts/redact_report.py` 仍是按需工具：只有把**某一份**报告发给第三方时才用，
   不是发版必经步骤。

托管方：GitHub（`guandada123`，与 `Claw` 同账号）。

## 为什么

| 理由 | 依据 |
|---|---|
| 库里含真实账户信息，不能公开 | 实测：A 股代码形状六位数命中 18 个非快照文件，绝对路径 28 个；`real-runs/` 含券商名与账户金额 |
| 但需要一个**异地副本** | 仓库原在外置盘，盘坏即全丢；远端天然解决异地问题 |
| 脱敏会毁掉证据价值 | `real-runs/` 的意义是「真实账本对过账」；换成「标的A」后无法复核，只剩结论 |
| 私有仓库足够 | 使用场景只有本人；私有权限下托管方可见，但不对外公开 |

## 明确不做的事

- ❌ 不建 public 仓库，也不「先 public 试试再改私有」——见风险第 1 条；
- ❌ 不删 `snapshots/`「降低暴露」——**删副本不降暴露**：它们是 `docs/` 与 `scripts/`
  的副本，正本仍在库里。暴露面 = 内容 × 可达性，副本数量是假指标（见 ARCHITECTURE §八）；
- ❌ 不做「公开/私有」双轨构建（两份 MANIFEST 必然分叉）。

## 机制：推之前跑什么（2026-10-23 落地）

口头流程会被忘，所以绑成一条命令 —— `make pre-push`（`scripts/pre_push_scan.py`）：

| 步 | 做什么 | 失败时 |
|---|---|---|
| 1 | **检测器自检**：每个模式必须命中自己的正样本；缺样本即拒扫 | rc=2，不扫描 |
| 2 | **历史扫描**：全部可达 blob（不是只看工作区） | rc=1，列出文件+模式 |
| 3 | **远端权限**：`gh repo view` 回读必须 `PRIVATE` | rc=1；离线时只告警不拦截 |

装上钩子后每次 `git push` 自动跑：`make hooks`（写 `.git/hooks/pre-push`）。

**可证伪性**（2026-10-23 实测）：
- 在临时副本里造一个 `ghp_…` 提交 → 脚本 rc=1，指名 `leak-test.txt`；
- 装 hook 后再 `git push` 到本地裸库 → **推送被拒（exit 1）**，输出同上。

⚠️ **钩子是本地文件，不入库**：换机 clone 后必须重跑 `make hooks`，
否则这条防线不存在，而 `make pre-push` 也只在人记得跑时才有用。

## 本地备份（与远端互补，不是替代）

**已固化成一条命令**：`make backup`（`scripts/make_backup.py`）。

| 产物 | 内容 | 每份都验证 |
|---|---|---|
| `*.bundle` | 全部 git 历史 | `clone` 到临时目录，比对 HEAD / 提交数 / 受控文件数 |
| `snapshots-archive-*.tar.gz` | `_trash/snapshots-archive/`（gitignore，远端不含） | 条目数 == 源文件数；抽 1 个文件比 sha256 |

工具本身也是可证伪的：`--self-test` 会造一个**完好** bundle（应通过）、一个**坏**文件
（应被拒）、一个**期望值错一位**的比对（应被拒）、一个条目数不对的 tar（应被拒），
4 项全过才说明「验证逻辑真的在验」，而不是恒真。

刻意不做的两件事：**不自动删旧备份**（备份工具删东西是自毁倾向，`--list` 只报告）、
**不加密**（口令管理是人的决定；产物在内盘是明文，只防盘坏不防窃取）。

2026-10-23 19:25 实测：bundle 2.2 MB（18 提交 / 1587 文件）、tar 26.4 MB（6852 文件），
两份均通过还原验证。

**周期化**（2026-10-23 补）：已登记一条自动化「ai-autonomy-team 月度备份」，
每月 1 日 20:00 执行 `scripts/make_backup.py`，判据是 exit 0 且两份产物都过还原验证；
失败时如实报告、不修复、**不删任何旧备份**；总占用超 500MB 只提示不清理。

> 自动化只在「本机 + 外置盘已挂载」时有意义。盘没挂载时它应报「跳过」而不是
> 去别的路径找 —— 这条写进了自动化提示词，因为「找不到就换个地方找」正是
> 让备份悄悄写到错误磁盘的经典路径。

## 风险（按严重度）

| # | 风险 | 处置 |
|---|---|---|
| 1 | **误设成 public**。一旦推上去，被克隆 / fork / 爬取的部分**收不回来**，改回 private 也无效 | 创建时 `--private`；创建后回读 `visibility`；**推之前**先做密钥扫描 |
| 2 | 推出去的含真实券商 / 金额，托管在第三方 | 接受（私有权限下仅本人与平台可见）；不因此裁剪内容 |
| 3 | `_trash/` 被 gitignore → 远端**不覆盖**历史快照归档（体量随快照增长，`make backup --list` 可查） | 保留本地 tar 备份（见上） |
| 4 | 远端是「一个副本」，但**不等于备份**：误删 / 强推仍会丢 | 保留本地 bundle；关键改动后打快照 |

### 推之前的密钥扫描（2026-10-23 实测）

- 范围：**全部可达历史的 1530 个 blob**，不只看工作区（推上去的数据会离开本机）；
- 结果：0 命中；
- 该结论可证伪：先拿正样本击破检测器 —— 原 8 条模式**连 `ghp_` 都认不出**
  （GitHub PAT 完全盲区）。补 GitHub classic / fine-grained、GitLab、Slack、
  腾讯云 `AKID`、阿里云 `LTAI` 六类前缀后，正样本全部命中、负样本（commit sha、
  `token 用量 126100`）全部不命中，再重扫得 0。

## 验收（2026-10-23 19:10 实测，全过）

| 项 | 判据 | 实测 |
|---|---|---|
| 权限 | `visibility` 回读为 PRIVATE | `{"isPrivate":true,"visibility":"PRIVATE"}` |
| 远端一致 | `origin/main` == 本地 HEAD | `c677e5d` == `c677e5d` |
| 规模 | 提交数 / 受控文件数一致 | 15 / 1583，两侧相同 |
| 忽略项 | `_trash` `_archive` `.workbuddy` 不得出现 | 三项均「未推」 |

最后一行是 L-0009 那条教训的检验点：**光「推上去了」不算完成，新机器只拿到这个
仓库也得能跑**。克隆副本里没有任何本机残留（无 `_trash`、无 `.workbuddy`），
而冻结基线、`migration-package/config/`、`snapshots/` 都在库内，所以能跑通。
