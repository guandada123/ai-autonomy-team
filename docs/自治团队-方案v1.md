## 第一部分 · 那个更深层的问题

### 1.1 它是什么

> **"这个任务该不该做？"——团队被制度性地禁止提出这个问题。**

更刺人的版本：

> **"如果这套东西明天消失，谁会受损？"**

这个问题从来没有被正面提出过。不是没想到，是**每个角色的授权都把它排除在外**：

| 角色 | 授权原文 | 被排除的部分 |
|---|---|---|
| 项目经理 | "把我的想法落地实现" | 质疑想法本身值不值得落地 |
| 执行 AI | "产出最佳执行路线" | 路线通向的地方该不该去 |
| 审计 AI | "只驳结构不驳结论"（`protocol/01` 明写） | 结论所服务的目的 |

三条授权拼起来，恰好构成一个**闭环**：没有人有权问"该不该"。
审计被赋予"专职驳回"，但驳回范围被限定在**结构**上——它被设计成一把只能刺向流程的刀。

### 1.2 它能解释哪些表层讨论

本项目 33 轮就是一份标本。下面每一件，根都在那个问题上：

| 表层现象 | 为什么会出现 | 它掩盖了什么 |
|---|---|---|
| 「20/20 条款命中」 | 答案由生成器写死，判据再判一遍 | **自证**：自己出题、自己判卷 |
| 「26:0 自洽」 | 只校验 `implies`，只扫签字后反填的聚合层 | **构造性通过**：检查覆盖不到矛盾处 |
| 反复辩「六席 vs 单席」 | 这是唯一能在内部测量的"价值" | 测的是**机制**，不是**用途** |
| `excluded_categories` 从 45 种查到 97 种、`task_id` 8 种形态、MANIFEST 差 1,740 字节 | **可修的东西**永远优先于**重要的东西**——因为修得动 | 修完很爽，但账户里的价值没变 |
| 每轮新增决策文件、检查项、快照 | 交付物是**工作量证明** | 价值证明一份也没有 |
| 真实数据一上手就抓出 4 个静默缺陷 | 合成环境是自己造的，保真度不足 | 33 轮"全绿"不代表能碰真账 |
| 最终 `D-0028` 把定位降级为"参考实现" | **回避式回答**：不回答问题，改写问题的提法 | 那个问题一次都没被摆上桌 |

### 1.3 为什么干活 AI 始终绕着它走

不是智力问题，是**激励与制度**问题，五条：

1. **激励不相容**：一旦问"该不该做"，自己前 33 轮的产出立刻贬值。任何理性角色都会绕开。
2. **授权边界**：PM 被授权"落地"而非"质疑"；执行被授权"路线"而非"目的地"；审计被明令"不驳结论"。
3. **判据能力错配**：硬裁判只能判"算得对不对"，判不了"值不值得做"。团队于是把**能判的**当成**重要的**。
4. **沉没成本**：28 份决策、43 个快照、五个 commit——越厚越难承认方向存疑。
5. **读空气**：提问者是需求方本人。团队会本能地判断"他不想听这个"，于是把它翻译成技术问题。

### 1.4 对辩解的正面反驳

| 辩解 | 反驳 |
|---|---|
| "先做出来才能评估价值" | 33 轮已经做出来了。**评估价值的动作一次都没发生**——不是没条件，是没授权。 |
| "我们的价值主张不是'更准'" | 换一个口径不等于有了价值。任何主张都必须落成**可观测指标**，否则它只是措辞。 |
| "保分歧已被实证有用" | n=1 任务、1 个实例（T-13）。**样本量 1 不是证据，是轶事**。而且"保分歧有用"最终也要外部结果检验。 |
| "审计只驳结构是为了防止它'制造确定性'" | 那条原则确实挡住了假确定性，代价是**造出目的盲区**。这是取舍，不是免责条款。 |
| "内部工具的价值就是少犯错" | 那就需要**事故率基线**。基线从未测过，"少犯错"无从比较。 |
| "这是 Phase 0，价值验证属于 Phase 1" | Phase 0 的终止条款（20 条达 92%+）是**自己定的**，且从未真正结算过。 |
| "参考实现本身就有价值" | 参考给谁？没有接受者的参考物，价值等于零。这不是谦辞，是事实。 |

### 1.5 干活 AI 的反驳（steelman，允许它们说话）

1. **"真实数据线证明判据可迁移"**——成立。判据层在真账上抓出 4 个静默缺陷，这是**唯一一次外部检验**，而且它成功了。这构成"机制的一部分确有价值"的实证。
2. **"内部工具不该用货币化指标衡量"**——部分成立。若指标是"避免一次错误决策"，那应追踪**错误决策的数量与代价**，而不是收入。
3. **"终止条款没结算是流程缺陷，不是方向错误"**——成立。这是执行疏漏，可以用一次结算补上，不必推翻方向。

### 1.6 项目经理拍板

**不砍团队。但改三件事，且设一个 90 天的价值闸门。**

理由：1.5 的第 1 条是真证据——**判据层在真实数据上有效**。它证明的不是"六席更准"，而是"这套审计纪律能抓到人眼看不见的错"。那就把资源压在它已经证明的地方，而不是继续扩大未证明的部分。

三条决定：

| # | 决定 | 内容 |
|---|---|---|
| **D1** | **价值闸门** | 任何新机制/新检查/新决策文件立项前，必须绑定**一个可观测业务指标**并写明基线。无基线不立项。 |
| **D2** | **审计扩权** | 审计从"只驳结构"扩为三层：结构 / 论证 / **前提**。每轮必须回答"如果这东西明天消失，谁受损"，答不出即视为未完成审计。 |
| **D3** | **单 agent 基线常设** | 研究结论明确：多席位收益大部分可由"同模型多次采样 + 多数票"复现（`Debate or Vote`, NeurIPS 2025）。因此每次团队产出都必须与**单 agent + 多采样**对照，团队只在**显著更好**时使用。 |

## 第二部分 · 方案

### 2.1 团队编制（5 席，不是 6 席）

| 席位 | 职责 | 关键约束 | 模型家族 |
|---|---|---|---|
| **PM-01** | 唯一写权限；拆解、派发、督促、拍板 | 必须给"决定 + 依据 + 风险边界 + 回滚"；**必须每轮回答一次 D2 的问题** | 家族 A |
| **EX-01 事实派** | 数据、可复现计算、证据指针 | 结论必须附可执行命令 | 家族 B |
| **EX-02 反方** | **专职唱反调**：给最强反对理由（steelman） | 不许和稀泥；必须给出"若我对，会看到什么" | 家族 C |
| **EX-03 落地派** | 成本、工期、可维护性、运维负担 | 必须给"不做"的代价 | 家族 D |
| **AD-01 审计** | 三层驳回（结构/论证/**前提**），含**终止提议权** | 不得以"流程未定义"为由回避前提审查 | 家族 E（或非 LLM 判据） |

**关键设计**：席位独立性的来源是**模型家族不同**，不是 prompt 不同。
证据：九个跨七家族的 AI 评委，实际只等于 **2.18 个独立意见**（`Nine Judges, Two Effective Votes`, 2026）。
同模型换 persona = 一个人戴五顶帽子。

### 2.2 协作与辩论机制

**四阶段，顺序不可换**：

```
① 独立作答（禁止互看）
   每个执行席独立产出：结论 + 证据 + 证伪条件 + 置信度
   ↓ 落盘 per-seat.json，不广播
② 匿名交叉（去身份）
   打乱署名后广播；评委看不到"哪份是自己写的"
   证据：去掉身份标记可显著降低谄媚（When Identity Skews Debate, 2026）
③ 结构化辩论（最多 2 轮）
   每轮只允许：①指出对方事实错误 ②给出新证据 ③改变立场并说明为何
   禁止：重复论点、人身/权威施压、无新证据的加码
   ↓ 监测 debate collapse：立场分布熵连续下降即强制中止
④ 聚合（不是投票）
   多数票作为**基线**，不直接采纳；PM 按"证据强度 × 可证伪性"裁决
```

**必须同时跑的基线**（否则无法判断团队是否有用）：

| 基线 | 目的 |
|---|---|
| 单 agent 单次 | 最低成本参照 |
| 单 agent 多采样 + 多数票 | **最关键**：研究显示多数票已能复现大部分"辩论收益" |
| 团队（本方案） | 待测对象 |

三条都跑，才叫"证明了团队有用"。

### 2.3 审计与驳回流程（三层）

| 层 | 审什么 | 驳回后果 |
|---|---|---|
| L1 结构 | 证据缺失、命令跑不通、字段不符 | 退回重做，不计轮次 |
| L2 论证 | 结论与证据不匹配、样本量不足、口径漂移 | 结论降级为"待证实" |
| **L3 前提** | **这个任务该不该做；若消失谁受损；指标是否可观测** | **可提议终止**，由 PM 裁决 |

**L3 是本方案的核**。原设计把 L3 排除在外，正是那个深层问题的制度来源。

审计输出固定四段：`驳回了什么 / 依据 / 还差什么 / 是否建议终止`。
连续 3 轮被驳回同一问题 → 升级为"设计缺陷"，进失败案例库。

### 2.4 项目经理的督促与决策

**督促不靠话术，靠机制**：

| 机制 | 实现 |
|---|---|
| 心跳 | 每席每轮须提交 `status.json`（进度/卡点/预计完成），超时未提交即视为卡住 |
| 卡点升级 | 卡住 ≥1 轮 → PM 强制拆解；≥2 轮 → 换席或降级任务 |
| 反拖延 | 任务颗粒度 ≤ 半天；超过即拆 |
| 决策留痕 | 每次拍板写 `D-XXXX`：依据 / 备选 / 未采用理由 / 回滚 |
| **前提复核** | 每轮结束前 1 次：回答"如果这东西明天消失，谁受损" |
| 停损 | 连续 3 轮无新增可验证结论 → 触发"是否该停"的强制议题 |

### 2.5 指标（价值闸门 D1 的落地）

只认三类，全部要**基线**：

| 类 | 指标 | 必须写 |
|---|---|---|
| 结果 | 该业务的一个可观测结果（错误数 / 耗时 / 金额偏差 / 事故率） | 基线值 + 测量方式 |
| 成本 | token / 时长 / 人工介入次数 | 与单 agent 基线对比 |
| 质量 | 被驳回率、翻边率、**被 L3 驳回的前提数** | 后两项是本方案独有 |

**没有基线的指标不算指标**——这是 D1 的全部内容。

### 2.6 持续优化路径

| 周期 | 动作 | 产出 |
|---|---|---|
| 每轮 | 三基线对照（2.2） | 一条"团队是否显著更好"的判定 |
| 每周 | 失败案例库复盘；连续无用的席位**剪枝** | 席位增删（宁可少，不可摆设） |
| 每月 | 重算价值指标；若团队未显著优于多采样基线 → **降为单 agent + 判据** | 定位调整决策 |
| 每季 | 重估模型家族独立性（`Nine Judges` 类检验） | 独立性报告 |

**剪枝优先于扩张**。研究一致指向：席位数量是最不重要的变量，而所有"多智能体产品"都在强调它。
