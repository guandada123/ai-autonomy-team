## 1. 现状评估

### 1.1 架构合理性

**成立、不要动**：
- 四阶段顺序（独立作答 → 匿名交叉 → 结构化辩论 → 聚合）符合减弱谄媚的实证；
- 「独立性来自模型家族而非 prompt」判断正确；
- 三层审计把**前提**单列，是全案唯一真正的新东西，也是原设计最大的制度盲区。

**不成立**：

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| A1 | 删掉 JD-01，第 ④ 步改由 PM 凭「证据强度×可证伪性」裁决 | `01:24-35` 七主体；`params.seat_contract` 6 席；`07:319` 六席流程 | 算术层失去非 LLM 终审，回到 LLM 判 LLM |
| A2 | PM 四权合一（写权限 + 拍板 + 前提复核 + 终止裁决） | 方案 §2.1/§2.3/§2.4 | 与 `01:16` 引用的 MAST 结论正相反：验证者继承了它要检查的失效模式 |
| A3 | 审计扩权含「结论降级为待证实」＝驳结论 | `params.audit.ad01_can_reject_conclusions=false`；`01:72` | 脚本按枚举校验判非法，或配置被静默架空 |
| A4 | 家族 A–E（5 个）不可满足，实测仅 2 个 | `04:160-167`；`D-0012` 记 round4 六席全落 `glm-5.3-flash` | 「五席五族」是纸面条件，且无降级路径 |
| A5 | 「显著更好」不可判定 | 方案 §1.6/§2.6 | D3、月度降级、剪枝全部无法执行 |
| A6 | 多数票双重标准：任务内禁用多数（`01:18`/`01:47`），架构存废却用多数基线裁决 | 方案 §2.2 基线表 | 元层级自相矛盾 |
| A7 | 两套体系不互认：5 个落地件仓库内均无实现；`metrics.py`/`seat_check.py`/`verify.py`/`inspect_agent_routing.py` 零引用 | 全案 `scripts/` 引用 0 次 | 落地＝重建，且与 33 轮数据不可比 |
| A8 | 「全自动」预期与平台能力冲突 | `07:13-16`：子代理只能由主会话发起，任何声称全自动多轮编排都是假的 | PM「督促」只能是生成提示词＋记账 |

### 1.2 关键流程断点

| 流程 | 方案表述 | 断在哪 |
|---|---|---|
| 独立作答 | 「禁止互看」 | 无落盘位置、无写入者、无「是否真独立」检测 |
| 匿名交叉 | 「打乱署名」 | 未说明删署名还是删文风；`07:255-257` 指出匿名删不掉指纹 |
| 结构化辩论 | 「最多 2 轮」+「collapse 强制中止」 | 与 `params.debate.max_rounds=3` 冲突；「连续下降」未定义（几轮/斜率/阈值） |
| 聚合 | 「PM 按证据强度×可证伪性」 | 两因子无量纲、无合成规则、无阈值 → 实为自由裁量 |
| 三层审计 | L1/L2/L3 | L2 落进「无裁判区」（`04:88` 硬裁判只对算术层有否决权）；L3 由**被审对象 PM** 裁决，且无申诉 |
| PM 督促 | 心跳 `status.json`／卡点升级／任务≤半天 | `07 §2` 无 `status.json` 约定；「卡住」无状态枚举；「半天」无字段 |
| 停损 | 连续 3 轮无新增结论 | 与 `params` 空转阈值 2 冲突；`07:52` 明确警告「第 2 轮会被自己的终止条件杀掉」 |

### 1.3 风险与薄弱环节

| 类 | 风险 | 量级 |
|---|---|---|
| 成本 | 三基线使每轮调用 ≈ 6+n×2；现有 87 条自动化已按 15,500 积分线性预估 | **会击穿**；且平台只有会话级 credit，无法按席位分账 |
| 并发 | Claw `check_schedule` 是「日内一次」语义，5 席每轮多次调用会互相屏蔽 | 一开跑就自锁 |
| 权限 | 只有「PM 唯一写权限」一句；读域（`read_domains.json`+第 9 查）完全未提 | 读域越界不可见 |
| 数据 | 5 个落地件只有名字，无 schema／路径／校验 | 无法进回归，无法复核 |
| 可复现 | 未附 sha256 / evidence pointer / `reads[]` | 结论不可回读 |
| 告警 | 群 `oc_9ee5…` 已被 29 项巡检 + 87 自动化共用 | 席位每轮推卡会淹没既有告警 |

## 2. 修复意见（按优先级）

### P0 · 不修不能落地

| # | 问题 | 影响 | 改进方向 | 可选替代 | 验收 |
|---|---|---|---|---|---|
| P0-1 | PM 四权合一（A2） | 裁决失去独立性，方案自我否定 | **恢复 JD-01**：算术层仍由非 LLM 终审；PM 只裁「证据强度」与路线，不碰数字 | 若坚持无 JD-01，必须引入**外部人类闸门**做算术终审（更贵） | 第 8/9 查 + `verify.py` 在链路上；PM 不能改写 verdict |
| P0-2 | 审计权限冲突（A3） | 代码与文档必有一方静默失效 | **改配置不改协议**：新增 `ad01_can_reject_conclusions_scope: "argument_only"`，L2 只驳「结论与证据不匹配」，不驳「结论对错」 | 把 L2 交给人类闸门 | `params.json` 与 `01` 一致；`verify` 枚举通过 |
| P0-3 | 5 席 vs 6 席（A1） | 历史 33 轮不可比 | **保留 6 席**，只把 AD-01 的审计范围扩为三层；「反方」沿用 `02:63` 既有 EX-02，不新设 | 若减为 5 席，须写决策修订 `01:24-35` 并重跑基线 | 席位数与 `seat_contract` 一致；决策文件存在 |
| P0-4 | 「显著更好」不可判定（A5） | 价值开关形同虚设 | 定义为**配对比较**：同任务集 n≥20、同预算上限、盲评判分；判据 = 相对「多采样多数票」胜率 ≥60% 且 95% CI 下界 >50% | 样本不足时降级为「不劣于」（非劣效，margin 5pp） | 预注册效应量 + 判定脚本 |
| P0-5 | 家族不可满足（A4） | 独立性是纸面条件 | 家族表改**实配**：当前 2 家族；不足 3 时**强制降级**为「单 agent 多采样 + 判据」，不假装五人五族 | 引入第三家族（成本增） | 开轮前 `inspect_agent_routing.py --json` 硬门；折扣写入 `independence_discount` |

### 3.1 适用条件（六条硬前置，缺一不可）

### 3.3 逐仓评估

**StockInsight —— 首选**
- 能接：门槛硬、失败即红，天然适合「团队 vs 单 agent」对照；前端 24 个组件测试 + e2e 提供可判定通过率。
- 要改：补 CONTRIBUTING 与 ADR（现 1 篇）；隔离根目录一次性脚本（`backfill_history.py` 等），否则评审面被噪声污染。
- 工作量：**1.5–2 人日**（接入 + 一轮对照）。
- 风险：覆盖率 86 已很高，团队「更好」的空间小——这恰是好事，容易证伪。

**QuantTradingSystem —— 第二站**
- 能接：已有 `tests/contracts/`，契约测试天然适合多席交叉验证；分服务门槛可灰度。
- 要改：13 服务先选 2–3 个；Security Scan 多数 job 仅观测，须先确认绿灯含义，否则「团队判绿」会被假绿污染。
- 工作量：**3–5 人日**。

**Claw —— 宿主，不是试点**
- 能接（零改造）：`automation_preamble.sh`（锁/推送/预算/退避）、`push_card.py`、`budget_guard`、`debate_engine` 四段式、`registry` 五态审批、`automations/<id>/memory.md`。
- 要改：① `check_schedule` 日内一次 → 换 `mutex_lock`；② `forbidden_zones` 禁写 `automations/`；③ 席位产物另起文件，避免与 `hub_reconcile --fix` 打架；④ 告警分流；⑤ 席位级预算只能近似（`credit_json` 是会话级）。
- 工作量：**5–8 人日**。
- 风险：30 天 442 次自动提交，评审信号会被噪声淹没。

**project-monitor-fusion —— 条件接入**
- 先决：Pint/PHPStan/PHPUnit 从 `|| warning` 改阻塞，否则「团队判绿」毫无意义。
- 工作量：硬化 1 人日 + 接入 2 人日。

**engineering-audit-kit —— 不接业务，接规则**
- 正确路径：在此发版 tag → 下游改 `uses: …@vN`；不要评审它（无测试，等于评审 YAML）。

**wechat_api / marvis_bridge —— 不接**
- `wechat_api`：零测试，先补 5–10 个核心用例（约 2 人日）；
- `marvis_bridge`：已退役且 archive，任何接入都是复活。

### 3.4 推荐接入顺序

```

   6 席保留 · 只启 AD-01 三层审计 · 三基线只跑 1 个任务类

第 2 步（2 周）：QTS 选 2 个服务复制；同时完成 Claw 宿主改造（锁/告警/预算）

```
