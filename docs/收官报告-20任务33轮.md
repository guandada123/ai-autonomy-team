|---|---|---|

### 5.2 恒定裁决原则（两轴均已锁定）

- **`ADJ-001 = count`**：少报不可逆——单侧单号必须计入，`excluded` 桶不得成为藏差错的抽屉。
- **`ADJ-002 = 6`**：零金额条目（送转 / 日期 / 费用差）留着才能暴露口径矛盾；剔除等于放弃复查。

两条原则在 29 轮签字中分别保持 100% 与 88.9% 一致，且不一致全部发生于契约尚未稳定的 r2–r4，**无一次在契约稳定后反复**。

### 5.3 机械改判留痕（r32）

`round32/answer-final.json` 记录了一次由签字推翻 PM 暂定多数：
- PM `exclude` 暂定多数 `120.00 / 260.00` 被 ADJ-001 推翻；
- 改判后 `amount_diff_total=380.00`、`excluded_amount_total=0.00`；
- `380.00 = T115 的 120.00 + T119 单侧 260.00`；
- 中性 `implies`（D-0016：两选项 implies 完全相同）下，签字是唯一裁决源，机器不得用「多数」充当判据。

## 六、审计发现（本报告新增）

### 6.1 🔴 金额字段类型漂移：5 轮，产生 1 个伪翻边

**事实**：以下 5 轮的 `summary` 中，**6 个金额字段全部为字符串**（`"26640.00"` 而非 `26640.0`）：

| 轮 | 席位 | 任务 |
|---|---|---|
| r6 | EX-01 | T-02 |
| r7 | EX-03 | T-03 |
| r10 | EX-03 | T-03（阶段检查） |
| r11 | EX-01 | T-04 |
| r13 | EX-02 | T-06 |

**为什么回归没抓到**：`MONEY_PATHS` 断言用 `decimal_equals` + `scale=2`，对字符串能做 `Decimal()` 转换，所以 13/13 依然全绿。**断言校验的是数值等价，不是类型契约。**

**实际影响（经复现校验，范围已收窄）**：

1. **席位层**：字符串金额只存在于席位的原始产出（`EX-0X.json`）。`answer-final.json`（PM 聚合产物）已统一为 number——用 `--answer runs/round11/answer-final.json` 复跑得 0 条 WARN，`runs/round11/EX-01.json` 得 6 条。**因此不存在「下游消费 answer-final 会崩」的风险**；
2. **统计层（真实影响）**：T-04/EX-01 的 `'26640.00' → 26640.0` 被误判为翻边，使翻边率虚高至 33.3%（真值 27.8%）——已在本报告 §4.1 剔除。凡以席位产出为输入的比较（翻边率、跨席一致性）都会受影响；
3. **证据链**：同一字段在不同轮次形态不一，跨轮 diff 产生噪声，人工审计时易误读。

> **本节结论的自我修正**：本报告初稿曾写「下游若用 `sum()` 会崩」，属过度推断——未验证 `answer-final` 的类型即下结论。经复跑核实后已收窄为上述范围。该修正本身印证了「读数须先确认被读对象」的必要性：同一字段在席位层与聚合层是两个不同对象。

**加固已实施（本轮）**：`judges/verify.py` 新增 `lint_answer_money_types()` 与 `--strict-money-type` 开关。

| 模式 | 行为 | 用途 |
|---|---|---|
| 默认 | 产出 `warnings[]`（`W_MONEY_STRING` / `W_MONEY_TYPE`）+ stderr 提示，**不改变 verdict** | 历史 5 轮是已签字证据链，不因类型形态回溯改判 |
| `--strict-money-type` | 转 `E_` 前缀并计入失败 check → `verdict=fail`, `EXIT=1` | 新产出准入，保证检测可证伪 |
