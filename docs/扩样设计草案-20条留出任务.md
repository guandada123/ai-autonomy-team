## 二、任务生成设计（以 002 为模板参数化）

**差异类型池**（round4 实测验证过的六类，全部有真实对账语义）：

| 类型 | 判断权归属 | 备注 |
|---|---|---|
| 费用漏记（佣金/印花税/过户费） | ADJ-费用轴 | round4 实测：机器 0 vs 人 63.17 |
| 委托价 vs 成交价（滑点） | 算术 + 语义 | n=1 支撑的归纳，留解释位 |
| 权益变动（送转/分红） | ADJ-清单轴 | 金额 0 的股数差是否算差异 |
| T+1 交割跨日 | ADJ-清单轴 | 日期基准列歧义是特性不是缺陷 |
| 单侧缺失（中签/股息） | ADJ-金额轴 | 漏记 vs 误入账的方向问题 |
| 分批成交（重复导入） | dedup 口径轴 | 「多出行」语义——round4 实测三席 2:1 分歧 |

**每任务 = 随机抽 3 类差异 + 随机金额量级 + 固定输出契约**。生成器按 002 的
make_fixtures 模式产出：两份 CSV（Decimal 真值由脚本算出，不手填）、
`spec/{arithmetic,adjudication,fact-schema,interpretations}.json`、truth.json。

**判断轴五条硬规则**（今晚全部踩过一遍，违反任何一条就是 D-0006 复发）：

1. 每条轴人类必须有判断权，且判错有真实代价
2. 四选项的组合计数互不相同（否则人只能签出机器已算出的答案）
3. truth 的 expected 必须标注「历史默认口径，非真值」
4. fact-schema.json 随任务生成，事实表多列比对（单列 sig 会漏 T206 型差异）
5. 判据分层物理分离：算术锚点不塞判断，判断项不含 expected

只在终测时首跑——防止任务生成器被结果反向调参。

## 四、人工裁决负担（必须正面设计，不能装看不见）

20 任务 × 2 轮 × 2 轴 ≈ 80 次签字。方案：

1. **口径原则一次签定**（如今晚的「少报不可逆 → 费用计入」），作为 adjudication 的
   `principle` 前置记录
2. 逐任务签字只确认「本任务是否适用该原则 + 有无例外」，例外必须单独写 rationale
3. 任何一轮 fail（人否机器）即触发该任务重做聚合——这是特性，不是负担
