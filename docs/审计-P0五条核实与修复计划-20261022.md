### P0-1 · 放行不落盘

**位置**：`migration-package/new_round.py:747-748`


**实测**：`preflight_gate()` 返回 `(ok, lines)`，调用方 `main()`（827-833 行）只 `print`。
`_man`（manifest）在此之后才构造（856 行），且**没有任何 preflight 字段**。
→ "将写入 manifest" 是**从未兑现的承诺**，属"报告成功但没做"。

**根因（比摘要更深一层）**：
1. `preflight_gate(root, runs, ...)` 的 `runs` 参数**在函数体内一次都没用**（死参数）——说明"写盘能力"当初设计过、没实现，参数留下了化石。
2. `self_test()` 的 16 项断言里**没有一条测 preflight**（只有匿名化 / 种子 / 幂等写盘 / schema 四组）。
   → 零覆盖是本条能存活的真正原因。**光补写盘不补测试，下次重构会再丢。**

**修复陷阱（摘要未提，但会导致修复失败）**：
preflight 在 823-833 行执行，而 `round_dir.mkdir()` 在 846 行才发生。
→ 直接 `write_json(round_dir / "preflight-exception.json", ...)` 会 `FileNotFoundError`。
必须先算 `round_name`（现 837 行）并前移，或写前 `mkdir(parents=True, exist_ok=True)`。

**修法**：
- `EXIT_BLOCKED = 4`（见 P0-2）后，`preflight_gate` 增参 `round_dir`、`who`，放行时写 `runs/<round>/preflight-exception.json`：`{who, when, reason, gate="families_unverified", params_verified_at}`

- 文案改为"已写入 `preflight-exception.json`"，与实际动作一致

**验收判据**（可证伪）：
