# 八角审查命令使用说明（octagon.py，2026-10-22）

> 一句话：把「输入一个决定 → 派 8 角 → 五项打勾 → 汇总」从手工流程固化成一条命令。
> 实现：`scripts/octagon.py`（约 560 行，纯标准库，零依赖）

---

## 一、命令入口与名称

| 项 | 值 |
|---|---|
| 名称 | `octagon`（八角） |
| 路径 | `scripts/octagon.py` |
| 调用 | `python3 scripts/octagon.py <开关>` |
| 依赖 | 仅 Python 标准库（与项目一致，见 `D-0032`） |
| 是否进迁移包 | **否**。迁移包必须零依赖且只含交付物；八角是团队工作流工具，只放 `scripts/` |

### 架构边界（不可绕过，写在最前面）

★ **本命令不调用子代理。** Python 无法调用 Agent 工具，只有主会话能发起 —— 这是 `new_round.py` 开头就声明的同一条事实。

| 环节 | 谁做 | 命令能不能代劳 |
|---|---|---|
| 生成 8 份提示词 | `octagon.py` | ✅ |
| 派发给 8 个子代理 | **主会话** | ❌ 做不到 |
| 收回 8 份产出 | **主会话** 保存到 `outputs/` | ❌ 做不到 |
| 校验收齐没有、五段齐不齐 | `octagon.py` | ✅ |
| 算矩阵与覆盖增量 | `octagon.py` | ✅ |

任何声称"一条命令自动跑完 8 个模型"的实现，在本环境都是假的。

## 二、参数与默认值

| 参数 | 默认 | 说明 |
|---|---|---|
| `--decision TEXT` | 空（init 必填） | 要审查的决定。缺省时打印帮助并退出码 2 |
| `--facts PATH` | 空 | 事实材料文件（md/txt）。**缺省时提示词会写明"禁止编造数字"** |
| `--out DIR` | `reviews/<日期>-<决定hash6>` | 输出目录。同日同决定 → 同目录（幂等前提） |
| `--angles SPEC` | `all8` | `all8` / `core3` / `all9` / `1,2,3` |
| `--include-optional` | False | 含第 9 角（可执行与维护） |
| `--check DIR` | — | 校验指定目录的回填完整性 |
| `--summary DIR` | — | 生成汇总报告（要求 score.json 无 `not_run`） |
| `--self-test` | — | 自检（24 项） |

### `--angles` 预设（对应 `角色覆盖度评估` §四「开几角按决策代价」）

| 预设 | 角 | 适用 |
|---|---|---|
| `core3` | 1 主推 + 2 反对 + 3 成本 | 有代价但可逆 |
| `all8`（默认） | 1–8 | 不可逆 / 对外 / 花钱 |
| `all9` | 1–9（含可执行与维护） | 同上且需落地路径 |
| `1,2,3` | 指定编号 | 自定义子集 |

> `--angles 9` 会报错：第 9 角是可选角，需 `--include-optional` 或 `all9`。
> 这是有意为之 —— 可选角被静默带上，会让"8 角"这个说法失真。

### 退出码（与 `protocol/05` 退出码总表一致）

| 码 | 含义 | 触发 |
|---|---|---|
| 0 | 成功 | — |
| 1 | schema 不符 | 产出缺失 / 五段不全 |
| 2 | 用法错误 | 缺 `--decision`、材料不存在、`--angles` 非法 |
| 3 | **未裁决** | `score.json` 还有 `not_run`，拒绝出汇总 |
| 4 | 闸门拒绝 | **本命令不使用**（保留给 `preflight`，避免与 3 混淆） |

## 三、内部执行流程

### init（`--decision`）

```
① 校验：decision 非空 → 读材料 → 解析 angles（任一失败 → 退出码 2，不建目录）
② 建目录：<out>/prompts/  <out>/outputs/
③ 写 review.json     元数据（决定、材料字数、8 角清单、5 判据、created_at）
④ 写 prompts/N-<角名>.md   8 份，每份含：本角一问 + 视角隔离声明 + 五段强制要求
                          + 7 条红线 + 决定原文 + 材料原文
⑤ 写 score.json      8×5=40 格骨架，**全部 not_run**（不预填 pass）
⑥ 写 outputs/README  回填说明
```

**幂等**：重跑同目录时 `created_at` 不变、内容未变的文件报 `unchanged`（与 `new_round.py` 同一套 `write_text`）。

**为什么 score.json 不预填 pass**：预填等于伪造验收。40 格全 `not_run` 时 `--summary` 会拒绝出报告（rc=3）——这是设计，不是缺陷。

### check（`--check`）

```
① 读 review.json，拿本轮开哪几角
② 逐角找 outputs/N-<角名>.md，缺失 → 记问题
③ 每份扫 `### 1.` ~ `### 5.` 五段标题，缺段 → 记问题
④ 有问题 → 逐条打印 + rc=1；全齐 → rc=0
```

**不做**的事：不自动判定五项 pass/fail。理由见 §六「为什么打分要人工」。

### summary（`--summary`）

```
① 读 review.json + score.json
② 有 not_run → 打印未裁决清单 + rc=3（不出报告）
③ 全裁决 → 算 8×5 矩阵 → 算每判据的命中角数
④ 命中角数 == 1 → 标记为「独有价值」判据（少开这一角就会漏）
⑤ 写 summary.md + summary.json
```

```
├── prompts/
│   ├── 1-主推.md
│   ├── 2-反对.md
│   ├── ... 共 8 份
│   └── 8-度量与证伪.md
├── outputs/         ★ 由主会话回填，脚本不生成
│   ├── README.md
│   └── 1-主推.md ... 8-度量与证伪.md
├── score.json       40 格裁决（pass / fail / not_run + evidence）
│                    + actions{角号:[...]}：可行动项（覆盖增量的真实载体）
├── summary.md       矩阵 + 覆盖增量（--summary 生成）
└── summary.json     机器可读版
```

### score.json 的两个字段，谁管什么

| 字段 | 管什么 | 不预填 |
|---|---|---|
| `results[]`（8×5） | **准入**：这份产出是不是一份合格的审查 | `status` 全 `not_run` |
| `actions{}`（按角） | **覆盖增量**：多开这一角，多看到什么 | 各角空列表 |

每项 actions 的写法：

```json
{"text": "先补测 pre_release_check 基线耗时", "level": "change", "dup": null}
```

- `level`：`change` 改变做法 / `minor` 补充认知
- `dup`：提出过同一项的**其他角号**（字符串），无重复填 `null`
- ★ **重复由填表人显式标注，脚本不做文本相似度判重**：措辞稍变就会漏判或误判，
  而把重复项误判成独有项会**高估覆盖**，比不统计更糟。

### summary.md 长这样（真实输出节选）

```markdown
## 判据矩阵

| 角 | C1 点名具体对象 | C2 数字可追溯 | C3 下游影响说清 | C4 可证伪条件 | C5 自身盲区 | 通过 |
|---|---|---|---|---|---|---|
| 1 主推 | ✅ | ✅ | ✅ | ❌ | ❌ | 3/5 |
| ...    |    |    |    |    |    |     |
| 7 风险与不可逆 | ✅ | ✅ | ✅ | ❌ | ✅ | 4/5 |
| 8 度量与证伪 | ✅ | ✅ | ✅ | ✅ | ❌ | 4/5 |

## 覆盖增量

| 判据 | 命中角数 | 只有 1 个角命中？（独有价值） |
|---|---|---|
| C4 可证伪条件 | 1/8 | 是：8 度量与证伪 |
| C5 自身盲区 | 1/8 | 是：7 风险与不可逆 |

- 通过格数合计：**26/40**
- **只有单一角色命中的判据 2 项** —— 这些是「少开这一角就会漏掉」的直接证据
```

## 六、为什么打分要人工，不做自动判定

五项里 C1/C2/C3 理论上可自动检测（正则找数字、找对象名），但这在本项目里是**假绿灯高发区**：

| 若做自动判定 | 后果 |
|---|---|
| 正则找数字 → 标 pass | 数字是从别处抄来的、或编造的，正则看不出来；只有对照材料才知道 |
| 正则找"若…则…" → 标 C4 pass | 空话也含"若"；可观测性无法用正则判 |
| 正则找"我可能漏了" → 标 C5 pass | 「可能有疏漏」正是最典型的空话，也含关键词 |

项目铁律「检测必须可证伪，绿灯必须能被正样本击破」——自动判定在这里过不了这一关。
所以：**脚本只做结构校验（收齐没、五段齐没），语义判定留给填表的人**，且要求每格填 `evidence`（引原文一句）。

### 唯一的一项 evidence 自动检查：占位检测

`--check` 与 `--summary` 都会检查已裁决格子的 evidence **是不是占位**。这不是语义判定，只判「有没有内容」。

起因是实测：填第 1 次影子运行的 40 格时，有几格 evidence 写成了「（见产出第 5 段）」——
矩阵 40/40 全过，那几格却没有任何依据，与真审查在度量口径下**完全不可区分**。

| 输入 | 判定 | 为什么 |
|---|---|---|
| `（见产出第 5 段）` | ❌ 拦 | 只有位置指引，没有内容 |
| `见材料 F` / `见上文` / `见第 3 段` | ❌ 拦 | 同上（整句匹配，不是长度阈值） |
| 整句只是一个占位词（「待填」「略」及英文同类词） | ❌ 拦 | 无任何依据 |
| 空 | ❌ 拦 | 已裁决却不写依据 |
| `无下游`（3 字） | ✅ 放行 | 短，但**是内容** |
| `材料未覆盖`（5 字） | ✅ 放行 | 同上 |
| `见产出第 5 段：40 格全合格与真审查不可区分` | ✅ 放行 | 位置 + 内容 |

**两条设计约束**：

1. **不用长度阈值判**。第一版就是「长度 < 25 且以『见』开头 → 占位」，结果把带内容的 24 字句子误拦了。改为整句正则匹配。
2. **两头都要验**。只验「占位必须拦」，一个「全部拦下」的实现也能全绿——那会把真审查一起拦掉。自检里 8 条拦、6 条放行，缺一头都不算过。

`status=not_run` 的格子**不查**——还没填时 evidence 为空不是缺陷。

## 十、判据补丁（2026-10-22 23:1x）

### 补丁要解决的问题

首次真实使用（`reviews/2026-10-22-5f3a17`）实测出：**判据矩阵 40/40 全过，但「独有价值」一栏为空**。

根因不是角没差异，是判据测错了对象：

| | 五项判据实际在测 | 而八角给每角下的任务书写的是 |
|---|---|---|
| 内容 | 格式合规（点名/数字/下游/证伪/盲区） | **同一份**「五段强制」 |

→ 每角都按格式写全 → 五项必然全中 → **格式统一 ⇒ 判据无法区分角**。
矩阵满分只证明"提示词生效了"，不证明"覆盖变多了"。

### 补丁做了什么

1. **分工拆开，写进代码注释**：矩阵 = 准入；`actions[]` = 覆盖增量。
2. `score.json` 新增 `actions{角号:[{text, level, dup}]}`，`do_init` 生成骨架，**重跑时原样保留**（丢了要重填）。
3. `--summary` 新增「覆盖增量（可行动项并集）」段：逐角登记数 / 独有数 / 改变做法级数 + 独有项明细。
4. **未登记时写 `no_data`，不写「0 项」** —— `no_data` 是"不知道"，`0` 是"没有"，两者不可混。
5. 矩阵段原文改写：不再提示"覆盖可能冗余"，改为指明"覆盖是否冗余要看可行动项并集"。

### 真实数据验证结果

回填本次真跑的 7 条独有项后：

