## 二、① 费用差：新增 `fee_diff_total`

### 裁定

在 `summary` 新增 `fee_diff_total`，承载 fee 列差合计。原 `excluded_amount_total` 中的费用部分自 3.0 起**应读作 0**。

### 依据（为什么必须新增）

1. **D-0016 的妥协必须解除**：费用差在旧六字段中无落点（`amount_diff_total` / `excluded_amount_total` 都定义在 `amount` 列差上，费用属 `fee_total` 列）。旧版把 `fee_gap` 塞进 `excluded_amount_total`，违反 TASK.md「费用不并入金额」易错点 1；D-0016 改为两选项 implies 同值以规避，代价是 **9/20 任务（T-05/06/09/12/14/15/16/19/20）的 ADJ-001 变成中性轴**——机器无法反推席位立场，人闸门签字失去可验证性。
2. **症状实证**：`runs/round32/answer-final.json` 的机械改判被迫引用「ADJ-001 implies 中性（D-0016）」绕路作出解释。若 implies 可辨，机器可直接判定，无需人工解释。
3. **不新增的代价**：这 9 个任务的裁决轴永久无检验力，`pending` 恒为 2 且其中 1 项永远无法消解。

### 值定义

```
fee_diff_total = Σ|ledger.fee_total − bill.fee_total|   （双侧都存在的差异单）
               + Σ src.fee_total                        （单侧缺失单，取存在侧整笔）
```
即**原 `fee_gap`**，等于旧 `excluded_amount_total` 所承载的量——属于「搬家」而非「新增计量」。

### ADJ-001 语义（两选项从此可辨）

| 选项 | amount_diff_total | excluded_amount_total | **fee_diff_total** |
|---|---|---|---|
| `count`（费用计入） | `amount_gap` | `0.0` | **`fee_gap`** |
| `exclude`（费用不计入） | `amount_gap` | `0.0` | **`0.0`** |

单侧缺失场景（`one_side` 类任务）额外区分 amount/excluded 分区，`fee_diff_total` 同样为 `count→fee_gap` / `exclude→0`。

> **闭合恒等式不变**：`amount_diff_total + excluded_amount_total == raw_total_gap`。`fee_diff_total` 是**第三维**，不参与该式（费用不属于 total 差）。

### 落地清单

| 文件 | 改动 | 数量 |
|---|---|---|
| `scripts/make_tasks_20.py` | `expected` 加 `fee_diff_total`；ADJ-001 两场景 implies 各加一维 | 1 份（生成器真源） |
| `fixtures/tasks/T-XX/spec/adjudication.json` | ADJ-001 `options[].implies` 加 `summary.fee_diff_total` | 20 份 |
| `fixtures/tasks/T-XX/truth.json` | `expected.fee_diff_total` + `note` 追加口径说明 | 20 份 |
| `runs/roundN/answer-final.json` | `summary.fee_diff_total` | 26 份 |
| `scripts/judges/verify.py` | `MONEY_PATHS` 加 `summary.fee_diff_total` | 1 处 |

**刻意不做**：`fee_diff_total` **不加入** `ARITHMETIC_ANCHOR_PATHS`。它是判断项（值依赖 ADJ-001 裁决），加入算术层白名单会违反闸门 1「判断项不得混入算术层」。

### 生效边界（重要）

- **判据总数从 13 变 14**（adjudication 层物化从 3 条变 4 条）。历史 verdict 落盘仍为 13/13，属**已签字证据链，不回溯改写**；
- 用**新** spec 重跑历史 answer，结果为 **14/14 adjudicated**（已抽验 r5/r11/r22/r24/r28/r33 六轮，全部一致）；
- 因此：**3.0 前后的 spec 不可交叉使用**。引用历史 verdict 时须同时标注其 spec 版本。

## 三、② 日期比对基准：`trade_date`

### 裁定

日期比对基准**写死 `trade_date`**，并声明于每个任务的 `truth.json#rules.date_basis`。

### 依据（实测，非推断）

| 任务 | 按 `trade_date` | 按 `settle_date` |
|---|---|---|
| T-09 | `diff_count = 6`（`T067…T072`） | **`7`**（`T065…T071`） |
| T-15 | `diff_count = 6`（`T115…T120`） | **`7`**（`T113…T119`） |

**机制**：`ledger.csv` 的 `date` 列实际存的是**成交日**。按 `settle_date` 比对会同时发生两件事：

1. **消除 1 条真差异**：`settlement_day` 类（T072/T120，其 `ledger.date == settle_date`，比 `trade_date` 晚一天）；
2. **引入 2 条伪差异**：正常单（T065/T066、T113/T114）的 `ledger.date == trade_date ≠ settle_date`，被误判为不一致。

净效应 `+1`。**`settle_date` 产出的不是「另一种口径下的正确答案」，而是含伪差异的错误答案**——因此它不构成等价口径。

### 附带裁定：`settlement_day` 类的性质

`settlement_day`（自记账按交割日入账、交割单按成交日列示）是**记账口径差异**，不是数据错误。处置：**计入 `diffs`，单列类别**，由 ADJ-002 决定是否列入清单（恒定裁决 `ADJ-002=6` 已隐含「列入」）。

## 四、③ `excluded_amount_total` 符号：非负绝对值

### 裁定

`excluded_amount_total`、`fee_diff_total`、`dedup_amount` 三量均为**非负绝对值合计**。负值由 `E_MONEY_NEGATIVE` 判 fail。

### 依据

- 实测 33 轮 × 4 席位（EX-01/02/03、PM-01）共 132 个席位-轮组合，其中 **94 个有 `excluded_amount_total` 值**（38 个无该字段：32 个无 summary、5 个文件不存在、1 个无该字段），**这 94 次读数中负值出现 0 次**——现行实现一致取绝对值，加断言零回溯影响；
- 契约此前未写死，跨实现必然分歧（有实现会按「移出量」写带符号值）。

### 实现

`verify.py`：

```python
NON_NEGATIVE_MONEY = {
    "summary.excluded_amount_total",
    "summary.fee_diff_total",
    "summary.dedup_amount",
}
```

`E_` 前缀的 lint 结果**无条件**计入失败判据（不受 `--strict-money-type` 控制）——负值是算错，不是形态偏好。

**刻意不含 `raw_total_gap`**：它是 `bill_total − ledger_total`，在少报场景下合法为负。

### 闭合恒等式（保持不变）

```
amount_diff_total + excluded_amount_total == raw_total_gap
```
因 `excluded` 恒非负，且 `amount` 亦取绝对值合计，该式在「单侧缺失」场景下仍成立（`amount_gap − one_side + one_side == amount_gap`）。

## 六、④ D-0024：空 `excluded_categories` 的合法性

### 裁定

`present` 单路径断言 → **`present_or_note` 双路径断言**：

| 情形 | 判定 |
|---|---|
| `excluded_categories` 非空 | **pass**（不论是否有 note） |
| 为空/缺失 + `excluded_categories_note` 非空 | **pass**（记明为何无类别） |
| 为空/缺失 + note 缺失或空白 | **fail** |

### 依据

1. **原文冲突**：TASK.md §C 明写「`excluded_categories`｜被排除在金额差异之外的类别名列表（**若无则填 `[]`**）」，但 `arithmetic.json` 的 `present summary.excluded_categories` 把空数组判 fail——**按文档做会被机器判错**。
2. **`present` 的语义盲区**：它无法区分「确实无类别」与「忘填」。两种情况在数据上都是 `[]`/缺失。
3. **实测无回溯风险**：26 份业务轮 `answer-final` 的 `excluded_categories` **全部非空**（1~4 类），零份为空。本改动对所有既有产出均为 pass，**不改变任何历史结论**。
4. **为什么不是「直接允许空数组」**：那样「空」与「漏填」仍不可区分，等于放弃这条闸门。要求一句说明的成本极低，但把不可判变为可判。

### 实现

`verify.py`：

```python
def chk_present_or_note(c, answer):
    path = c.get("path");  note_path = c.get("note_path")
    cur = resolve(answer, path)
    if cur is not _MISSING and cur not in (None, "", [], {}):
        return True, f"已声明 {n} 项"
    note = resolve(answer, note_path)
    if note is not _MISSING and isinstance(note, str) and note.strip():
        return True, f"...但有说明：{brief(note)}"
    return False, "...「空」与「漏填」不可区分"
```

`note_path` 由 spec 指定而**不硬编码**，便于复用到其他可空列表字段。

### spec 变更

20 份 `arithmetic.json`：

```json
{"name": "必须声明排除类别或说明为何为空",
 "type": "present_or_note",
 "path": "summary.excluded_categories",
 "note_path": "summary.excluded_categories_note"}
```

判据**数量不变**（10 项 → 10 项），仅类型变化，故历史 13/13 与现 14/14 的通过数不受影响。

### TASK.md 同步

§C 表格新增 `excluded_categories_note` 行，并补「📌 空数组条款（D-0024 收口）」说明：`[]` 合法但必须配说明，机器判据为二选一。

### 可证伪验证（三路径，实测）

| 构造 | 结果 |
|---|---|
| 现有 answer（非空） | `adjudicated 14/14` |
| 空数组 + 无 note | **`fail`** — `必须声明排除类别或说明为何为空` |
| 空数组 + 有效 note | `adjudicated 14/14` |
| 空数组 + 纯空白 note（`"   "`） | **`fail`** — 空白不算说明 |

## 七、⑤ 类别封闭枚举

### 裁定

`excluded_categories` 收敛为 **6 类 + `other:<说明>` 兜底**，由 `W_CATEGORY_NOT_ENUM` 提示非枚举值。

```python
CATEGORY_ENUM = {
    "股数不符",   # shares 不一致（送转/权益变动未更新）
    "日期口径差",  # date 不一致（自记账按交割日、券商按成交日）
    "费用差",     # fee_total 不一致（漏记/费率错）
    "金额不符",   # amount 不一致
    "单侧缺失",   # 仅一侧存在（非交易性现金流/股息/误入账）
    "重复单号",   # 同 txn_id 多行（分批成交合并记账）
}
```

按**差异成因字段**分类（shares / date / fee / amount / 存在性 / 重复性），互斥性最好。

### 依据（实测，45 种写法）

26 份业务轮产出共 **45 种不同类别名**（对齐前为 44 种；对齐时 r20 的中文类别被替换为英文常量，净增 1 种），按语义归并后只有 5 族，但每族的写法高度发散：

| 语义族 | 变体数 | 摘样 |
|---|---|---|
| 股数 / 送转 | **19** | `股数差异-送转未更新`、`数量差-送转未更新`、`SHARE_QTY_DIFF`、`股数不符(送转)`、`权益变动股数未更新`、`股数权益变动(仅股数·零金额)`… |
| 日期 / 记账基准 | **13** | `日期口径差`、`日期口径差-按交割日入账`、`口径差-记账日期`、`BOOKING_DATE_DIFF`、`日期差（入账日≠成交日）`… |
| 费用 | **8** | `费用差-漏过户费`、`费用列差异（成交金额不变）`、`FEE_ONLY_DIFF`、`仅费用不符`、`费用漏记`… |
| 单侧 / 非交易现金流 | **4** | `单侧仅交割单·股息入账（非交易性现金流）`、`现金分红口径差`、`非交易事项-股息入账`… |
| 其他 | — | — |

**同一语义 19 种写法，任何按类别聚合的统计都不可靠**——与 §二 的 fee 字段问题同源（同一语义无单一真源）。

### 为什么只提示、不判死

历史 45 种写法是**已签字产出**，不因命名不规范回溯改判。`W_CATEGORY_NOT_ENUM` 属 warning 通道：
- 不改变 verdict（历史轮仍 14/14）
- 不受 `--strict-money-type` 波及（该开关语义只覆盖金额项）
- 新产出按枚举填写即无警告

### ✅ 语义澄清（对一次误判的修正）

**先前的错误结论**：曾判定「`excluded_categories` 非空但 `excluded_amount_total == 0`」说明字段语义与命名不符，席位把它当成了「差异类别全集」。**该判断是错的，已撤销。**

**实测反证**：`excluded_categories` 实际是 `diffs[].category` 的**真子集**（对齐后 26/26 全部满足；对齐前为 24/26，那 2 份越界正是后文要处理的 r20/T-16 与 r27/T-08）：

| 轮/任务 | `excluded_categories`（填写） | `diffs[].category`（全集） |
|---|---|---|
| r5/T-01 | 口径差-记账日期、口径差-送转股数 | 价格费用不符、单侧缺失-成交、**口径差-记账日期**、口径差-分红现金、**口径差-送转股数** |
| r28/T-09 | 费用差-漏过户费、数量差-送转未更新、日期口径差-按交割日入账 | 价格差、**费用差**、**数量差**、**日期差** 等 5 类 |

**为什么「非空但金额为 0」不矛盾**：日期差、股数差、费用差这三类差异的 **`amount` 差本来就是 0**（日期不同不改变成交金额；送转只改股数；费用在 `fee_total` 列而非 `amount` 列）。所以：

- `diffs` = **全部**差异（含被排除的类别）
- `excluded_categories` = 其中**不计入金额差异**的那几类
- `excluded_amount_total` = 这些类别的金额差合计 = **0**（正确）

三者完全自洽。字段名「excluded_categories」**准确**，无需改名。

**先前误判的根因**：只看了 `excluded_amount_total == 0` 与 `excluded_categories` 非空这一对表面矛盾，没有去比对 `diffs[].category` 这个真正的参照系。**教训：判「数据自相矛盾」之前，必须先找到它本该对齐的那个集合。**

### 新增校验：子集约束

既然该字段必须 ⊆ `diffs[].category`，就应加机器校验（此前完全没有）：

```python
W_CATEGORY_NOT_IN_DIFFS   # excluded_categories 中出现 diffs 里不存在的类别
```

**初次实测命中 2/26**，两份性质不同：

| 轮/任务 | 问题 | 处理 |
|---|---|---|
| r27/T-08 | 措辞差一字：`日期口径差-按交割日入账` vs diffs 的 `日期差异-按交割日入账` | 改为与 diffs 一致 |
| r20/T-16 | **同一份产出用两套体系**：summary 用中文描述，diffs 用英文常量（`FEE_UNDERSTATED` / `SHARES_MISMATCH` / `DATE_BASIS_DIFF`） | 改为原样引用 diffs 的英文值 |

### 对齐原则（重要）

`excluded_categories` 是**派生视图**，必须**原样引用** `diffs[].category` 的值，不得在派生层重新命名。

因此 r20 的处理方向是「改成英文」而**不是**「把 diffs 改成中文」——原始记录的命名规范化应在原始层解决，派生层只负责如实反映。若反过来改 diffs，等于为迁就派生层而篡改原始证据。

### 对齐后状态

| 项 | 结果 |
|---|---|
| 全库子集校验 | **26/26 通过** |
| `W_CATEGORY_NOT_IN_DIFFS` 触发 | **0 次** |
| r20/T-16、r27/T-08 判据 | 仍 **14/14 adjudicated**（仅改措辞，未动任何数值） |
| 留痕 | 两份 answer 的 `summary._category_alignment_note` 记录对齐理由与"数值未变"声明 |

### TASK.md 同步

§C 新增语义说明段，明确三点：① 本字段是 `diffs[].category` 的真子集；② 「非空但金额为 0」不是矛盾及其原因；③ 机器校验规则。
