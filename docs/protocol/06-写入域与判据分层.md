# 06 · 写入域与判据分层

> 本文件定义两件**机制性约束**，它们各自对应一个已被实测复现的结构缺陷：
> - **写入域** —— 对应 F2：「写权限唯一化」曾是纯文本约束，无物理屏障
> - **判据分层** —— 对应 F1：硬裁判曾携带它本该仲裁的判断，于是无法仲裁只能复述
>
> 这两条都不是风格偏好，是缺陷修复。修改须走 `docs/decisions/`。

---

## 一、写入域

### 1.1 问题

`01-架构.md` 曾声明执行体「只读、只提案」，但**没有任何强制手段**。
实测结果：三处越权写入、两个席位，其中一处是**凭空发明了一个目录**。

> 当规则只声明而不划界时，执行体不会询问边界在哪，它会自己划一条。

### 1.2 规则

唯一可机器消费的定义源：`migration-package/config/write_domains.json`

```json
{
  "write_authority": "PM-01",
  "allow": ["runs/round{n}/{seat}/", "runs/round{n}/"],
  "deny":  ["fixtures/", "outputs/", "docs/", "protocol/", "prompts/", "config/", "judges/"]
}
```

> ⚠️ 上例与 `migration-package/config/write_domains.json` **必须逐字对齐**（曾出现文档写 `scripts/`、
> 配置写 `judges/` 的漂移）。注意本配置是**包相对路径**：源侧的 `scripts/` 对应包内的 `judges/`，
> 因此 deny 里写 `judges/` 而不是 `scripts/`。二者不一致时**以配置文件为准**。

| 域 | 席位权限 |
|---|---|
| `allow` 前缀 | 可写（仅 PM-01 与各自席位的运行目录） |
| `deny` 前缀 | **一律禁写**，含 PM |
| 允许/禁止之外 | 视为禁止（fail-closed） |

### 1.3 第 8 查：共享输入目录是否被写入

判定**完全自动**，不依赖席位自觉：

```bash
# 轮次【前】：对 deny 前缀建基线快照
python3 gen_manifest.py --root . --write-domain config/write_domains.json \
    --out runs/round1/wd-baseline.json

# 轮次【后】：比对
python3 gen_manifest.py --root . --write-domain config/write_domains.json \
    --check runs/round1/wd-baseline.json --out runs/round1/write-domain-check.json
```

产出含 `verdict: HIT | CLEAN`，作为结构审计第 8 查的**证据指针**。

### 1.4 一个必须写明的语义边界

比对脚本**只判结构变化**（sha256 新增/删除/变更），**不判语义**。

因此：
- `HIT` ≠ 越权。一次按需的、有决策日志留痕的再生成，也会产生 `HIT`。
- 「越权写入」与「合法再生成」的区分**由 PM 在 `docs/decisions/` 留痕裁定**。

这不是缺陷，是刻意的：AD-01 只驳结构不驳结论，工具同理。工具负责**把不可见变成可见**，判断留给人。

### 1.5 目标机（macOS）的物理落实

```bash
# 概念示例：对 deny 目录去写权限，仅保留运行目录可写
chmod -R a-w fixtures outputs docs protocol prompts config judges scripts
chmod -R u+w runs
```

**Windows 开发机做不到物理隔离**：`attrib +R` 只是软屏障（进程可自行清除），**不得视为安全边界**。
Windows 侧的可靠手段只有**检测**（1.3 的第 8 查）。
→ **检测可得，预防不可得。** 这一句必须如实写在这里，不得让机制显得比它实际更硬。

## 二、判据分层

### 2.1 问题

原 `truth.json` 把 14 条判据混在一起。其中 4 条——`diff_count`、`diffs`、`amount_diff_total`、`excluded_amount_total`——**编码了「什么算差异」「口径差该不该排除」这类归类判断**。

后果：硬裁判比对的是 answer 与 truth 的 expected，**两者共享同一套归类假设**。
→ 硬裁判只能**复述**该假设，无法对它裁决。实测中 EX-02（异族对立面）为对立立场构造的 steelman 论证质量更高，却未能改变结果。

### 2.2 分层规则

| 层 | 含什么 | 谁裁决 | 有无否决权 |
|---|---|---|---|
| `arithmetic` | 仅凭输入数据 + 已声明规则即可**唯一算出**的量 | 硬裁判 JD-01 自动裁决 | **有** |
| `adjudication` | 需要立场/定义的判断项 | **人类闸门** | 无 |

**关键约束：`adjudication` 层的 item 不得含 `expected` 键。**
机器侧根本不存在可被误当「真值」的量 —— 这是防止判断项伪装成客观事实的第一道闸门。

### 2.3 算术层的路径白名单

`verify.py` 内置 `ARITHMETIC_ANCHOR_PATHS`：

```
summary.ledger_rows            summary.bill_rows
summary.dedup_removed_txn_count
summary.dedup_amount           summary.ledger_total
summary.bill_total             summary.raw_total_gap
```

规则：`layer=arithmetic` 下，凡**比对型**判据的 `path` 不在白名单内 → **拒绝加载（exit 2）**。

> 白名单本身就是设计要求：它把 `diff_count` / `diffs` / `amount_diff_total` / `excluded_amount_total`
> **机械地**挡在算术层之外。不靠人自觉，靠拒载。

### 2.4 金额检查的硬闸门

金额类路径必须使用 `decimal_equals` 并声明 `scale`；若误用 float 语义的 `numeric_equals` → **拒绝加载（exit 2）**。

依据：实测 `(2500.01-2500.00)+(3210.51-3210.50) = 0.020000000000436557 ≠ 0.02`。
容差可以掩盖它，但掩盖不等于正确。

### 2.5 裁定语义与退出码

| `--spec-layer` | `--record` | verdict | 退出码 |
|---|---|---|---|
| `arithmetic` | — | `pass` / `fail` | 0 / 1 |
| `adjudication` | 否 | `pending_adjudication` | **3** |
| `adjudication` | 是 | `adjudicated` | 0 |
| `all`（缺省，**fail-closed**） | 否 | `fail` / `pending_adjudication` / `pass` | 1 / **3** / 0 |
| `all` | 是 | `fail` / `pass` | 1 / 0 |

退出码：`0`=pass ｜ `1`=fail ｜ `2`=错误（输入缺失/格式错误/**spec 违规**） ｜ `3`=待裁决

**「未裁决」必须是非零退出。** 若 pending 返回 0，上游会把「没裁决」当成「通过」——那正是 F1 要消除的假信心。

### 2.6 人类闸门往返

**机器产出**：`runs/round{n}/pending-adjudication.json`（待裁决清单）
**状态载体**：`runs/round{n}/answer-status.json`（机器可读的待裁状态，见 §2.6.1）
**模板**：`runs/round{n}/adjudication-record.TEMPLATE.md`（由 `seat_check.py --emit-record-template` 生成）
**人类填写**：`runs/round{n}/adjudication-record.json`

```json
{
  "task_id": "SYNTH-RECON-001",
  "source": "human_adjudication",
  "recorded_by": "<人类署名，不得为空>",
  "recorded_at": "2026-10-19T17:00:00+08:00",
  "decisions": [
    {"id": "ADJ-001", "chosen": "exclude", "rationale": "<理由>"},
    {"id": "ADJ-002", "chosen": "7", "rationale": "<理由>"}
  ]
}
```

**重跑**：加 `--record <该文件>` → `verdict=adjudicated`，每项标注 `source=human_adjudication`，并把 record 的 sha256 写入 `evidence`。

**★ 模板可脚本生成，记录不可。** 模板由 spec 自动渲染（含事实表、选项对照、各方立场、
后果说明），因为它只是**把已知信息摆整齐**；记录是**表态**，必须由人写。

### 2.6.1 待裁状态的机器可读载体（`answer-status.json`）

**定义**：`answer-status.json` 由 JD-01（`verify.py --status-out`）产出，`adjudication_state` 四态：

| 值 | 含义 |
|---|---|
| `pending` | 无 `--record` 且 spec 含 ≥1 判断项 → `verdict=pending_adjudication` |
| `adjudicated` | 有 `--record`、`lint_record` 通过、物化判据全部 ok |
| `fail` | 任一物化判据 not ok |
| `not_applicable` | spec 不含判断项（`verdict=pass`） |

**为什么另起一个文件，而不是给 `answer-final.json` 加字段**：
`answer-final.json` 由 PM-01 唯一写入，工具改写它会破坏「单写多读」；且它的 sha256 已被
`verdict-layered.json` 与 `pending-adjudication.json` 锚定，改了等于让那两份证据指向另一份文件。

**锚定式**：

```
强锚（唯一）：status.answer.sha256 == sha256(answer-final.json)
弱锚（对照）：status.source_verdict = {path, verdict, spec_layer, pending_count, ts}
```

★ **不用 verdict 文件的 sha256 做锚**：`verdict-layered.json` 含 `ts`（`now_iso()` 生成），
同一输入重算一次 sha 就变，状态文件会「自动过期」，而它描述的其实是同一件事 ——
那是把非语义噪声编进指纹（见 `L-0011`）。

**校验（`seat_check.py --verify-final`）**：`contract_version >= 2.1` 时缺失即
`E_ANSWER_STATUS_MISSING`；`< 2.1`（round2/round3）缺失只记 `[WARN]`。
但**文件一旦存在就必须自洽**（sha 匹配 / 四态合法 / `pending_items` 与 pending 文件一致 /
`state=fail` 时 `verdict` 必须是 `fail`）—— 一个撒谎的状态文件比没有更危险，不因版本低而放行。

**★ 结构审计第 7 查据此判定**：「已标注裁判状态」= 存在状态文件且自洽，或 `answer-final.json`
顶层自带等价字段。两者皆无 ⇒ 按「未标注」处理。这不替 AD-01 判 PASS，只是给它一个可检验的对象。
把「生成模板」接上「自动填值」，闸门立刻失效而校验不会报警。

**★ 选项空间必须覆盖真实判断（F15，2026-10-19）**：判断轴的选项若不含某人真实判断的
那个组合，则闸门只能承载机器已有的答案 —— 那不是「人做了裁决」，是「人确认了机器的裁决」。
故 `fixtures/spec/adjudication.json` 的选项由定义式生成，且生成器断言选项 id == 清单条数。

### 2.7 人类闸门防伪：四条校验，以及它守不住的边界

`verify.py` 会拒绝：
1. `adjudication` item 含 `expected` 键
2. record 缺 `source == "human_adjudication"`
3. record 的 `recorded_by` 为空
4. **record 含 spec 之外的 `id`（已退役项）或同一 `id` 重复** —— 多签一项不得被静默忽略
   （`ADJ-003` 已于 2026-10-19 退役；旧 schema 的记录必须**响**，退出码 2）

**但必须坦白**：以上四条只校验 record 的**声明字段**，`verify.py` **无法证明**该文件确实由人而非模型撰写。

> **真正的保证是程序性的，不是技术性的**：
> record 由人类在机器流程之外填好、放入路径，**工具链不对它做任何自动生成**。
> 一旦有人把「自动生成 adjudication-record」写进流水线，这道闸门立刻失效 —— 而校验不会报警。

这条边界必须写在这里，不得让「人类闸门」看起来比它实际更硬。

## 三、读取域（第 9 查，修复 F5）

### 3.1 问题

席位读取域**从未被声明过**：六个席位模板只约束「不可写什么」，没有任何一句说「可以读什么」。于是席位（实测 EX-03）读了含硬裁判真值与 expected 的 `fixtures/truth.json`，再据此「独立得出结论」——**那不是违规，是没人告诉它边界在哪**。这与写入域的问题（F2）同构：只写不防的规则等于没有规则。

### 3.2 与写入域的根本差别（必须先读懂）

**写入会改变文件，读取不改变任何东西。**

- 写入 → 前后快照比对抓得住（第 8 查：`gen_manifest.py --write-domain`，deny 前缀下 path+sha256 差集）
- 读取 → **没有可观测的物理痕迹**。唯一抓手是：①席位**申报**了什么（`reads[]`）②席位把什么**用作证据**（`evidence[].pointer`）

所以读取域是**声明 + 检测**，不是**隔离墙**。第 8 查的快照机制在此完全不适用。

### 3.3 四层清单（`config/read_domains.json`）

单一 allow/deny 无法表达「AD-01 必须读本轮机器产出，而辩论席位必须禁读」——审计席位的职责恰恰是读机器产出，给它们套辩论席位的清单是反的。故分四层，优先级自上而下：

| 层 | 键 | 语义 |
|---|---|---|
| 1 | `deny_absolute` | 任何席位、任何情况**不可覆盖**（truth.json、spec/、config/、judges/、templates/、outputs/、docs/decisions/、历史基线答案） |
| 2 | `allow` + `allow_exceptions` + `allow_extra_by_seat[seat]` | 合规；**可覆盖第 3 层**（如 AD-01/XJ-01/PM-01 对 `runs/round{n}/` 的追加） |
| 3 | `deny_default` | 默认禁读、可被第 2 层覆盖（`runs/` —— 历史轮次产物含未经匿名化的完整结论与立场反推，是绕开匿名化的直接通道） |
| 4 | 其余 | `unclassified`：报告给 AD-01，**不判错** |

判定式：

```
canonical(p) := 多根解析（轮次目录 / 包根 / 工作区根）后的包根相对路径
越界(p)     := ∃deny_absolute: canonical(p).startswith(deny_absolute)
           OR (∃deny_default: canonical(p).startswith(deny_default)
               AND ¬∃allow项: canonical(p).startswith(allow项))
未分类(p)   := ¬越界(p) ∧ ¬(∃allow项: canonical(p).startswith(allow项))
```

占位符：`{n}` = 轮次号（round2 → 2），`{seat}` = 席位 id。

**严重度按轮次契约版本**（与 `reads[]` 同一套机制，不引入第二条规则）：
- `contract_version >= 2.0` → 越界 = `E_READ_DOMAIN_VIOLATION`（error，挡在聚合外）
- `< 2.0` → `W_READ_DOMAIN_VIOLATION`（warning，不追溯作废历史轮次）
- 无论严重度，越界事实都进 `read-domain-check.json`，第 9 查照样记 HIT。

### 3.4 `reads[]` 与第 9 查

- `reads[]` = 席位**实际读过**的文件全集；`evidence[]` = 用什么支撑结论。**语义不同必须分开**——只查 evidence 会漏掉「读了真值但没写成证据」这一最需要抓的形态。
- 第 9 查机器产出 `read-domain-check.json`（由 `seat_check.py` 顺手产出，含每席位原始提取路径，供 AD-01 目视复核而非相信单一结论值）：
  - `verdict == "HIT"`：存在 deny 命中 ⇒ 结构审计 HOLD
  - `NO_DECLARATION`：无任何席位申报 reads[]（v1.0 历史轮次）⇒ 记「未能核验」，**不**据此 HOLD（否则所有历史轮次一律 HOLD，是噪声不是信号）
  - `CLEAN`：未发现命中

### 3.5 匿名包路径净化（辅助，非隔离）

`new_round.py` 在匿名化后追加 `scrub_paths()`：把 deny 清单里的路径字符串替换为 `[deny-domain path redacted]`，并写 `presentation/redaction.json` 记录替换数。目的：历史产物正文里已出现过 `fixtures/truth.json` 这个字符串，不擦掉等于把禁读清单递给席位。**这是「去掉提示」，不是「阻止读取」。**

### 3.6 ★ 诚实边界（不许软化成「已隔离」）

1. **检测强度天然不对称**。脚本**能**判定：申报的读取、用作证据的指针是否越界。脚本**不能**判定：席位是否读取了未申报的文件。**`CLEAN` 是下界，不是证明。**
2. **净化是去掉提示，不是阻止读取**（见 3.5）。
3. **物理隔离只能在目标机（macOS）实现**：席位进程以低权限用户运行 + `chmod -R a-r fixtures/spec config judges templates`。Windows 开发机做不到——`attrib +R` 与 ACL 都是软屏障，进程可自行清除，**不得视为安全边界**。Windows 侧唯一可靠手段是检测。**检测可得，预防不可得。**

## 四、向后兼容

- 旧的单层 spec（顶层有 `checks`、无 `layer` 键）→ 走 legacy 模式，`--spec-layer` 被忽略，
  stderr 打**弃用警告**。
- 理由：现有 `truth.json` 与其 14 条判据仍须可跑（这是回归门的一部分），但**应当**迁移到分层形态。

### 白名单在 legacy 模式下**不生效** —— 以及为什么这不是妥协

初看似乎应当「一视同仁地强制白名单」，但那样会让所有历史 spec 立刻失效，
而它们恰恰是回归基线。所以规则是：

| spec 形态 | 白名单 | 行为 |
|---|---|---|
| 分层 spec 的 `arithmetic` 层 | **强制** | 越界即拒载（exit 2） |
| 单层 legacy spec | **不强制** | 放行，但在结果里打 `carries_undeclared_judgment: true` 标记 |

**理由是清晰的**：防循环针对的是**新写的判据**——防止有人把判断项塞进算术层冒充客观事实。
历史 spec 已经存在、已经被逐条审阅过、其判断项已被 F1 识别并列入分层计划；
对它拒载只会销毁回归基线，不会提高任何安全性。

> 但请注意一个诚实的后果：**legacy 模式下硬裁判仍然只能复述判断**。
> 这正是 F1 未被修复时的状态。legacy 兼容是为了「不破坏历史」，不是为了「继续用它做决策」。
> 实际决策一律走分层 spec。
